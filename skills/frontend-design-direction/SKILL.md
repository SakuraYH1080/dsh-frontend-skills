# 从细节到整体范式

整体范式不是"更多效果"，是一组能反复回答设计问题的项目规则：用户先看到什么、哪些对象值得比较、同一种状态怎样跨页表达、哪里允许一处意外细节。这个技能的工作，是在写第一行 CSS 之前把这组规则定下来，再决定哪些部分交给专项。

它解决的是"这批内容该长成什么样"，不是"这个风格好不好看"。判断标准只有一条：换掉产品名，页面是否还只属于这个项目。

## 0. 先判入口

**需要同时改动两件以上、且互相依赖的事**（信息结构 + 视觉语言、整页节奏 + 材质、多个专项抢同一块表面）→ 用本技能。
**只改一个维度、边界已经清楚** → 直接交给专项。

| 请求 | 走 | 理由 |
| --- | --- | --- |
| 新站、整页、整站改版；从局部效果统一到整体 | 本技能 | 要先定规则，再分配细节 |
| 整站去 AI 味、形成项目个性 | 本技能 + 按需专项 | 个性来自内容与取舍，不来自风格词 |
| 多个专项都要用，且会互相改到对方的决定 | 本技能 | 需要台账与裁决 |
| 只修一块玻璃的对比度、模糊、边缘 | `frontend-liquid-glass` | 材质单点，不涉及版式与 IA |
| 只改字阶、节高、栏宽、滚动节奏 | `frontend-apple-minimal` 或 `frontend-taste-base` | 按页面类型选；两者边界见 §3 |
| 只改角色与界面的空间关系 | `frontend-anime-fusion` | 只决定前后关系、安全区与裁切 |
| 只改粒子层 | `frontend-particles` | 只决定粒子层 |
| 只改背景/玻璃/角色/设置的交接与退出 | `frontend-ecosystem` | 只负责层间合同与时序 |
| 只改控制台几何、读数、状态语言 | `frontend-industrial-sci-fi` | 专项语言，不重排信息结构 |
| 只改文案声口 | `frontend-taste-base`（编辑可加 `humanizer-zh`） | 不动骨架 |

一句话判据：**改完这件事，会不会迫使另一页或另一个组件也改？** 会，才是整体问题；不会，交给专项。

完整路由、专项能力与不管什么，见 `references/30-routing-and-ownership.md`。

## 1. 核心流程

七步，按顺序做。每一步都有产出物；没有产出物就不算做完。

### 1.1 写任务句

不是"做一个高级感的档案站"，而是一句能失败的话：

> 让 [谁] 带着 [什么线索] 来，在 [哪个页面] 完成 [什么判断或动作]，并能用 [什么证据] 确认自己做成了。

示例（《针迹》）：

> 让只知道曲名的听众，在首页和目录里认出班卓琴录音、读出目录号，并判断地点能否当作已确认资料引用；完成的标志是能说出"Victor 3045，Camden, New Jersey，地点未确认"，并指出回查处。

写法要求：

- 一句话只放一个主任务。次任务最多两条，写在同一段后面。
- "谁"要带线索：知道曲名、拿着唱片编号、来做采购、来复核数据。线索不同，入口就不同。
- "确认做成"必须是用户能说出口或做出来的事，不是"感觉很高级"。
- 任务句写不出来，说明内容还没盘清，回到 1.2。

产出：任务句 + 完成证据（一句用户会说的话，或一个会做的动作）。

### 1.2 盘内容

把真实记录摊在桌上，先不画页面。至少准备：

- 两条同类的真实记录（能互相对比，不是一条样板）；
- 一条长项（长人名、长地名、长标题）；
- 一条空项或易误读项（缺失字段、未确认地点、同名不同版本）。

每条记录填一张表：

| 字段 | 真实值示例 | 来源 | 确定性 | 用户拿它干什么 |
| --- | --- | --- | --- | --- |
| 曲名 | `Banjo Solo` | 馆藏原页 | 已确认 | 认出作品 |
| 目录号 | `Victor 3045` | 馆藏原页 | 已确认 | 报给他人、查发行品 |
| 母版号 | `[Pre-matrix B-]3045` | 馆藏原页 | 已确认 | 核对具体录制 |
| 录音次号 | `take 1` | 馆藏原页 | 已确认 | 区分同一次录音的不同次 |
| 录音日期 | `1901-01-21` | 馆藏原页 | 已确认 | 排序、引用 |
| 地点 | `Camden, New Jersey` | 馆藏原页 | 未确认 | 判断能否引用 |
| 直径 | `10 in.` | 馆藏原页 | 已确认 | 比较版本 |

规则：

- 字段名用用户会说的词。"录音日期"不是 `date`，"地点未确认"不是 `location_status`。
- 确定性是内容的一部分。已确认、未确认、推定、缺失，各有各的写法；不要为了让页面干净而吞掉。
- 缺数据就标 `[待确认]`，不要编一个看起来合理的值。
- 把"用户拿它干什么"写出来。写不出来的字段，多半不该进折叠态。

产出：内容表 + 两条可对比记录 + 一条长项/空项。

### 1.3 分标题、列表、详情

同一批内容，分工不同，页面就不同。先定三层，再谈样式。

| 层 | 回答的问题 | 放什么 | 判据 |
| --- | --- | --- | --- |
| 标题 | 这是什么作品/对象？ | 作品名或对象名，全页只出现一次 | 换一条记录，标题必须换 |
| 列表 | 这一条和那一条差在哪？ | 折叠态就能完成第一次辨认的字段 | 两条记录折叠时不能长得一样 |
| 详情 | 我要引用/核对什么？ | 编号、次号、尺寸、确定性、出处、原件入口 | 每个字段都能回查原始记录 |

三条常见错误：

1. **标题当分类用**。"精选录音"不是标题，"Banjo Solo"才是。分类名放筛选或栏目，不占作品位。
2. **列表放营销语**。"沉浸式听觉之旅"不能区分两条录音。列表要放可比较的事实。
3. **详情重复列表**。折叠态已经能判断的字段，详情里不必再占一整行；详情应该往"核对与引用"走。

《针迹》的分工：

- 标题：`Banjo Solo` / `The Stars and Stripes Forever`，各出现一次；
- 列表（折叠态）：录音日期、演奏形式、演出人员、目录号；
- 详情：母版号、录音次号、直径、地点与确定性、指挥、馆藏链接。

折叠态字段怎么算，见 §2。

### 1.4 选主导视觉语言

不从风格名开始（"复古""高级""科技感"不是语言，是形容词），从三个来源找语法：

1. **对象本身的形态**：唱片是圆的，直径有比例，标签有同心圆，编号印在死沟区。
2. **行业/档案的记录方式**：目录号、母版号、次号、日期、图注、来源。它们决定什么该并排、什么该用等宽。
3. **使用场景**：查档、引用、比较、试听。它决定密度、焦点和恢复路径。

把找到的语法写成 5–7 条规则，每条都要能回答一个未来问题：

| 问题 | 规则示例（《针迹》） |
| --- | --- |
| 字怎么分工？ | 大号宋体给曲目定题；等宽字对照日期与目录号；正文与控件用清楚无衬线 |
| 颜色表示什么？ | 纸底与墨色承载阅读；锈红只给查找、链接、键盘焦点 |
| 表面怎么分层？ | 主图可用更深图版底；正文保持平整纸底；线纹不进正文 |
| 密度怎么变？ | 首页疏、目录密、详情更密；同一字段在三处用同一个词 |
| 动效解释什么？ | 展开/收起解释层级变化；不做与对象无关的漂浮 |
| 不确定怎么表达？ | "未确认"紧跟地点，不藏在详情末尾 |

规则要能延续到第二页。只在首屏成立的，是构图，不是语言。

### 1.5 做一处识别细节

识别细节是"这个项目独有、又能从内容解释"的一处视觉决定。它让页面被记住，但不承担唯一的信息编码。

四个条件，缺一不可：

1. **有依据**：来自真实字段、真实比例或真实材料，能说出出处。
2. **会重复**：至少在两个位置出现（主图与列表、详情与来源），形成可跟随的线索。
3. **可撤下**：拿掉它，任务仍然完成。撤下后如果页面垮了，说明它是结构，不是细节。
4. **有说明**：图注、来源、比例说明。尤其是示意图，必须写明"据尺寸字段绘制"。

两个测试：

- **遮标测试**：遮住 logo 和产品名，页面是否还能被认出属于这个项目？
- **撤细节测试**：拿掉这处细节，从首屏走到结果、再走到详情，路径是否仍然成立？

《针迹》选的是唱片直径：两张图版按 10:7 同比例绘制，圆心在同一水平线，目录号在图版与列表重复。图注写明"据馆藏尺寸字段绘制的示意图"。撤掉图版，查档路径仍然成立，所以它是细节而不是结构。

一个项目只留一处。第二页复用后如果变成纯装饰，就撤下。

### 1.6 排专项、立台账

先骨架，后细节。顺序固定：

1. 信息结构（本技能）
2. 版式、字阶、节高（`frontend-apple-minimal` / `frontend-taste-base`）
3. 材质（`frontend-liquid-glass`）
4. 角色、粒子（`frontend-anime-fusion` / `frontend-particles`）
5. 动效（按承载对象归口：叙事动效归 apple-minimal，材质形变归 liquid-glass，角色动效归 anime-fusion，粒子运动归 particles）
6. 多层协作的交接、让位、退出（`frontend-ecosystem`）

每选一个专项，写清三件事：它管什么、它不管什么、它交付什么。然后填决定台账：

| 决定 | 定稿方 | 只读输入 | 范围 | 复查条件 |
| --- | --- | --- | --- | --- |
| 标题/列表/详情分工 | 本项目 | 内容表 | 首页、目录、详情 | 两条折叠记录能否区分 |
| 字阶与栏宽 | `frontend-apple-minimal` | 内容大纲 | 产品页主体 | 长标题、390px |
| 一块购买条的玻璃 | `frontend-liquid-glass` | 背景取样 | 仅该组件 | 亮底/暗底对比度 |
| 识别细节 | 本项目 | 直径字段 | 首屏 + 列表 | 撤下后路径仍成立 |

硬规则：**同一项决定只能有一个定稿方**。其他专项可以给输入、做检查、提反对意见，但不能并列写第二套默认值。台账里出现两个定稿方，就是冲突，按 §3 裁决。

### 1.7 用同一任务验收

不要按页面挨个看，按用户的一条任务路线走：

1. 从入口进目录，保持记录折叠，找到目标记录的关键字段；
2. 展开一条，核对一个需要引用的事实，定位出处；
3. 做一次无匹配筛选，再清除，确认结果数与可见记录相符；
4. 切一次视图/主题/场景，确认已展开的记录与焦点没丢；键盘重复一遍。

证据分四级，交付时必须标明：

| 级别 | 含义 | 例子 |
| --- | --- | --- |
| 观察到 | 实际运行、截图、DOM/控制台 | 390px 下标题换行 3 行，未溢出 |
| 计算到 | 公式或脚本可复算 | `#242820` 在 `#f5f0e5` 上 13.20:1 |
| 推断 | 基于规范/经验的判断 | 该焦点环在深色底上应仍可见 |
| 待验证 | 当前环境做不到 | 读屏器、真实设备、目标读者测试 |

不要把"推断"写成"通过"。通过只属于前两级。

## 2. 折叠态字段怎么定

这是整页改版最常错的一步：把所有字段塞进折叠行，或者把关键字段全藏进详情。

算法：

1. 写下用户在折叠态要完成的**一个判断**（认出作品 / 选中版本 / 报出编号 / 判断能否引用）。
2. 拿两条真实记录逐字段对比，找出"只有这个字段能区分它们"的最小集合。
3. 能区分版本的字段进折叠行；不能区分的同名字段（如曲名）上升为作品级标题，只出现一次。
4. 需要引用、核对、追源的字段（母版号、次号、尺寸、确定性、出处）进详情。
5. 恢复信息（结果数、无匹配原因、清除筛选）独立于记录，放在列表级，不塞进每一条。
6. 用最长真实值和零结果各测一次。窄屏先换行、再减次要信息，不删身份字段。

《针迹》的结果：

- 折叠态：日期、演奏形式、演出人员、目录号、展开提示；
- 详情：母版号、录音次号、直径、地点 + "未确认"、指挥、馆藏链接；
- 列表级：结果数、无匹配说明、清除筛选。

反例（通用稿）：折叠卡片只显示两条相近的英文曲名与演奏者，演奏形式和目录号在详情里。用户必须先展开或先筛选，才能完成第一次辨认——这不是风格差异，是折叠态字段没定对。

## 3. 职责与裁决

### 3.1 谁定稿什么

| 决定维度 | 定稿方 | 只提供输入/检查 |
| --- | --- | --- |
| 任务句、内容分层、标题/列表/详情 | 本项目（本技能） | 内容方、目标用户 |
| 节高、一屏一节、长页节奏、动效额度、文案声口 | `frontend-taste-base` | 本项目给任务与内容 |
| 信息三层、8pt 网格、字阶、栏宽、产品页叙事、滚动 | `frontend-apple-minimal` | `frontend-taste-base` 只做文案/动效检查 |
| 控制台几何、切角、读数、状态三态、工业配色 | `frontend-industrial-sci-fi` | 本项目给对象与状态 |
| 玻璃材质、模糊/折射/边缘、亮暗背衬、降级 | `frontend-liquid-glass` | 本项目给表面位置与背景 |
| 粒子生成、力场、帧预算、降级 | `frontend-particles` | 本项目给用途与区域 |
| 角色前后关系、安全区、裁切、遮挡 | `frontend-anime-fusion` | 本项目给角色职责与素材 |
| 场景/表面/角色/设置的交接、让位、退出、恢复 | `frontend-ecosystem` | 各专项给本层参数 |
| 识别细节、跨页术语、冲突裁决 | 本项目（本技能） | 专项提可行性 |

"排版"要拆开看：节高与节奏归 taste-base；字阶、栏宽、产品页 section 归 apple-minimal；工业读数与编号归 industrial-sci-fi。三者不在同一页抢同一个决定。

### 3.2 冲突怎么裁

按顺序：

1. **事实与术语优先**。业务真实性、已确认字段、状态语义，不能被视觉效果改写。
2. **明确的产品要求与无障碍条件同时校验**。任一不满足，候选方案直接淘汰，不进入风格比较。
3. **主导语言优先于专项默认值**。项目已经定了轮廓、字 roles、色 roles，专项在自己的范围内工作；要改骨架，先回到本技能。
4. **同一表面/同一维度只留一个定稿方**。不取平均，不并列两套默认值。
5. **拆范围，不拆原则**。可以按页面、区块、表面、场景带分别定，但同一范围内只能有一套规则。
6. **效果干扰任务时，先恢复任务，再缩小效果**。不是把效果调淡，而是把它移出任务路径。

常见裁法：

- 工业切角 vs 玻璃圆角：工业语言定轮廓；确需透明，只用兼容几何的材质，或把透光限制在独立场景带。
- 苹果式弹性节高 vs 一屏一节：叙事区由 apple-minimal 定高度；taste-base 只给文案与动效检查；查询/工作界面高度随内容。
- 持续氛围动效 vs 阅读稳定：页面定动效区域与启停；粒子参数归 particles；跨层交接归 ecosystem。
- 告警单向升级 vs 业务自动恢复：只有锁存告警用显式复位；普通同步状态随有效业务事件更新。

裁决结果写回台账：冲突是什么、依据哪条、谁改、复查什么。见 `references/30-routing-and-ownership.md`。

## 4. 短案例：同一批内容，两种分工

《针迹》用同一份馆藏数据做了两版：

| | 通用稿 | 档案稿 |
| --- | --- | --- |
| 首屏 | 居中 hero + 英文曲名 + 两张等权卡片 | 具体曲名 + 10:7 图版 + 进入目录 |
| 折叠卡片 | 曲名、演奏者；形式与编号在详情 | 日期、演奏形式、演出人员、目录号 |
| 目录组织 | 入口集中，按卡片浏览 | 沿录音日期组织，版本行用分组线连接 |
| 第一次辨认 | 需筛选或展开 | 折叠态即可 |
| 适合 | 题材各异的选集 | 同曲多版本、需要引用编号的档案 |

两版共用筛选、记录展开和来源链接；切换时保留已展开记录与焦点。差异不在配色，而在标题、列表、详情各承担什么。

三条可迁移结论：

1. 同曲多版本，曲名只写一次；版本之间的差异字段必须进折叠态。
2. 需要引用的事实（编号、次号、确定性、出处）放详情，但入口要紧贴记录。
3. 识别细节要能跟着记录走：图版上的目录号与列表里的目录号是同一个，读者才能在图、列表、来源之间定位。

完整案例、字段表、对比度实测与移动端顺序见 `references/50-case-needlemarks.md`。

## 5. 交付

设计简报九项（模板见 `references/60-brief-template.md`）：

1. 项目与改版范围；
2. 使用者带什么线索来、要做什么、怎样算做成；
3. 两条真实内容与出处，一条长项/空项/易误读项；
4. 参考页面的观察、用途推断、采用范围；
5. 主导语言、首屏与结果的阅读顺序、一处识别细节；
6. 共用术语/状态/样式，以及各页可变的部分；
7. 选用的专项、各自位置、冲突决定；
8. 正常与恢复路径、宽窄屏、键盘、系统偏好；
9. 实际验收证据、测试环境、待验证项。

交付回复里要能直接看到：主导语言一句话、识别细节一句话、每个专项负责的那一段、以及哪些结论是"待验证"。
