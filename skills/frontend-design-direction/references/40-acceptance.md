# 验收：同一任务、证据分级与环境矩阵

## 一、按一条任务路线走

不要按页面挨个看。用目标用户真实会走的一条路线，从入口到恢复：

1. **折叠辨认**：从入口进目录，保持记录折叠，找到目标记录的关键字段（作品、形式、编号）。
2. **展开核对**：展开一条，读一个需要引用的事实，定位出处/原件。
3. **无匹配恢复**：组合筛选到 0 条，确认提示说清原因，清除后计数与可见记录相符。
4. **切换与键盘**：切视图/主题/场景，确认已展开记录与焦点没丢；只用键盘重复第 1–3 步。

每一步都比"同一件事"：第 1 步比关键信息可见性，第 2 步比同一事实能否复核，第 3 步比恢复是否可执行，第 4 步比状态是否连续。

要证明"用户用时变少"，需要招募真实读者、轮换两版顺序、记录答对率/出错点/用时。没有这一步，只能写"结构上减少了展开次数"，不能写"更快"。

## 二、六组检查

### 1. 内容真实

- 列表与详情的每个字段都能回查原始记录；
- 目录号、日期、次号、地点确定性在各处一致；
- 示意图有图注与依据；
- 没有编造的字段、来源、日期。

通过标准：随机抽两条记录，逐字段对照来源，零差异。

### 2. 一眼可辨

- 遮住 logo 与产品名，仍能看出行业、对象、任务；
- 记录折叠时，标题/形式/编号仍指向同一个查档任务；
- 两条同类记录折叠时能被区分。

通过标准：不看详情，能说出"这两条差在哪"。

### 3. 恢复动作

- 无匹配时说明是哪个筛选导致；
- 提供清除筛选或放宽条件的动作；
- 清除后结果数与可见记录相符；
- 空状态不是只有"暂无内容"。

通过标准：从 0 条回到完整列表，不需要刷新或回退。

### 4. 键盘与窄屏

- 跳转链接、筛选、展开、原件链接都能键盘到达；
- 焦点可见，顺序跟内容；
- 320/390px 下长标题、长人名、长地名换行不溢出；
- 触控目标 ≥44px。

通过标准：只用键盘完成第 1–3 步；390px 下无横向滚动。

### 5. 颜色与对比度

- 逐对测实际底色与文字/控件边界/焦点；
- 普通文字 ≥4.5:1；大字号 ≥3:1；必要控件边界与状态提示 ≥3:1；
- 焦点环与相邻色 ≥3:1；
- 玻璃/半透明表面在背景最亮与最暗两端都成立；
- 强制颜色模式下信息不丢。

通过标准：记录每一对前景/背景的实际值与比值，不只写"通过"。

### 6. 可选增强

- 静态、关闭脚本、减少动态、关闭透明/模糊后，核心内容与原始资料仍可获取；
- 恢复增强后路径清楚；
- 动效有静态形态。

通过标准：逐项关闭后重走第 1–2 步。

## 三、对比度怎么算

相对亮度：

```
L = 0.2126 R + 0.7152 G + 0.0722 B
其中每个通道 c: c <= 0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4
对比度 = (L1 + 0.05) / (L2 + 0.05)
```

阈值：

| 对象 | 最低 |
| --- | --- |
| 普通文字（<24px，或 <18.66px 粗体） | 4.5:1 |
| 大字号文字（≥24px，或 ≥18.66px 粗体） | 3:1 |
| 控件边界、状态提示、图形对象 | 3:1 |
| 焦点指示与相邻色 | 3:1 |

半透明/玻璃：

1. 先算合成后的实际颜色（玻璃底色 + 背景 + 文字），不要拿设计稿的纯色值代替；
2. 取背景最亮与最暗两个极端各算一次；
3. 两端都达标才算通过；只在一端达标，视为不通过；
4. 做不到就加承载层、改文字色，或把正文移出玻璃。

### 算例：《针迹》

| 前景 | 背景 | 比值 | 用途 | 结论 |
| --- | --- | --- | --- | --- |
| `#242820` | `#f5f0e5` | 13.20:1 | 主文字 | 通过 |
| `#53584e` | `#f5f0e5` | 6.43:1 | 次文字 | 通过 |
| `#9b3824` | `#f5f0e5` | 6.19:1 | 链接/查找 | 通过 |
| `#9b3824` | `#ece5d7` | 5.61:1 | 展开行链接 | 通过 |
| `#827769` | `#f5f0e5` | 3.86:1 | 控件边界 | 通过（非文字 3:1） |
| `#242820` | `#ece5d7` | 11.97:1 | 展开行主文字 | 通过 |

注意：细分组线只辅助扫读，不承担记录身份；身份由文字与排布表达。这样即使分组线对比度低，也不影响辨认。

## 四、环境矩阵

至少覆盖：

| 项 | 取值 |
| --- | --- |
| 视口 | 320 / 390 / 768 / 1024 / 1440 CSS px |
| 根字号 | 390px 下 200% |
| 输入 | 鼠标、键盘、触摸 |
| 偏好 | 减少动态、强制颜色 |
| 脚本 | 开启、关闭 |
| 网络 | 离线（如声称离线可用） |
| 内容 | 最长标题、最长人名/地名、空字段、零结果 |

记录浏览器与版本、系统、是否本地文件、是否有网络请求。

## 五、证据分级

| 级别 | 定义 | 写法 |
| --- | --- | --- |
| 观察到 | 实际运行、截图、DOM、控制台、网络面板 | "390px 下标题 3 行，无横向滚动" |
| 计算到 | 公式/脚本可复算 | "`#242820`/`#f5f0e5` = 13.20:1" |
| 推断 | 基于规范/经验，未实测 | "该焦点环在深底上应可见，未实测" |
| 待验证 | 当前环境做不到 | "读屏器未测；原页 403" |

规则：

- 只有前两级能写"通过"。
- 推断要写依据；待验证要写缺什么环境、怎么补。
- 自动化工具（对比度检查、axe）只能证明它检查的那一项，不能替代任务走查。

## 七、发布前最后一问

把页面给一个没参与设计的人，只给任务句，不给解释。看他能否：

1. 在折叠态说出两条记录的差异；
2. 找到并读出一个可引用的事实；
3. 在无结果后回到列表；
4. 说出这页属于什么项目。

四件事有一件做不到，回到对应步骤，不要用"风格"解释。
