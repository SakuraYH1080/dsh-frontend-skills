# 整体范式：范围、不变量与反模式

## 为什么需要它

局部决定（一块玻璃的模糊、一个标题的字号）可以单独做对，合起来仍然可能不像一个产品。原因是缺少一组跨页规则：

- 用户先看到什么；
- 哪些对象值得比较；
- 同一种状态在首页、列表、详情里怎样表达；
- 哪里允许出现一处意外细节。

这组规则就是整体范式。它不是风格名，也不是组件库，而是"下一次遇到同类问题时，不用重新争论"的依据。

## 三个决策范围

| 范围 | 决定什么 | 典型请求 | 谁定稿 |
| --- | --- | --- | --- |
| 局部 | 参数、构图、安全区、回退 | 聊天框换成玻璃；按钮圆角改小；粒子慢一点 | 对应专项 |
| 多层协作 | 职责、交接顺序、退出条件 | 背景、玻璃、角色、设置共存于一个工作台 | `frontend-ecosystem` + 各专项 |
| 整体范式 | 真实任务、信息结构、表达规则、验收样本 | 新站、整页改版、整站去 AI 味 | 本技能 |

判断方法：把请求改写成"用户要做的那件事有没有变"。任务没变、只换材料，是局部；任务的主次变了，是整体。

例：

- "聊天框换成玻璃，但仍然是发消息" → 局部，交给 `frontend-liquid-glass`。
- "把聊天页改成长时间写作工作台，要能继续对话、回查旧资料、编辑长消息" → 整体，先排三件事的主次，再谈材料。

## 四条不变量

1. **任务先于风格。** 先能说清谁带着什么线索来、要完成什么判断；再决定页面长什么样。风格词不能替代任务句。
2. **一项决定只有一个定稿方。** 其他专项可以给输入、做检查、提反对意见，但不能并列写第二套默认值。
3. **事实、术语与可读性不是偏好。** 已确认字段、状态语义、对比度下限，不能被视觉效果改写；不满足的候选直接淘汰。
4. **增强可撤下。** 玻璃、粒子、角色、动效都是增强；关掉之后，核心任务仍能完成，路径仍然清楚。

## 反模式

| 反模式 | 症状 | 改法 |
| --- | --- | --- |
| 风格词驱动 | "要高级、复古、科技感"，但说不出页面该先给什么 | 回到任务句与内容表 |
| 全页同一权重 | 所有区块同标题、同容器、同间距 | 分第一眼/扫读/核对/恢复四层 |
| 专项堆叠 | 玻璃 + 粒子 + 角色 + 工业切角同时上，互不改动 | 选一个主导语言，其余限定范围 |
| 两套默认值取平均 | 两套节高、两套灰阶各取一半 | 指定定稿方，另一套退出该范围 |
| 把推断当验收 | 没跑过就写"已通过" | 标"推断"或"待验证" |
| 识别细节承担编码 | 只有图版能区分版本，文字看不出来 | 细节可撤下，身份靠文字与排布 |

## 术语

- **任务句**：谁、带什么线索、在哪、完成什么、怎样算做成。
- **内容层**：第一眼、扫读比较、核对、恢复。
- **折叠态**：记录未展开时可见的字段集合。
- **主导语言**：能跨页回答字体、颜色、表面、密度、动效、不确定性的一组规则。
- **识别细节**：有内容依据、会重复、可撤下、有说明的一处视觉决定。
- **决定台账**：决定 / 定稿方 / 只读输入 / 范围 / 复查条件。
- **恢复路径**：无结果、出错、清除筛选、关闭增强之后，用户回到任务的路。
