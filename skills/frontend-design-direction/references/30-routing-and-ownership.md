# 路由、职责与冲突裁决

## 一、先判：整体还是专项

按"这件事会迫使多少其他地方一起改"判断：

| 情况 | 走 | 例子 |
| --- | --- | --- |
| 只改一个维度，边界清楚 | 对应专项 | 玻璃对比度、一个按钮的字号、粒子速度 |
| 改两个以上互相依赖的维度 | 本技能 | 信息结构 + 视觉语言；整页节奏 + 材质；多专项抢同一块表面 |
| 任务本身变了 | 本技能 | 聊天页 → 写作工作台；目录页 → 查档工具 |
| 普通后台/内部工具，无品牌语言需求 | 不加载风格专项 | 用现有设计系统，只做信息结构与可读性 |

一句话：**改完会不会迫使另一页也改？** 会，整体；不会，专项。

## 二、专项能力与边界

### frontend-taste-base（通用品味基线）

- 管：节高与"一屏一节"的可计算规则、内容窗口表、三层动效结构与动效额度、两代 AI tell 清单与 ban/cap 分级、中文排版与文案声口。
- 不管：材质、配色体系、插画/角色风格。
- 进入：长页节奏发虚、节高不匀、文案像模型写的、动效没有目的。
- 交付：节高表、动效清单、文案修改清单。
- 边界：通用营销页/品牌页由它定节高；产品发布页采用苹果式叙事时，节高与 section 归 `frontend-apple-minimal`，它只给文案与动效检查；查询/工作界面高度随内容，不强行套整屏节高。

### frontend-apple-minimal（极简信息设计）

- 管：信息三层（主张/证据/细节）、8pt 网格、64/96/128/160 节间距、1.25 与 1.333 字阶及 clamp、600px 正文栏宽、九级中性灰 + 单一强调色、hero 三结构、产品页 section 编排、sticky 边界、scroll-driven 与 IntersectionObserver 兜底、0.15–0.4 视差、120/240/400/650ms 四段动效。
- 不管：玻璃、粒子、角色、HUD。
- 进入：产品发布页、文档站、品牌主页、应用落地页、极简长页重排。
- 交付：节高、字阶、栏宽、灰阶、动效时长表。
- 边界：组合时结构、层级、留白、滚动归它；玻璃只能做局部增强，不改骨架与字阶。

### frontend-industrial-sci-fi（工业科幻）

- 管：冷白/深墨双底色、单一信号色（只表示当前位置/可点/需注意）、状态色（正常/警告/中断，不用于按钮）、对角切角与 1px 同路径、HUD 编号、状态单向升级与显式复位、宽体大写 + 粗中文 + 0.14em 字距、等宽读数、机械动效、四套场景预设。
- 不管：玻璃、粒子、苹果式留白叙事、角色；普通后台不加载。
- 进入：控制台、科研数据面板、监控大屏、设备管理、档案检索、单机游戏 UI、科幻落地页。
- 交付：几何、色、字、状态、读数规则。
- 边界：状态开始/恢复/复位来自业务事件；它定表达，不定事实。

### frontend-liquid-glass（液态玻璃）

- 管：玻璃四成因（模糊、折射、边缘高光、环境色渗透）、`backdrop-filter` 与 `feDisplacementMap`、分层参数、组件六态、动态形变与性能降级、可读性算例、场景变体、玻璃层数 ≤3。
- 不管：版式、信息架构、品牌语言、页面整体风格。
- 进入：已有背景、需要浮层；玻璃太糊/太脏/边缘没厚度/掉帧/文字读不清。
- 交付：材质参数、亮暗背衬复核、实底或关闭模糊的回退。
- 边界：对比度由玻璃自身提供，背景最亮与最暗两端都要 ≥4.5:1；做不到就不在这块玻璃上放正文。

### frontend-particles（粒子层）

- 管：发射器与初始分布、寿命曲线与对象池、速度场/力场、simplex/curl 噪声、拖尾与密度、Canvas 2D/WebGL/CSS 选型、指针交互与连接线、对比度与遮罩、60fps/单帧 6ms、DPR 上限 2、减少动态静态帧、低端降级、移动触摸与电池。
- 不管：页面布局、玻璃、角色。
- 进入：星场/尘埃/数据流/天气/鼠标跟随；掉帧、压字。
- 交付：粒子层参数、性能预算、降级形态。
- 边界：只决定粒子层，不决定它为何存在；用途与区域由本项目定。

### frontend-anime-fusion（角色与界面）

- 管：三种关系模型（背景层/跨层/内容块）与代价、三分与黄金分割、视线方向、头顶留白 8–12%、角色占屏 55–75%、四层结构、mask 渐隐、blend 正误、抠图边 1px 内发光、面板禁区、遮挡顺序、入场 120–200ms、呼吸 ±2px/4s、视差层级、hover 与点击、scrim 4.5:1、object-position、移动竖屏、素材授权。
- 不管：角色画得好不好看；不决定整体版式与材质。
- 进入：已有角色承担职责、立绘与 UI 共存、面板压脸、裁头顶、像"背景上贴了一张角色图"。
- 交付：空间关系、安全区、裁切、层级、动效节奏。
- 边界：只决定角色与界面的空间关系。

### frontend-ecosystem（多层协作）

- 管：五层职责（场景/表面/角色/氛围/业务界面）、启用/让位/退出/恢复条件、场景就绪交接、连切只提交最新、四级回退、暂停/加载/失败分列、雾化与阅读底色分离、亮/暗/条纹背衬复核、一个表面只由一个提供者承载、角色安全区与等价入口、三种寿命与版本化预设、验收矩阵。
- 不管：单项材质、立绘、粒子参数。
- 进入：背景 + 玻璃 + 角色 + 设置共存；切场景闪黑；设置丢失；增强拖慢任务。
- 交付：层间合同、交接时序、退出/恢复矩阵、验收矩阵。
- 边界：管合同，不管参数；参数由各专项给。

## 三、交接合同

派给专项时，一次给全：

1. 任务句与完成证据；
2. 内容表或两条真实记录；
3. 它定稿的那项决定、范围（页面/区块/表面）、不能改的东西；
4. 约束：术语、已确认字段、对比度、44px、键盘；
5. 交付物与复查条件；
6. 同时在场的其他专项及各自范围。

专项返回时，要求写明：

- 参数/规则；
- 影响范围；
- 回退形态；
- 证据级别（观察到/计算到/推断/待验证）；
- 未解决问题。

缺任何一项，不进入下一层。

## 四、谁定稿什么

| 决定 | 定稿方 | 只读输入/检查 |
| --- | --- | --- |
| 任务句、内容分层、标题/列表/详情 | 本项目 | 内容方、目标用户 |
| 通用营销页节高、动效额度、文案声口 | `frontend-taste-base` | 本项目给任务与内容 |
| 产品页信息三层、字阶、栏宽、section、滚动 | `frontend-apple-minimal` | taste-base 只做文案/动效检查 |
| 工业几何、读数、状态语言、工业配色 | `frontend-industrial-sci-fi` | 本项目给对象与状态事实 |
| 玻璃材质与可读性 | `frontend-liquid-glass` | 本项目给表面位置与背景 |
| 粒子层 | `frontend-particles` | 本项目给用途与区域 |
| 角色空间关系 | `frontend-anime-fusion` | 本项目给角色职责与素材 |
| 层间交接、让位、退出、恢复 | `frontend-ecosystem` | 各专项给本层参数 |
| 识别细节、跨页术语、冲突裁决 | 本项目 | 专项提可行性 |

"排版"必须拆开：

- 节高与节奏：taste-base（通用页）或 apple-minimal（产品页）；
- 字阶、栏宽、产品页 section：apple-minimal；
- 工业读数、编号、标签：industrial-sci-fi；
- 中文断行、标点、行高基线：taste-base 检查，但不改字阶表。

同一页出现两个"排版"负责人时，按页面类型只留一个。

## 五、冲突裁决

顺序：

1. 事实、术语、状态语义优先；视觉不能改写它们。
2. 明确产品要求与无障碍条件同时校验；不满足的候选直接淘汰。
3. 主导语言优先于专项默认值；要改骨架，回到本项目。
4. 同一表面/同一维度只留一个定稿方；不取平均。
5. 拆范围不拆原则：可按页面/区块/表面/场景带分别定，同一范围只能一套。
6. 效果干扰任务：先恢复任务，再把效果移出任务路径，不是调淡。

裁决记录四行：冲突是什么、依据哪条、谁改、复查什么。

### 例 1：工业切角 vs 玻璃圆角

- 冲突：切角要求 `border-radius: 0` 与对角几何；玻璃默认圆滑边缘。
- 裁：轮廓归工业语言；玻璃只提供透明与折射，边缘必须走切角路径。若工具面确需圆角玻璃，把透光限制在独立场景带，不与工业面板同层。
- 复查：切角路径与 1px 边是否同路径；玻璃层是否破坏 `border-radius: 0`。

### 例 2：苹果式弹性节高 vs 一屏一节

- 冲突：taste-base 要整屏节高；产品叙事需要某节更高。
- 裁：叙事区由 apple-minimal 定高度；taste-base 只给文案与动效检查；查询/工作界面高度随内容。
- 复查：长标题、390px、滚动到下一节是否仍有明确起点。

### 例 3：持续氛围动效 vs 阅读稳定

- 冲突：粒子/背景持续运动；正文需要稳定背衬。
- 裁：页面定动效区域与启停；粒子参数归 particles；跨层交接与退出归 ecosystem；阅读区用稳定底色，粒子不进入正文背衬。
- 复查：减少动态下是否有静态形态；关闭后路径是否仍成立。

### 例 4：告警单向升级 vs 业务自动恢复

- 冲突：工业状态只升不降；业务事件会自动恢复。
- 裁：只有锁存告警用显式复位；普通同步状态随有效业务事件更新。状态事实来自业务，不由视觉决定。
- 复查：正常/警告/中断/恢复四态各走一遍。

### 例 5：产品页加局部玻璃

- 冲突：apple-minimal 的留白与字阶 vs 玻璃购买条的模糊范围。
- 裁：叙事、section、字阶归 apple-minimal；玻璃只负责购买条这一块表面。玻璃不得把模糊铺到标题背衬，不得为材质改 section 高度。若玻璃上的文字在亮底/暗底任一端低于 4.5:1，先加承载层或改文字色；仍不行就把玻璃移出文字区。
- 复查：亮底/暗底各测一次；390px；减少透明/关闭模糊。

### 例 6：录音档案首页改版

- 冲突：通用卡片模板要求所有块等权；档案要求按录音日期组织、折叠态可比较。
- 裁：信息结构与字段分工归本项目；taste-base 不得用"一屏一节"压平目录；目录高度随记录数；识别细节（直径图版）可撤下。
- 复查：两条折叠记录能否直接读出演奏形式与目录号。

## 六、台账模板

| 决定 | 定稿方 | 只读输入 | 范围 | 复查条件 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

填法：

- "决定"写成一句可验收的话，不写"整体风格"。
- "定稿方"只能一个；需要两个时拆成两行。
- "只读输入"写清谁提供事实、谁只做检查。
- "范围"写到页面/区块/表面，不写"全站"除非真的全站。
- "复查条件"写成能跑的动作或能算的数。

## 七、没有专项可用时

1. 先确认是不是真的没有：可能是问题没拆对，或专项的边界没读全。
2. 用现有设计系统与原生控件，不硬套风格。
3. 自己实现时，至少给出：参数、回退、对比度、键盘、窄屏五项证据。
4. 在简报里写"能力缺口 + 采用替代 + 待验证"，不假装专项已覆盖。
