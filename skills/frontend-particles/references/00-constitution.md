# 00 · 宪法：粒子何时是信息，何时是噪音

## 判据先行

粒子层只有两种合法性：

1. **空间定向**——告诉用户「你在哪、往哪去」。星场建立纵深，数据流建立方向，天气建立环境。
2. **状态余韵**——动作结束后的残留。点击爆发的 400ms 尾迹、加载完成后的散开。

两种都不成立时，粒子就是噪音。判断只需一问：**把粒子层整层删掉，用户会不会少知道一件事？** 不会，就是噪音。

## 三个反例（真实高频）

| 反例 | 为什么会发生 | 正确的动作 |
|---|---|---|
| 后台管理表格后面铺 300 颗漂浮粒子 | 「看起来太空」 | 空是信息。表格需要的是行距与列对齐，粒子让扫描成本上升 8–12% |
| 登录页加流星雨 + 点击爆点 + 鼠标连线，三个都有 | 每个单独都成立，叠加后互相抢注意力 | 一个页面最多一层粒子、一个交互响应。流星雨与连线二选一 |
| 落地页粒子用品牌色，浓度调高以「强化品牌」 | 把装饰当品牌载体 | 品牌语言属于排版与色彩系统。粒子只借用色值，不承担识别度 |

## 粒子承担信息的三条红线

一旦粒子被要求承载数据，它就不再是粒子层，而是数据可视化，退出本 skill：

- **数量编码**：粒子多少表示进度、库存、人数。
- **颜色编码**：粒子颜色表示状态（红=故障、绿=正常）。
- **位置编码**：粒子落在某个区域表示归属。

为什么划红线：可视化的第一要求是可读、可复现、可无障碍替代。粒子系统天生随机、不可复现、无法被屏幕阅读器读取。用它编码等于放弃这三条。

## 密度与「安静」的量化

安静不是感觉，是可算的：

| 指标 | 舒适区 | 越过之后 |
|---|---|---|
| 单位面积粒子数 | 每 10000 px² ≤ 0.35 颗（1920×1080 → ≤ 72 颗可见） | 视觉噪点，正文扫描速度下降 |
| 单帧新增粒子 | ≤ 6 颗 | 出现「喷泉」感，注意力被出生点吸走 |
| 同屏运动方向数 | ≤ 2 | 超过 2 个方向，人眼无法建立流场 |
| 单粒最大速度 | ≤ 260 px/s | 低于 24px 的粒子会变成拖影噪点 |

1920×1080 = 2,073,600 px²，按 0.35 算约 726 颗理论上限；但正文页的实际可见量应控制在 72–140 颗，因为**粒子只在留白处工作**。

## 什么时候根本不该做粒子

- 页面主要任务是「读」或「填」：文档、表单、后台、结算流程。粒子只会延长首次可读时间。
- 首屏有 LCP 元素是文字或图片：粒子层若在 LCP 之前绘制，会把 LCP 推后 80–300ms。
- 目标设备是低端安卓（< 4GB RAM）：先把主线程让给内容渲染。
- 已有视频背景或渐变噪点背景：两个动态背景叠加必然互相削弱。

## 一票退回（与 SKILL.md 同步）

- 粒子层盖住可点击元素，或 `pointer-events` 非 `none`。
- 正文区域粒子峰值 alpha > 0.18。
- 用粒子编码数据。
- 同屏出现两套以上独立的粒子系统。
- 关掉动画后静态帧不成立（空、乱、无焦点）。
- 降级分支缺失：reduced-motion / 无 WebGL / 低端设备任一未处理。

## 与兄弟 skill 的分界（一句话版）

粒子决定「空间里有没有东西在动」，其余全部不属于这里：材质归 `frontend-liquid-glass`，排版与留白归 `frontend-apple-minimal`，高密度信息结构归 `frontend-industrial-sci-fi`，角色归 `frontend-anime-fusion`。
