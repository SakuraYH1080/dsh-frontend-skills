# 20 · 运动：速度场、力场、噪声流场、拖尾

## 更新顺序（固定，不可调）

```text
1. 累加力 → 加速度 a
2. v += a * dt
3. v *= (1 - drag * dt)          // 阻尼
4. p += v * dt
5. 边界处理（环绕 / 反弹 / 回收）
6. 按寿命算 alpha / size
```

顺序错了结果会不同：先阻尼再累加力，会让「力越大越快」的关系失真；先位移再算力，会引入一帧延迟（可见的「黏手感」）。**为什么固定**：速度积分必须满足 `a → v → p` 的因果链，反过来是求数值上不稳定的一阶格式。

dt 必须秒为单位且夹在 0–0.05s。

## 四类力场

| 力场 | 公式 | 参数 | 视觉 | 典型值 |
|---|---|---|---|---|
| 重力 | `a.y += g` | g px/s² | 下落、加速 | 380（雪花）/ 60（尘埃） |
| 风 | `a.x += wind` | wind px/s² 或常速 | 单向漂移 | ±40（正弦摆动） |
| 漩涡 | `a += perp(p - c) * k / (d + 60)` | k、中心 | 旋转、卷曲 | k = 900 |
| 吸引子 | `a += norm(c - p) * k / (1 + d²/r²)` | k、r | 聚拢、指向 | k = 240，r = 220 |

漩涡的垂直向量写法：

```js
const dx = p.x - cx, dy = p.y - cy;
const d = Math.hypot(dx, dy) + 60;
p.vx += (-dy / d) * k * dt;
p.vy += ( dx / d) * k * dt;
```

**为什么分母要 +60**：中心附近 d→0 时加速度趋于无穷，粒子会被弹飞。加一个软化常数（softening）是物理模拟的标准做法，也让漩涡中心留出一个空洞，视觉上更像真实涡流。

反例：直接 `k/d` 且 k=2000，粒子在中心 5px 内获得 400px/s²，一帧就飞出去。

## 噪声流场

用 simplex noise 采样速度场，而不是每粒随机扰动：

```js
// perlin/simplex 的二维采样，返回值 ∈ [-1,1]
const angle = noise2(p.x * freq, p.y * freq + time * 0.06) * Math.PI * 2 * spread;
p.vx += Math.cos(angle) * strength * dt;
p.vy += Math.sin(angle) * strength * dt;
```

| 参数 | 含义 | 建议 |
|---|---|---|
| `freq` | 空间频率，越小越大团 | 0.0016–0.004（屏幕坐标直接乘） |
| `spread` | 方向分散（弧度倍数） | 1.0（全向）到 0.25（近似单向流） |
| `strength` | 加速度幅度 px/s² | 20–90 |
| 时间项 | 场的流动速度 | `time * 0.05–0.12` |

**为什么用噪声而不是速度场纹理**：噪声是位置的连续函数，相邻粒子拿到相近的方向，才会「成团流动」；每粒独立随机只会得到布朗运动，看起来是抖而不是流。

## curl noise（无散度流场）

simplex 直接当角度会得到「有源有汇」的流：粒子会聚成团再散开。curl 通过取噪声的旋度得到无散场，密度天然守恒：

```js
const e = 0.6; // 采样步长
const n1 = noise2(x, y + e), n2 = noise2(x, y - e);
const n3 = noise2(x + e, y), n4 = noise2(x - e, y);
const vx =  (n1 - n2) / (2 * e);
const vy = -(n3 - n4) / (2 * e);
```

每粒每帧 4 次噪声采样。2000 粒 = 8000 次/帧，simplex 约 0.1µs → 0.8ms，可接受；超过 2000 粒改用预烘焙的 256×256 流场贴图（WebGL 下采样 texture 即可，几乎零成本）。

## 边界处理

| 方式 | 写法 | 适用 | 代价 |
|---|---|---|---|
| 环绕 | `x = (x % w + w) % w` | 无限星场、尘埃 | 无 |
| 反弹 | 反转速度并 ×0.6 | 天气、有容器感 | 无 |
| 回收 | 标记死亡，由发射器重生 | 发射器模型 | 无 |
| 边缘淡出 | 距边界 80px 内 alpha 线性降 | 有明确边界的容器 | 无 |

**为什么优先环绕**：`%` 两次即可，比判断 + 重生便宜；而且粒子从另一侧出现时如果配 `trail=0` 完全无缝。

## 拖尾

两种实现，别混用：

| 方案 | 写法 | 效果 | 成本 |
|---|---|---|---|
| 全屏淡出 | 每帧 `ctx.fillStyle = 'rgba(11,14,20,' + trail + ')'` 全屏填充 | 所有粒子共享同一残影 | 1 次全屏填充，2K 下约 0.6ms |
| 逐粒历史 | 保存最近 6 个位置画折线 | 每粒独立尾迹 | 6× draw call，只适合 ≤300 粒 |

残影长度 ≈ `1 / trail` 帧。`trail = 0.18` → 约 5.5 帧 → 60fps 下 92ms 的视觉记忆。

| trail | 残影（帧） | 观感 |
|---|---|---|
| 0.05 | 20 | 长拖尾，慢速优雅 |
| 0.18 | 5.5 | 默认，有运动感且不糊 |
| 0.35 | 2.9 | 干脆，快速粒子 |
| 0.5 | 2 | 几乎无尾，只有轻微柔化 |

**为什么全屏淡出更优**：它把残影的成本从「每粒 × 历史点数」压到「一次全屏 rect」，而且天然制造「越旧越暗」的效果。代价是背景必须不透明；若粒子层叠在照片上，改用 `globalCompositeOperation = 'destination-out'` 擦除。

反例：用 `ctx.clearRect` 后再画，得到的是硬切，没有尾迹——很多人以为是 trail 参数没生效。

## 密度控制

同屏粒子数不是恒定值：发射器在视口内外的分布会导致密度不均。用「网格配额」压制抖动的热点：

```js
// 每 128px 一格，每格最多 3 颗
const cell = Math.floor(p.x / 128) + ',' + Math.floor(p.y / 96);
const n = (quota.get(cell) || 0);
if (n < 3) { quota.set(cell, n + 1); emit(); }
```

每帧清空 quota。成本：稀疏数组，2000 粒约 0.15ms。

## 速度与寿命的乘积

单粒行程 = `speed × lifeMs / 1000`（无阻力）。设计上这个值应 ≥ 视口短边的一半，否则粒子看起来「原地闪」：

| 场景 | speed | lifeMs | 行程 | 判据 |
|---|---|---|---|---|
| 尘埃 | 12 | 9000 | 108px | 不够，改用噪声流场而非直线 |
| 星场 | 6 | ∞ | ∞ | 靠视差而非寿命 |
| 数据流 | 160 | 1400 | 224px | 需 ≥ 短边 40% |
| 天气 | 88 | 4200 | 370px | 需从顶到底 |

## 常见错误

- 用 `Math.random()` 每帧扰动速度：得到的是抖动而非流场。扰动必须是位置的函数。
- 阻尼写成 `v *= 0.98` 而不乘 dt：帧率不同则行为不同，120Hz 屏上粒子慢一倍。
- 力场参数用「看起来差不多」的值：重力 380 与 400 在 60fps 下差 3% 行程，但配合不同 speed 会差出一个数量级的观感。改一个参数时其他保持不动。
