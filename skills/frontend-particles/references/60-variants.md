# 60 · 四个变体与变体卡格式

## 变体卡（先写卡，再写代码）

每做一个变体，先填满这张卡。六个字段缺一不可，缺的那个就是将来返工的地方。

```text
变体：      starfield / dust / dataflow / weather 之一
用途：      这个页面靠它建立什么空间感（一句话）
参数：      count / size / speed / lifeMs / trail / 场 六项具体数值
视差：      层数 + 每层 depth 与位移系数
交互：      none / repel / attract / follow / burst 中的几项，附半径与力度
降级：      L3 下画成什么样（描述静态帧）
```

**为什么卡片必须先写**：参数之间的关系（speed × lifeMs = 行程）在代码里看不出来，在卡片上是一眼可见的。先写卡能避免「边调边改」导致四个参数互相打架。

## 一、星场 starfield

空间定向：告诉用户「这是一个大的、可探索的地方」。

| 项 | 值 |
|---|---|
| count | 220（距 1920×1080 的 691 上限留 3 倍余量） |
| size | 0.8–2.2px，按 layer 分档 |
| speed | 6 / 14 / 28 px/s（三层），方向统一向左下 |
| lifeMs | ∞（无寿命，靠环绕） |
| trail | 0 |
| 场 | 无外力，纯匀速 + 极弱噪声（strength 8） |

三层视差：

| 层 | 占比 | size | alpha | 移动系数 | 指针位移 |
|---|---|---|---|---|---|
| 远 | 60% | 0.8–1.2 | 0.20–0.35 | 0.25 | 3px |
| 中 | 30% | 1.2–1.7 | 0.40–0.60 | 0.6 | 9px |
| 近 | 10% | 1.7–2.2 | 0.65–0.85 | 1.0 | 18px |

**为什么近层只占 10%**：大而亮的粒子在近处移动快，超过 12% 会让画面变成「雪花屏」，失去深空感。远层撑满面积，提供均匀底噪。

**反例**：所有粒子同尺寸同速度 = 一层会移动的纹理，没有纵深。星场的全部价值在「三层系数差」。

静态帧判据：关掉动画后，仍能看出近、中、远三层密度差异，且右下角有一块较空的暗区（给标题留位）。

## 二、尘埃 dust

环境余韵：几乎察觉不到在动，但页面不「死」。

| 项 | 值 |
|---|---|
| count | 140 |
| size | 1.0–2.6px |
| speed | 12 px/s |
| lifeMs | 9000 |
| trail | 0.05 |
| 场 | curl 噪声，freq 0.0022，strength 26，时间项 0.06 |

**为什么用 curl 而不是 simplex 角度**：尘埃需要「不聚集」。curl 的无散性保证密度守恒，画面永远不会出现一团白斑。

**反例**：用重力做尘埃。3 秒内所有粒子沉到底部，上半屏空白——这是最常见的「尘埃变雪」事故。

静态帧判据：随机截一帧，四角与中心的粒子密度差不超过 2 倍。

## 三、数据流 dataflow

方向与秩序：告诉用户「信息在流动」。

| 项 | 值 |
|---|---|
| count | 260 |
| size | 1.2–2.0px |
| speed | 160 px/s |
| lifeMs | 1400 |
| trail | 0.22 |
| 场 | 沿路径出生 + 风 wind = −40（左向） |

**方向必须单一**。两个方向并存会读成「乱流」而不是「数据」。

| 项 | 值 | 原因 |
|---|---|---|
| 路径数 | 3–5 条 | 单条像进度条，超过 6 条失去结构 |
| 路径间距 | ≥ 96px | 小于 96 会读成一组竖线 |
| 出生密度 | 每路径 4–8 粒/秒 | 与 speed 160 配合，形成可数的「列」 |
| 拖尾 | 0.22 → 残影 4.5 帧 = 75ms | 与 1400ms 寿命配合，拖尾占行程 1/6 |

**为什么用 trail 而不是逐粒历史**：数据流的视觉核心是「线」，全屏淡出天然产生线与线的叠加，成本恒定。逐粒历史在 260 粒时要 1560 次 draw call。

静态帧判据：单帧里能看出至少 3 条平行且等距的粒子列，列内粒子大小一致。

## 四、天气 weather

氛围与落点：让页面有温度、有时间。

| 项 | 值 |
|---|---|
| count | 320 |
| size | 1.4–3.0px |
| speed | 88 px/s |
| lifeMs | 4200 |
| trail | 0.10 |
| 场 | 重力 g = 380，风 wind = ±40（正弦，周期 7s） |

| 天气 | 变化 | 判断 |
|---|---|---|
| 雪 | speed 60–90，size 2.0–3.0，风 ±60，水平漂移 | 必须能看出横向摆动 |
| 雨 | speed 200–280，size 1.0–1.4，风 ±20，trail 0.28 | 必须是线不是点 |
| 灰烬 | speed 24–40，size 1.0–2.0，风 ±80，alpha 上限 0.35 | 必须向上飘（重力取负） |

**为什么雨必须用 trail**：雨的识别度来自「线」而不是「点」。没有拖尾的 250px/s 粒子在 60fps 下每帧移动 4.2px，看起来是一串点。

静态帧判据：雪要有横向位移的散点；雨要能数出至少 30 条斜线；灰烬的方向必须与雨相反。

## 变体选择表

| 页面类型 | 首选 | 次选 | 不要用 |
|---|---|---|---|
| 落地页首屏（大字 + 一个 CTA） | 星场 | 尘埃 | 数据流（抢方向感） |
| 长文阅读页 | 尘埃 | 无 | 星场（近层移动干扰阅读） |
| 监控/数据看板 | 数据流 | 无 | 天气（情绪与数据冲突） |
| 节日/活动页 | 天气 | 星场 | 数据流 |
| 404 / 空状态 | 尘埃 | 星场 | 全都不要堆三个 |

## 混用规则

一个页面最多一个变体。若确实需要两种（如首屏星场 + 页脚尘埃），必须满足：

1. 分处不同滚动区间，同一时刻不可见。
2. 共用同一个 canvas 与同一个池（用两套发射器参数，不是两个实例）。
3. 粒子总数取两者上限的较大值，不叠加。

**为什么**：两个独立实例意味着两套 rAF、两个 backing store、两份降级逻辑。总成本约等于 1.8 倍，而视觉收益在 1.05 倍左右。

## 反 AI 模板化的提醒

不要把四个变体做成四个「皮肤」（只改颜色）。变体的差异在**场的类型**和**方向性**：

- 星场 = 无场 + 三层视差
- 尘埃 = 无散场 + 极低速
- 数据流 = 单方向 + 沿路径出生
- 天气 = 恒定加速度 + 落点

只改色值而保留同一套运动，等于同一个东西换了四个颜色，用户能看出来。
