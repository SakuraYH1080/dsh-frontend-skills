# 液态玻璃材质（frontend-liquid-glass）

这个 skill 只做一件事：**把"玻璃"当成一种有物理成因的材料来设计**，而不是给元素加一行 `backdrop-filter: blur(20px)`。

它不决定页面长什么样。版式、栅格、字体、色彩体系、动效节奏属于别的地方；这里只回答玻璃这一个问题：**这块材料是什么玻璃、它盖住了什么、它自己怎样被光照到、它在什么情况下会失效。**

## 一、什么时候用 / 不用

**用**

- 界面已经有背景（照片、视频、渐变、3D、壁纸），需要一层浮起来的操作面板。
- 导航栏、侧栏、播放器、工具条、HUD 面板、通知卡、弹窗、底部抽屉需要"半透明但压得住背景"。
- 已有玻璃但糊成一片：文字发灰、多个玻璃层叠后变脏、边缘没有厚度、滚动时闪烁。
- 玻璃在 iPhone 上掉帧、在低端安卓上黑白闪烁、Safari 与 Chrome 观感不一致。
- 需要一套可复算的参数，而不是凭感觉拖滑块。

**不用**

- 背景本身就是纯色或纯色渐变，且没有内容从下面穿过 —— 玻璃在这里只会增加 GPU 开销，换不来任何信息（改用分层色与阴影）。
- 用户要的是"整体风格"：那是另外四个 skill 的职责。这里给的玻璃可以套在任何风格上，但不会替它决定风格。
- 只是要圆角、投影、卡片描边 —— 那是普通表面，不是玻璃。
- 需要"玻璃"承担信息编码（例如用透明度表示优先级）：透明度不是可靠的编码通道，改用位置、尺寸、颜色。

| 用户实际要的 | 交给谁 | 为什么不是这里 |
| --- | --- | --- |
| 整页的层级、留白、字阶、滚动叙事、长页节奏 | `frontend-apple-minimal` | 玻璃不改版式，只改一块材料的透光、厚度与边缘 |
| 会动的背景：星场、尘埃、数据流、鼠标跟手、点击爆发 | `frontend-particles` | 玻璃是静止的表面；粒子归谁、怎么动、怎么降级不在本 skill 里 |
| 二次元立绘与面板的空间关系、角色压不压脸、竖屏裁切 | `frontend-anime-fusion` | 本 skill 不生产角色，也不决定角色站在哪一层 |
| HUD 模块、切角、编号、状态三态、工业控制台 | `frontend-industrial-sci-fi` | 这里只给材质，不给视觉语言与信息架构 |

组合只能在用户明确要求时发生，且必须指定一个主导语言：材质归本 skill，页面结构、叙事与信息架构归主导方，本 skill 只做局部增强。

## 二、核心原则与硬边界

### 原则 1：玻璃是"关系"，不是"滤镜"

一块玻璃之所以看起来像玻璃，来自四件事同时成立：

| 成因 | 物理来源 | 代码对应 | 缺失后的症状 |
| --- | --- | --- | --- |
| 模糊 | 表面粗糙度散射 | `backdrop-filter: blur(Npx)` | 背景细节穿透，文字被花纹干扰 |
| 折射 | 厚度导致的偏移与放大 | `feDisplacementMap` / 边缘 `scale` 变形 | 像一张半透明贴纸，没有厚度 |
| 边缘高光 | 侧壁受光 | 内阴影 `inset 0 1px 0`、1px 亮边 | 没有边界，看不出材料在哪结束 |
| 环境色渗透 | 透射光带色 | `saturate()` + `brightness()` + 色调叠加 | 玻璃永远是灰的，和背景脱节 |

少任何一条，观感都会退化成"半透明 div"。**四件事必须一起设计**，这是本 skill 的第一条硬边界。

### 原则 2：玻璃的对比度来自"它自己"，不来自背景

玻璃后面的内容每帧都在变，任何依赖背景的对比度都是不稳定的。可读性必须由玻璃自己提供：
文字色 + 玻璃自身亮度 + 一层足够不透明的"承载层"。算例见 `references/40-performance-a11y.md`。

**硬边界**：正文文本与玻璃的对比度必须 ≥ 4.5:1，且这个值要在**背景最亮**和**背景最暗**两种极端下都成立。做不到就不要在这块玻璃上放正文。

### 原则 3：每多一层玻璃，模糊半径要减半

层叠玻璃是这类设计最常见的崩坏点。两层 `blur(24px)` 叠加后有效模糊远大于 24，边界消失成一团雾。

**硬边界**：同一视觉栈内玻璃层数 ≤ 3；第 2 层 blur × 0.5，第 3 层 blur × 0.25，并且第 2 层起必须提高底色不透明度（+12% / +22%）。

### 原则 4：玻璃只做"浮起来的东西"

玻璃表达的是**层级**：它离用户更近。因此玻璃只用在覆盖层、临时层、工具层。把它用在页面主体容器上，会让整个页面变成"所有东西都浮着"，层级信息归零。

### 原则 5：可降级是一等公民

玻璃是增强，不是结构。**关掉模糊之后，界面的层级、可读性、可操作性必须完全不变**，只是少了质感。做不到就说明结构依赖了材质。

### 一票退回

- 用玻璃遮住关键信息再靠 hover 才显示。
- 玻璃上的文字是 12px 以下的浅灰色。
- 三层以上玻璃叠在一起。
- 用 `filter: blur()`（模糊元素自身而不是背景）冒充玻璃，导致内容一起被糊掉。
- 只写了 `-webkit-backdrop-filter` 或只写了标准属性。
- 在 `prefers-reduced-transparency` 下仍是全透明。

## 三、可调参数与设计变体

完整的参数表在 `references/10-parameters.md`，四套场景变体在 `references/50-variants.md`。这里是骨架：

**九个可调旋钮**

1. `--lg-blur` 背景模糊半径（px）
2. `--lg-saturate` 背景饱和度放大（%）
3. `--lg-brightness` 背景亮度（%）
4. `--lg-tint` 玻璃自身的底色与不透明度
5. `--lg-border` 边缘宽度与亮度
6. `--lg-highlight` 上沿内高光强度
7. `--lg-shadow` 外投影（近距 + 远距两段）
8. `--lg-refraction` 折射强度（SVG 位移比例）
9. `--lg-noise` 表面细噪声（消除大面积纯色带来的塑料感）

**四套预设**

| 预设 | blur | saturate | tint α | 场景 |
| --- | --- | --- | --- | --- |
| `thin` 薄雾 | 12px | 130% | 0.28 | 悬停工具条、标签、芯片 |
| `standard` 标准 | 24px | 160% | 0.42 | 导航栏、侧栏、播放器 |
| `deep` 厚玻璃 | 40px | 180% | 0.55 | 弹窗、抽屉、模态 |
| `frost` 磨砂 | 8px | 100% | 0.72 | 需要高可读性的数据面板 |

参数不是越多越好：**一个产品只用一套预设 + 一个变体差异**，否则玻璃本身会变成风格噪音。

**读取纪律**：先读本文件的第二节与第三节；确认任务属于哪个场景后，只开对应的 1–2 个 reference。参数实验室 `templates/lab.html` 用浏览器直接打开即可拖动九个旋钮。

**运行期契约（`assets/glass.js`，唯一全局 `window.LiquidGlass`）**

| 成员 | 签名 | 作用 |
| --- | --- | --- |
| `LiquidGlass.init(cfg?)` | `{ refract, guard, scale } = { true, true, 9 }` | 注入 SVG 折射滤镜、按设备能力加 `.lg-lite`、启动滚动性能守卫。**返回 undefined**，不要写 `const x = LiquidGlass.init()`。 |
| `LiquidGlass.supportsBackdrop()` | `() => boolean` | 检测 `backdrop-filter` 是否可用；不可用时调用方应自己切到实心底。 |
| `LiquidGlass.injectRefraction(cfg?)` | 同 init 的 cfg | 单独注入 `#lg-refract` 滤镜，内部包了 try/catch。 |
| `document` 事件 `lg:degraded` | `detail: { fps }` | 守卫判定持续掉帧时派发一次，此后**不再回升**。用它打点，不要重复监听做升降档。 |

降级判定线：`deviceMemory ≤ 2`、`hardwareConcurrency ≤ 4` 或 `saveData` 为真时直接低配；守卫在 300ms 窗口内连续 3 次低于 45fps 才触发降级。

**不要把 `init` 写在动画帧里**：它挂监听、建 SVG，一次就够。

## 五、执行流程

1. **判定是否该用玻璃**：背景是否有内容穿过？是否有真实的层级需要表达？两个都"否"就停，改用分层色。
2. **选预设**：按第三节的表选一个，写进交付说明的"材质卡"（三行：预设 / 变体 / 降级策略）。
3. **定承载层**：先决定文字坐在什么不透明度上，再决定玻璃多透。顺序不能反。
4. **写参数**：从 `assets/tokens.json` 取九个旋钮的值，落到 CSS 自定义属性，一处定义。
5. **补四件事**：模糊、折射、边缘高光、环境色。缺一项就退回第 4 步。
6. **过降级**：`prefers-reduced-transparency`、不支持 `backdrop-filter`、低端设备、打印。
7. **过可读性**：按 `references/40-performance-a11y.md` 的算例，在最亮与最暗背景上各测一次。
8. **过性能**：滚动时测帧；移动端测电池档位；确认没有 `will-change` 常驻。

## 六、交付检查清单

- [ ] 玻璃只出现在覆盖层 / 工具层，没有变成页面主体容器。
- [ ] 四件事齐全：模糊、折射（或等效边缘变形）、边缘高光、环境色渗透。
- [ ] 同一栈玻璃层数 ≤ 3，且每层按 0.5 / 0.25 递减并提高不透明度。
- [ ] 正文对比度在**最亮背景**与**最暗背景**下都 ≥ 4.5:1（给出两个实测值）。
- [ ] 同时写了 `backdrop-filter` 与 `-webkit-backdrop-filter`。
- [ ] `prefers-reduced-transparency: reduce` 下有实心回退，且层级仍可辨。
- [ ] 浏览器不支持 `backdrop-filter` 时（`@supports not`）有回退，不是一片空白。
- [ ] 移动端 60fps；无 `will-change` 常驻；无滚动时逐帧重绘。
- [ ] 没有用 `filter: blur()` 模糊元素自身。
- [ ] 打印样式里玻璃退化为白底 + 细边。
- [ ] 材质卡写在交付说明最前面（预设 / 变体 / 降级策略）。
