# 10 · 字阶、间距、网格、栏宽、灰阶

数值全部可复算，唯一权威是 `assets/tokens.json`。本文件里出现任何与它冲突的数字，一律以 tokens.json 为准，并视为本文件的 bug。

## 1. 两套模块化字阶（选一套，全域不换）

极简页的字号不是"挑好看的大小"，是一条**等比数列**。等比意味着任意两级之间的比值恒定，读者的眼睛只要学会一次"这是下一级"，就能在整页复用。

| 比例 | 序列（px） | 相邻比 | 适合 |
| --- | --- | --- | --- |
| 1.25（大三度） | 17 / 21 / 27 / 33 / 41 / 52 | ×1.25 | 信息密度高的文档站、参数多的产品页 |
| 1.333（纯四度） | 17 / 23 / 30 / 40 / 54 / 72 | ×1.333 | 一句主张撑一屏的发布页、品牌站 |

**为什么只有两套，不是"随便选比例"**：1.2 以下的相邻两级只差 3–4px，在 2x 屏上分辨不出层级，读者会把 h2 当正文加粗；1.414 以上，h1 到 body 的落差会超过 4 倍，页面读起来像"标题 + 一堆小字"，中间层形同虚设。1.25 与 1.333 是唯一两个"六个层级都清晰、落差又不失控"的比例。

**为什么两套的 body 都是 17px**：17px 是中文正文的可读下界（见 `50-responsive-a11y.md` 第 2 节）。比例只决定往上怎么长，不决定起点 —— 起点被可读性锁死。

### 落到 clamp()（本项目实际用值）

流体字号用一条线性插值：`clamp(下限, 斜率 × 100vw + 截距, 上限)`。斜率与截距由「在 480px 视口取到下限、在 1280px 视口取到上限」两个点解出。

| 角色 | token | 值 | 480px 时 | 1280px 时 |
| --- | --- | --- | --- | --- |
| `--fs-h1` | h1 | `clamp(40px, 4vw + 20.8px, 72px)` | 40px | 72px |
| `--fs-h2` | h2 | `clamp(30px, 2.25vw + 19.2px, 48px)` | 30px | 48px |
| `--fs-h3` | h3 | `clamp(23px, 0.875vw + 18.8px, 30px)` | 23px | 30px |
| `--fs-lead` | lead | `clamp(18px, 0.375vw + 16.2px, 21px)` | 18px | 21px |
| `--fs-body` | body | `clamp(16px, 0.125vw + 15.4px, 17px)` | 16px | 17px |
| `--fs-small` | small | 15px（固定） | 15px | 15px |
| `--fs-caption` | caption | 13px（固定） | 13px | 13px |

算法复算：h1 的下限 40 在 480px 出现，上限 72 在 1280px 出现 → 斜率 = (72−40)/(1280−480) = 0.04 = 4vw 的系数；截距 = 40 − 0.04×480 = 20.8。**改任何一端，两个数必须一起改**，只改 clamp 里的 px 会让曲线在中间段折角。

**为什么 small 与 caption 不用 clamp**：15 与 13px 已经是下限，再缩就不可读；而它们不承担层级，固定值反而稳定。给它们写 clamp 只会让 13px 在手机上变成 12.4px。

**反例**：`clamp(14px, 2vw, 64px)`。斜率的绝对量大，在 900px 视口上就是 32px —— 一个本该是正文段的位置突然变成标题，全站节奏被一个 clamp 毁掉。

## 2. 光学校正：字号、行高、字距必须三联动

字号放大时，字形的绝对留白按比例放大，观感从"紧凑"变"散"。所以大字要收字距、压行高，小字反过来。

| 字号区间 | 字距 | 行高 |
| --- | --- | --- |
| ≥ 40px | −0.04em ~ −0.03em | 1.06 – 1.10 |
| 24 – 39px | −0.03em ~ −0.02em | 1.10 – 1.20 |
| 17 – 23px | −0.005em ~ 0 | 1.40 – 1.50 |
| ≤ 16px | 0 ~ +0.01em | 1.35 – 1.50 |

本项目的落点：h1 −0.04em / 1.08，h2 −0.03em / 1.12，h3 −0.02em / 1.2，lead 0 / 1.45，body 0 / 1.65，small 0 / 1.5，caption +0.01em / 1.4。

**中文的特殊处理**：中文字身是满格方块，字距收到 −0.04em 时相邻笔画会粘连（"国"与"园"的边框连成一条线）。中英混排时英文用 tokens 值，中文单独写：

```css
:lang(zh) h1, :lang(zh) h2 { letter-spacing: -0.02em; }
```

**可变字重的用法**：标称值 600 只在**确认字体有 600 这一档**（可变字体，或系统里真有 Semibold）时使用。做法是写 `font-weight: 600` 让浏览器走 variation 轴，不写 `font-variation-settings`（后者会覆盖掉 `font-weight` 与继承，且不能与 `font-optical-sizing` 并存）。没有 600 档时回退到 700（真实 Bold），**不要让它合成**：`synthetic bold` 会把笔画往右加粗 0.5–1px，汉字横画粘连、字宽不齐，14px 以上一眼能看出。可用 `font-synthesis: none` 强制暴露这个问题。

**反例**：标题写 `letter-spacing: 0.02em` 求"高级感"。正字距会让大字的字间空隙比笔画还宽，标题散架成一个个孤立的方块 —— 这是最容易被一眼看穿的"模板感"。

## 3. 8pt 基准与间距阶梯

所有间距从 **8px** 派生，只有两段刻度：

| 用途 | 值 |
| --- | --- |
| 内容内（图标与文字、标题到正文、段落之间） | 8 / 16 / 24 / 32px（`--gap-1` … `--gap-4`） |
| 段与段之间 | 64 / 96 / 128 / 160px（`--section-xs` … `--section-l`） |

**为什么两段刻度而不是一条连续阶梯**：内容内间距服务于"这些东西属于一起"，段间间距服务于"这里换了一个话题"，两个尺度的语义不同。用一条连续阶梯（4/8/12/16/24/32/48/72…）时，人会在 24 与 32 之间反复犹豫，最后每个 section 用不同的值，页面出现"手调感"。

**为什么是 8 不是 4 或 10**：8 能被 2、4 整除，在 DPR 1 / 1.5 / 2 / 3 下都落在物理像素整点上。4 太碎，会诱使人在每处微调；10 与 12 的公约数只有 2，一半间距会落在半像素，1px 描边在非整数位置发虚。

**段间距的四档怎么选**

- `--section-xs` 64px：只换块不换话题（同一节的第 2、3 张图）。
- `--section-s` 96px：常规换段，最常用。
- `--section-m` 128px：换话题，且下一段有自己的小标题。
- `--section-l` 160px：页首、CTA 前、全幅视觉块前后。

**硬规则**：相邻两段的间距不得同档。同档会让两段黏成一段；差两档以上（96 → 160）会让人觉得"漏了一段"。

**section 的流体写法**（窄屏不用 160px，否则手机上会以为页面断了）：

```css
--section-fluid-xs: clamp(56px, 7vw, 96px);
--section-fluid-m:  clamp(72px, 9vw, 128px);
--section-fluid-l:  clamp(88px, 11vw, 160px);
```

**hero 的留白是另一条规则**：hero 文字块上下留白合计 ≥ 视口高 × 0.36。1000px 高的视口，上下空白合计至少 360px。少于这个数，首屏就变成"标题顶着导航、下面紧接下一节"的信息墙。

**反例**：全站 section 都用 `padding: 120px 0`。120 不在任何一档上，且在 768px 宽时占掉屏幕的 1/6，在 1440px 时又显得挤 —— 这正是"哪里都对、合起来不对"的来源。

## 4. 容器、栏宽与网格

| 项 | 值 | 理由 |
| --- | --- | --- |
| `--container` | 1120px | 三列内容刚好落在约 30cm 的自然视野内 |
| `--container-wide` | 1440px | 全幅视觉块的极限，再宽就要靠留白撑 |
| `--measure` | 600px | 正文栏宽 —— 17px 下中文约 35 字/行、英文约 71 字符/行 |
| `--measure-narrow` | 480px | 图注、引文、侧栏 |
| `--gutter` | `min(6vw, 96px)` | 内容永不贴边；96px 封顶，避免超宽屏把内容挤成窄条 |

**为什么正文是 600px 而不是 68ch**：`ch` 是"0"的字宽，中文字体里 0 与汉字宽度不等，中文用 `ch` 量出来的行宽会偏窄 —— 68ch 在中文下约 21 字/行，低于舒适区。改用 px 锁死，中英混排时行宽一致，同时把"换字号导致行宽漂移"这件事挡掉（字号已经被 clamp 限制在 16–17px，600px 始终落在 35 字上下）。

实测：600px ÷ 17px ≈ 35.3 个汉字；600px ÷ (17px × 0.5) ≈ 70.6 个英文字符。两条都落在舒适区中部（中文 32–38 字、英文 60–75 字符）。

**为什么不用百分比**：容器变宽时百分比跟着变，1920 屏上会拉成 90 字符/行，回读时眼睛找不到下一行开头（超过 75 字符，扫视落点误差超过一行）。

**网格**：只用 12 栏在 ≥ 1200px 生效，900–1199 用 8 栏，< 900 单栏。分栏比例只有两种：**5:7**（文 + 图）与 **6:6**（对等两栏）。7:5 会让图的视觉重量压过文字，读者只看图不看字。三栏时 4:4:4，任何一栏超过 5 就等于回到两栏。

```css
.split { display: grid; grid-template-columns: 5fr 7fr; gap: var(--gap-4); }
@media (max-width: 900px) { .split { grid-template-columns: 1fr; } }
```

## 5. 九级灰阶与单一强调色

九个值，各自绑定一个角色。不是调色盘，是**职位表**。

| token | 值 | 角色 | 白底对比度 |
| --- | --- | --- | --- |
| `--n-0` | `#FFFFFF` | 页面底 | 1.00 |
| `--n-1` | `#F8F8F9` | 分区底、代码块 | 1.06 |
| `--n-2` | `#EDEDEF` | 分隔块、hover 底 | 1.17 |
| `--n-3` | `#C6C6CB` | 禁用边、1px 分隔线 | 1.70 |
| `--n-4` | `#9A9AA1` | 装饰性文字（**不承载信息**） | 2.80 |
| `--n-5` | `#73737B` | 次要文字、图注 | 4.70 |
| `--n-6` | `#4C4C53` | 正文辅助段落 | 8.52 |
| `--n-7` | `#31313A` | 正文、标题 | 12.88 |
| `--n-8` | `#0A0A0C` | 反色底、按钮底 | 19.78 |

**为什么是九个**：三个明度段（底 0–2 / 线 3 / 文字 4–7）+ 一个反色底，正好覆盖"底、分隔、三级文字"。少于九个会逼出临时值（`#666`、`#888`），多于九个没人记得住谁是谁，最后每个组件自己挑一个。

**关键判据**：`--n-4` 只有 2.80:1，**只能出现在不承载信息的装饰上**（大号水印字、分隔标）。15px 正文用它是违规的 —— 这是极简页最常见的隐形可读性事故，因为淡灰在设计师的大屏上"看起来很雅"。

**强调色只有一个**：`#0A6CFF`。它在白底 4.56:1（够 3:1 的图形门槛，不够 4.5:1 的正文门槛），所以：

| 用途 | 用哪个 | 实测 |
| --- | --- | --- |
| 图形、描边、焦点环、按钮底 | `#0A6CFF` | 白底 4.56:1 |
| 正文里的链接文字（白底） | `#0055D4` | 6.46:1 |
| 深色底上的链接文字 | `#5EA8FF` | 8.03:1（于 `#0A0A0C`） |

**为什么不在白底用 `#0A6CFF` 写正文链接**：4.56 只比 4.5 高 0.06，屏上有抗锯齿与次像素渲染损耗，实测观感接近门槛；而且它在 `--n-1`（#F8F8F9）底上会掉到 4.28。链接必须扛得住不同底色，所以文字版压深一档。

**反例**：强调色同时用于按钮、链接、图标、标签、图表五处。极简页的强调色只标"这里可以点"和"这里是重点"，出现超过 4 次/两屏就失去指示作用 —— 满屏蓝点等于没有重点。

## 6. 深色模式不是反色

深色模式用**重新映射**，不是 `filter: invert()`，也不是把 n-0 与 n-8 对调。反色会把照片、插画、品牌色一起翻掉，并让 `#FFFFFF` 变成纯黑（对比过强、发灰）。

| 角色 | 亮色 | 暗色 |
| --- | --- | --- |
| 页面底 | `#FFFFFF` | `#0A0A0C` |
| 卡片 / 分区底 | `#F8F8F9` | `#111114` |
| 正文 | `#31313A` | `#C6C6CB`（11.62:1） |
| 次要文字 | `#73737B` | `#9A9AA1`（7.07:1） |
| 分隔线 | `#C6C6CB` | `#2A2A2F` |
| 链接 | `#0055D4` | `#5EA8FF`（8.03:1） |

三条规则：

1. **暗色正文不用纯白**。`#FFFFFF` 在 `#0A0A0C` 上是 19.78:1，长文阅读会光晕（halation），实际用 `#C6C6CB`（11.62:1）。
2. **暗色底比亮色底"更暗一档"**。亮色页的底是 n-0，暗色页的底是 n-8 再压一点（`#0A0A0C`），而"分区底"只比它亮 7 个色阶（`#111114`）—— 暗色下分层的可辨区间比亮色窄，间距要收。
3. **强调色必须换一支**。`#0A6CFF` 在 `#0A0A0C` 上只有 4.33:1，做大字或粗描边勉强，做正文链接不够；暗色链接一律 `#5EA8FF`。

**反例**：暗色模式里仍用 `rgba(0,0,0,0.06)` 做分隔线。它在深底上等于不存在，页面失去所有分区边界，读者分不清哪几段是一组。

## 7. 规则

1. 一套页面只用一套比例（1.25 或 1.333）；混用视为版式错误。
2. 字号只从 `--fs-*` 七个 token 里取，不写第八个值。
3. 所有间距 ∈ {8,16,24,32,64,96,128,160}；出现 20/30/50/120 一律改回阶梯值。
4. 正文 `max-width: var(--measure)`（600px）；宽屏下实测行宽不得漂移。
5. 灰阶只用 `--n-0` … `--n-8`；`--n-4` 不得承载信息。
6. 彩色只有一个；正文链接用 `--accent-text`，图形用 `--accent`，暗底用 `--accent-text-dark`。
7. 深色模式走 `:root[data-theme="dark"]` 重新映射，禁止 `invert()`。
8. 改 tokens 里任何一个数，必须同时改本文件对应表格、`assets/apple-minimal.css` 的 `:root`，三处一致才算改完。
