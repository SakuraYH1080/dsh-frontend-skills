# 00 · 极简的判据：删到什么程度为止

极简不是「少放东西」，是「放的东西每一个都在承担一个不可替代的功能」。
这份文件只回答一个问题：**这一块该不该留。**

---

## 1. 为什么极简会失效

### 1.1 极简的反面不是拥挤，是「没有主次」

一个满屏内容的页面，如果字号层级清楚，读者依然能读；一个只有三个元素的页面，如果三个都一样大，读者会不知道该看哪。
所以极简的第一性目标不是「减法」，是**排序**。减法只是排序的副产品。

反例：整页只有 logo、一句标语、一个按钮，三者字号分别是 18/18/18——极简到极致，也读不出重点。

### 1.2 决策成本守恒

每增加一个视觉变量（字号档、颜色、边框、圆角、阴影、图标），读者要做的区分就多一次。
认知负荷实验的常用结论是：人在一屏内能稳定区分的**视觉层级**不超过 3 层，超过之后分类会退化成「大的/小的」二分。
所以层级上限是 3，不是审美偏好，是**分辨能力上限**。

### 1.3 空白的边际收益会反转

留白增加，可读性上升；但超过某点之后，读者的**内容预期**落空，会开始怀疑「是不是没加载完」。
单 section 的空白占比在 45%–60% 之间最稳；超过 70% 且没有视觉锚点（大字、大图、强对比元素），页面会显得空。
所以 hero 可以到 75%（因为有 h1 做锚），普通正文 section 停在 55% 左右。

## 2. 三层结构：主张 / 证据 / 细节

| 层 | 承担什么 | 典型元素 | 占视口 | 字号 | 每页数量 |
|---|---|---|---|---|---|
| 主张 | 这一屏要读者记住的一句话 | h1 / h2 / 一个大数字 | 0.8–1.2 | 30–72px | 一屏一个 |
| 证据 | 凭什么信 | 产品截图、数据、客户引言、对比图 | 0.5–1.0 | 17–21px | 每个主张 1–2 个 |
| 细节 | 想深究的人要什么 | 正文段落、参数表、FAQ | 0.3–1.5 | 15–17px | 按需 |

### 为什么只有三层

第四层意味着读者必须**记住**前三层的关系才能读到它。记忆成本 > 信息收益，读者会跳过。
需要第四层时，正确做法是**拆页**（新建 section 或新路由），不是加字重。

反例：h1 48px / h2 30px / h3 20px / h4 17px / h5 15px 全部同页出现——实际效果是 h4、h5 与正文无法区分，等于浪费两档。

## 3. 删减四问

对页面上的每一块内容依次问：

**问 1：删掉它，读者会失去一条信息，还是只失去一种感觉？**
只失去感觉 → 删。判断方法：把这块遮住，剩下的内容是否还能让读者做出同样的决定。

**问 2：这条信息在别处已经说过吗？**
说过 → 删重复的那一份，保留信息密度更高的那一份。同一个卖点在一页里出现两次，第二次的边际说服力下降约 60%（读者会认为你在凑数）。

**问 3：它是证据，还是形容词？**
「极致轻薄」是形容词，「1.24kg，比上代轻 180g」是证据。形容词删掉换成数字；换不出数字就删掉整句。

**问 4：它服务的是主张、证据还是细节？**
三者都不服务 → 删。服务不明确 → 先放进「细节」层，看它是否撑得住 15px 字号；撑不住就是废话。

### 四问的用法

不要一次问完四问再动手。**逐块问，问完立刻删**，删完再问下一块。批量问会导致你开始为保留找理由。

## 4. 删到哪为止：三条停止线

**停止线 A · 信息线**：再删一条，读者就无法回答「这是什么、凭什么信、怎么获得」三问中的任意一问。
**停止线 B · 节奏线**：相邻两个 section 的主张之间，仍然存在可复述的递进（是什么 → 凭什么 → 多少钱 → 现在做）。
**停止线 C · 识别线**：删掉某个元素后，页面仍然能被认出是「谁的页面」（品牌名、产品形态、独有的一句话）。

三条线同时满足即停。任何一条被突破，说明删过头了，往回加一层。

反例：把所有 section 压成一个长段落——信息还在，节奏没了，识别度也没了。

## 5. 一票退回清单（与 SKILL.md 第二节同步）

任意一条命中即退回，不进入"整体看起来还行"的收尾。

1. 首屏出现两个以上同等重量的主张（两个大标题、两段等长的解释）。
2. 正文栏宽超过 660px 或小于 520px。
3. 出现三套以上间距值（例如同时有 20、24、30、48）。
4. 标题字距为正（大字加字距会让标题散架）。
5. 强调色在两屏内出现超过 4 次，或出现第二种彩色。
6. 正文对比度 < 4.5:1，或 15px 以下文字用 `--n-4` / `--n-5`。
7. 滚动区里用 `scroll-behavior: smooth` 做逐段吸附（scroll-hijack）。
8. 揭示动画的初始态是 `opacity: 0`，且 JS 未加载时元素仍然不可见。
9. 容器上写了 `overflow: hidden`，导致内部 `position: sticky` 静默失效。
10. 深色模式用 `filter: invert()` 或直接反色实现。

补充三条工程判据（不在 SKILL.md 主列，但同样一票退回）：

11. 动效里出现 `width` / `height` / `top` / `left` / `margin` / `box-shadow` 的过渡。
12. 图片与视频没有显式 `aspect-ratio`，滚动时引发布局跳动（CLS > 0.1）。
13. 未写 `prefers-reduced-motion` 分支。

## 6. 常见误判

| 你以为 | 实际 | 正确做法 |
|---|---|---|
| 极简 = 只用黑白 | 极简 = 层级清楚；黑白只是最容易做到的默认 | 单强调色 + 9 级灰阶，别再减 |
| 极简 = 大量留白 | 留白要有锚点，否则是「空」 | hero 75%、正文 section 55% |
| 极简 = 不要动效 | 极简 = 动效只解释变化 | 保留 120/240ms 的状态反馈，砍掉叙事性飞入 |
| 极简 = 字体越细越好 | 细字重在中文小字号下笔画会断 | 正文 400，标题 600，不要 300 |
| 极简 = 一张大图 + 一句话 | 那只是 hero 的一种 | 见 20-narrative.md 的三种结构 |

## 7. 规则

- **规则**：每一块内容必须能回答「我服务哪一层」，答不出就删。
- **规则**：层级数 ≤ 3，字号档 ≤ 7，强调色 = 1。
- **规则**：删减以三条停止线收尾，不以「感觉差不多了」收尾。
