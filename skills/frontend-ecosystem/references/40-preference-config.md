# 40 · 偏好的寿命、写入与预设

> 只在"设置存不住""两个窗口互相覆盖""导入预设把资产弄丢了""自动主题又把我改回去了"时读。

## 1. 三类数据，三种寿命

| 类别 | 例子 | 存在哪 | 失效条件 | 能否导出 |
| --- | --- | --- | --- | --- |
| 业务事实 | 当前会话、消息、笔记内容、已读进度 | 业务库 | 用户删除 / 同步冲突 | 单独导出，不进主题包 |
| 长期偏好 | 选中背景、玻璃数值、角色开关、缩放 | 版本化设置 + 预设 | 用户改 / 导入预设 | 是 |
| 运行事实 | 首帧是否就绪、可见性、provider 选型、失败冷却、拖动比例 | 内存 | 刷新即失效 | 否，永远不导出 |

**硬约束**：运行事实一旦写进设置文件，就会出现"刷新之后应用以为某个 provider 还活着"这类幽灵状态。

**命名空间**：设置项按命名空间分组（如 `appearance.*` / `scene.*` / `actor.*`），写差分时按命名空间整批发。

## 2. 写入路径

### 2.1 输入 → 预览 → 合并 → 落盘

```text
输入事件（拖动滑块）
  → 立即应用视觉（live 预览，不动字体等重计算）
  → 标记 dirty，启动 200ms 合并窗口
  → 窗口到期：按命名空间收集差分，一批写入
  → 宿主：排队 → 写临时文件 → rename 原子替换
  → 回传成功组 → 推进基线
```

【源码】证实存在 `setTimeout(flushPersist, 200)`，字体设置同一窗口。

**约束**：
- 拖动期间用 `applyEffects({ live: true })`，跳过字体度量与布局重算。
- 只有 `change`（松手 / 失焦）才发完整通知。
- 浏览器存储只是缓存与迁移入口；跨端口重启以宿主文件为准。

### 2.2 确认基线：一个必须做对的算例

场景：用户把数值拖到 16 → 30 → 16，首批写入还在进行中。

| 步骤 | 用户意图 | 实际写入 | 正确基线 |
| --- | --- | --- | --- |
| t0 | 16 | 批次 1 发出（16） | — |
| t1 | 30 | 排队 | — |
| t2 | 16 | 排队 | — |
| t3 | — | 批次 1 成功（16） | **不能**把基线设成 16 就完事 |
| t4 | — | 批次 2 写入最新意图 16 | 基线 = 实际成功写入的那批 |

**规则**：
1. 基线只取**实际成功写入**的那一批，不取"最新意图"。
2. 数组 / 对象按值比较，基线持独立快照（不能持引用）。
3. 失败组不推进基线；后续变化或恢复可见时再写。
4. 读取宿主时若本页已有未写的新改动，避开旧读取回写（否则会把新值盖掉）。
5. 多编辑者：加版本号或 ETag，冲突时以较新版本为准并提示。

### 2.3 "已预览"与"已保存"是两个状态

UI 必须能分别表达：

```text
dirty      = 有改动未写
saving     = 有批次在飞
saved      = 基线已追上当前值
failed     = 有批次失败（指出是哪一批，留重试）
```

**反模式**：一个"保存中…"转圈在拖动时反复闪。预览不该触发 saving。

## 3. 预设：带边界的快照

### 3.1 两段结构

```json
{
  "schema": "app/profile-preset@1",
  "settings": { "scene": "moon", "material": "frost", "tint": 0.72, "mascot": true, "motion": true },
  "assets":   { "font": "songti", "portrait": null }
}
```

- `settings` 段：取**完整可预设键集**（缺键 = 用默认，不是"保持现状"）。
- `assets` 段：允许分项选择（字体 / 立绘 / 头像各自独立）。

### 3.2 缺席 ≠ 显式清除

| 写法 | 含义 |
| --- | --- |
| 字段不存在 | 保持本机现有资产 |
| `null` | 清掉自定义素材，回默认 |
| 字符串（如 `"factory"`） | 指向出厂形态 |

**硬约束**：把"缺席"当 `null` 处理，就是导入一个不含立绘的主题包会清空用户自己的立绘。

### 3.3 顺序

```text
读取 → 校验 → 准备 → 提交 → 保存 → 报告
```

- **读取**：解析 + schema 版本检查。
- **校验**：未知键拒绝或忽略（要明确策略），数值夹到值域内，资产标识必须已知。
- **准备**：把要用的资产先加载到位（字体走字体集通道；多文件资产要查发布事务边界）。
- **提交**：一次性切换有效配置。
- **保存**：写持久化，保留旧配置直到新配置可用。
- **报告**：告诉用户成功了哪些、失败了哪些。

**约束**：旧配置在新配置可用前继续生效。资产失败时客户端要有设置快照回退。

### 3.4 导入与应用分开

导入只是把包放进列表，用户另行点"应用"。这样"我导进来看看"不会立刻改变外观。

### 3.5 最小主题包

只允许**已知资产标识 + 有限参数**。禁止在包里放脚本、路径、URL 模板、任意 CSS。

## 4. 自动适配必须向手动让位

```text
自动主题默认：关
打开后：
  1. 先看作者配色（场景本身声明的色调）
  2. 取不到 → 用预览图
  3. 再取不到 → 用实际帧
  4. 图源矛盾 → 偏深色（不是偏浅）
用户在当前壁纸期间手动改主题 → 自动逻辑让位
换下一张壁纸 → 重新评估
```

**异步取样必须带代次**：前一张壁纸的取色结果，绝不能决定当前主题。

**可解释**：界面上要能说出"为什么是这个主题"（跟随壁纸 / 手选 / 回退到深色）。

**颜色各自过检查**：正文色、状态色、焦点色分别验对比度，不能只验正文。

## 5. 模块级持久化边界

| 场景 | 要求 |
| --- | --- |
| 单个外观子包停用 | 它的键保留但不再生效；重启后不复活 |
| 子包重新启用 | 读回原值；若 schema 迁移过，走迁移函数 |
| 预设删除 | 写墓碑（如 `app/glass-preset-tombstone@1`），防止同步恢复 |
| 跨服务写入 | 先查事务边界，再做两阶段提交 |

## 6. 本层验收点

- [ ] 三类数据分表，运行事实不落盘。
- [ ] 拖动 200ms 内合并，松手才发完整通知。
- [ ] 16 → 30 → 16 的连改后，基线等于**实际成功写入**的那批。
- [ ] 刷新后外观与已读记录都在；外观与业务数据分别保存、互不覆盖。
- [ ] 两个窗口同时改，不出现"后写的被旧值盖掉"。
- [ ] 预设："缺席"保持本机资产，`null` 清回默认，二者都有测试。
- [ ] 导入不自动应用；应用失败能回退到设置快照。
- [ ] 自动主题默认关；手改后让位；换图才重评估；取样带代次。
- [ ] 无效 JSON / 未知版本 / 越界数值都有明确提示，且当前外观不被破坏。
