# 10 · 场景底层与按就绪交接

> 只在做换场景、加动态背景、接第三方 Web 壁纸时读。其余时候别打开。

## 1. 四级档位

| 档位 | 形态 | 能力 | 失败后的下一档 |
| --- | --- | --- | --- |
| 实时 | WebGL / Canvas / WebGL 视频，可交互 | 最高 | 视频 |
| 视频 | MP4 / WebM 播放 | 中 | 海报（静态帧） |
| 海报 | 一张高分辨率静帧 | 低但确定 | 纯色 |
| 纯色 | 主题色 / 渐变 | 最低，永远可用 | 无（它是终点） |

**约束**：四级必须都实现。只做"实时 + 纯色"会让中间态变成黑屏。降级顺序不可跳档跳到"空白"。

## 2. asset 合同

每个场景资产对外只暴露四个字段：

```text
{
  assetId: string,        // 稳定标识，不含路径
  variant: 'live' | 'video' | 'image' | 'solid',
  poster: string | null,  // 可以是首帧、可以是作者提供的封面
  capabilities: { audio?: boolean, pointer?: boolean, loop?: boolean }
}
```

**画面与音轨分别列入合同**：有画面不等于有声音，有声音不等于允许自动播放。

## 3. 五类素材的归一化

| 类型 | 装载要点 | 可显示判据 |
| --- | --- | --- |
| 实时（WebGL / Canvas） | 先用垫底图占位，首帧绘制完成后置标记 | 实际绘出第一帧 |
| 第三方 Web（iframe + 桥接） | 沙箱容器，消息白名单 | 收到 ready 且容器尺寸非零 |
| 视频 | 海报优先、首帧次之，监听解码异常 | 有海报，或 `readyState` 足以出帧 |
| 图片 / 幻灯片 | 首张为底层，另层交叉淡化 | `complete && naturalWidth > 0` |
| 本地导入 | 先校验格式与尺寸，再进列表 | 同上，且不是 0 字节 |

**注意**：不要用 `decode()` 成功的 Promise 当唯一判据——它可能在图片被替换后才 resolve。以自然尺寸与当前代次双重确认。

## 4. 首帧交接（核心）

### 4.1 四步

```text
1. 准备   新层在屏幕外（或透明度 0 但已布局）开始加载
2. 确认   满足该档位的"可显示判据"
3. 交接   新层进入可见位置；此时旧层仍在
4. 释放   新层稳定显示后，旧层才 destroy（清监听、清定时器、释放纹理）
```

**反模式**：先 `opacity: 0` 淡出旧层 → 再开始加载新的。中间那段时间就是空屏。

### 4.2 代次规则

```text
let generation = 0;

function requestScene(asset) {
  const mine = ++generation;
  loadScene(asset).then((layer) => {
    if (mine !== generation) { layer.dispose(); return; }   // 过期结果直接丢弃
    if (!canDisplay(layer)) { fallback(asset, mine); return; }
    commit(layer);          // 只有这里改 displayed
  });
}
```

**验收脚本**：A 已显示 → 点 B（慢）→ 点 C（快）。
- 屏幕先保持 A。
- B 的回调到达时代次已过期，按作废处理，不得提交。
- C 有可交接画面后交接给 C。
- C 失败 → 先上 C 的海报 / 可识别底面，再提交降级档位与失败说明。

### 4.3 状态三分

| 状态 | 画面 | 文案 | 可做的动作 |
| --- | --- | --- | --- |
| 暂停 | 停在可识别的一帧 | 说明为什么停（隐藏页 / 省电 / 用户暂停） | 继续播放 |
| 加载 | 旧画面或海报 | 说明正在准备哪一级 | 取消 / 换一个 |
| 失败 | 海报或纯色底 | 指出失败来源（解码 / 网络 / 实时渲染） | 重试 / 降级 / 换场景 |

**约束**：这三种状态不允许共用一个转圈图标。

## 5. 播放三栏

| 意图 | 有效画面 | 反馈 |
| --- | --- | --- |
| 用户点了暂停 | 停在可识别帧 | 显示"已暂停"与恢复按钮 |
| 页面隐藏 / 全遮挡 | 暂停或限帧 | 恢复可见时重算并说明原因 |
| 用户输入但场景抢资源 | 降场景帧率 / 特效质量 | 操作保持即时，不排队 |
| 解码或实时渲染失败 | 换可用替代画面 | 显示失败来源与重试 |
| 系统减少动态 | 静态构图 | 功能按钮与结果完整 |

**实现要点**（【源码】证实存在，具体判据为【约束】）：
- `selection.playing` 是**意图**，不是事实。实际是否播放 = 意图 ∧ 可见 ∧ 未失焦 ∧ 未省电 ∧ 未被遮挡。
- 隐藏页暂停带 1200ms 持续期防抖（`HIDDEN_PAUSE_DEBOUNCE_MS`），避免切窗口瞬间闪停。
- 桌面适配器关闭"失焦即暂停"——桌面端切到别的应用是常态。
- 健康检测要读**暂停理由**：有意停住时，首帧超时与无帧诊断应冻结，否则会误报。传输类停滞先记会话内软失败并冷却重试，证据充分才进持久记忆，且要有显式清理。

## 6. 音频门

**约束**：同一时刻只允许一路音频响。

- 场景有音轨时，场景准备、系统音频、用户允许播放是三个不同状态。
- 自动播放被拒 → 显示可操作播放入口，不要静默失败。
- 场景接管音频前，先把别的音频源压低或停掉，交接完成后再恢复。
- 可分别停声音、停动画、关角色——三个开关不能合并成一个"关闭特效"。

## 7. 第三方 Web 壁纸

```html
<iframe sandbox="allow-scripts" src="..."></iframe>
```

- 刻意**不给** `allow-same-origin`，换取不透明源（opaque origin）。
- 不透明源的 `origin` 可能为字符串 `"null"`，所以只靠 origin 校验不够。
- 校验顺序：`event.source === 当前 iframe.contentWindow` → origin 白名单（含 `"null"` 的显式处理）→ 字段白名单。
- 更强做法：一次性握手换取私有 `MessagePort`，之后只在该端口上通信。
- 允许的消息类型只有：`ready` / `resize` / `pause` / `resume` / 限定坐标的指针事件。
- **媒体供给与宿主业务权限分开**：壁纸页面不得触达宿主的文件、设置、业务接口。

## 8. 预热与容器

- 预热的实时 iframe 接管外层容器时，**移动容器，不移动 iframe**——移动 iframe 会重新加载，白等一次。
- 普通网页项目可以先用两张图片实现同一套协议（准备 → 确认 → 交接 → 释放），把协议跑通再加实时层。

## 9. 本层验收点

- [ ] 四级档位都能通过开关强制进入。
- [ ] 连点三次场景，最终显示的是最后一次；中间态无空屏。
- [ ] B 的慢回调不会替换 C。
- [ ] 失败时先有可识别画面，再有错误说明与重试。
- [ ] 暂停 / 加载 / 失败三态在文案与画面上可区分。
- [ ] 页面隐藏 1200ms 内不闪停；恢复可见后正确重算。
- [ ] 同一时刻只有一路音频。
- [ ] 第三方 iframe 无 `allow-same-origin`，且伪造 origin 的消息被拒。
