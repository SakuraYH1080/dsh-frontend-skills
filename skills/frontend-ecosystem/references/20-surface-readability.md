# 20 · 表面承载与可读性

> 只在"这块面该不该透光""正文压在背景上读不清""玻璃叠起来发脏"时读。
> 材质配方本身交给 `frontend-liquid-glass`，这里只管承载方式与可读性下限。

## 1. 承载分区：五种面，五种待遇

| 面 | 职责 | 承载方式 | 强度取向 | 典型错误 |
| --- | --- | --- | --- | --- |
| 背景整体 | 大尺度色、光向、深度 | 场景本身，不叠玻璃 | — | 正文区背景细节太多 |
| 侧栏 / 工具条 | 浮在舞台前，可透环境色 | 局部玻璃 | 中等，可透 | 与正文同强度，导致层级不明 |
| 阅读正文 / 代码块 | 稳定阅读 | 正文画布或独立底板 | 对比密度优先 | 用玻璃承载长文本 |
| 弹窗 / 审批 | 区分任务与临时决定 | 模态 + 遮罩 + 实底 | 最实 | 弹窗比正文还透 |
| 单个主控件 | 光学辨识度 | 局部玻璃 | 较强 | 到处用，预算被稀释 |

**约束**：一个表面只能由一个提供者承载。两个元素都试图给同一块面加毛玻璃，结果是发灰、边缘重叠、性能翻倍。

### 1.1 选择顺序（照这个顺序问，问到"是"就停）

1. 这个面是否被声明为"保留原生"？→ 是：结束，不要玻璃。
2. 该面当前是否不可见（`display:none` / 零尺寸 / 被遮挡）？→ 是：不创建承载者。
3. 是否已经有宿主提供的模糊？→ 是：复用，不叠加。
4. 是否已被别的载体占用（画布、iframe、视频）？→ 是：改用独立底板。
5. 安全几何是否够（正文盒、圆角、内边距）？→ 否：改用实底。
6. 否则：正文画布 / 局部玻璃。

运行时给每块面打标（`data-surface="reading|chrome|modal|control"`），并在启动后清一遍重复的表面节点。

## 2. 三个参数必须分开

| 参数 | 管什么 | 调大之后 | 不该用它解决 |
| --- | --- | --- | --- |
| 雾化（blur） | 背后细节的模糊程度 | 背景更"化"，边缘更柔 | 文字看不清（越糊越像一层灰） |
| 染色（tint / alpha） | 面板自身的色与不透明度 | 面板更实、更遮背景 | 层级关系（那是 z 与阴影的事） |
| 阅读底色（floor） | 正文背后那块实底 | 文字对比上升 | 整体观感（它只为可读性存在） |

**判据**：用户报"读不清"，先查的是染色与阅读底色，最后才查雾化。

## 3. 覆盖度模型

设：
- `F` = 阅读底色（不透明度，0–1）
- `a` = 玻璃自身不透明度
- 覆盖度 `C = F + a × (1 - F)`

**透明度 → a 的映射【源码】**（`client.glass.js`）：

```js
const a = Math.max(0.10, 0.25 - (glassAlpha / 100) * 0.15);   // glassAlpha: 0–100
```

含义：界面透明度滑块越大（越透），a 越小，但**永不低于 0.10**——这是"再透也留一点底"的硬地板。

**暗主题衰减【源码】**：暗色下 a 再乘 0.4。因为深色背景本身吸光，同样的 alpha 观感更实。

**地板基数【源码】**：`READABILITY_FLOOR = 0.45`（浅）、`READABILITY_FLOOR_DARK = 0.59`（深）；再乘保真度 `f = glassFidelity / 100`。

**最坏情况【源码·注释】**：4.63:1。这是"深色 + 最不利叠合"下源码自己标注的余量，不是普适保证。

### 3.1 两个算例

**算例 A（源码参数，深色，保真度 100%）**
```text
glassAlpha = 100   → a = max(0.10, 0.25 - 0.15) = 0.10，暗色 ×0.4 → a = 0.04
F = READABILITY_FLOOR_DARK × f = 0.59 × 1.00 = 0.59
C = 0.59 + 0.04 × (1 - 0.59) = 0.59 + 0.0164 = 0.6064
```

**算例 B（同上，保真度 35%）**
```text
F = 0.59 × 0.35 = 0.2065
C = 0.2065 + 0.04 × (1 - 0.2065) = 0.2065 + 0.03174 = 0.23824
```

结论：保真度从 100% 降到 35%，覆盖度从 0.606 掉到 0.238——**降的不是"好看程度"，是可读性**。低保真度必须配更亮的文字色或更实的阅读底。

### 3.2 对比度算例【手册】

文字 `#f1f5ff`、深底 `#101a30`，白底叠合：

| 白底不透明度 | 对比度 |
| --- | --- |
| 0.60 | ≈ 4.20:1（手册原值 / 本机复算 4.43:1） |
| 0.68 | ≈ 5.50:1（手册原值 / 本机复算 5.78:1） |
| 临界 | ≈ 0.621（手册原值 / 本机复算约 0.605） |

**复算发现（重要）**：这组数字只有一条叠合链能复现——**亮底 + 深色遮罩 + 亮文字**（`#101a30` 以 alpha 叠在 `#f1f5ff` 上，文字仍取 `#f1f5ff`）。若按"白色半透明叠在深色底上"算，方向正相反：alpha 从 0.60 到 0.68，对比度从 2.32:1 **降到** 1.86:1。所以引用这组数值时必须同时写明叠合顺序，否则算出来的结论会完全相反。本机复算与手册的绝对差在 0.2–0.3，属取整与色值微差，量级可用、绝对值不可照抄。

**手册的工程结论**：实验工具面下限取 0.68；输入类面可降到 0.35（因为输入框内文字短、且通常有焦点边框辅助）。

**约束**：以上只是量级参考。任何项目都要用 `assets/contrast.mjs` 在**自己的两个颜色**上重算，不能照抄 0.68。

## 4. 三种背衬必须都测

| 背衬 | 用途 | 判据 |
| --- | --- | --- |
| 纯白 | 最坏"亮"情况 | 正文 ≥ 4.5:1 |
| 纯黑 | 最坏"暗"情况 | 正文 ≥ 4.5:1 |
| 黑白条纹 | 暴露边缘与细节 | 文字不被条纹切断阅读；边界可见 |

条纹背衬的用法：把背景换成 1px 交替条纹，**看的是"文字周围还有没有稳定的底"**。如果条纹直接穿过字间，说明阅读底色不足或压根没有。

再补三项：反色（深色文字 / 浅色文字各试一次）、长文本（连续 10 行以上）、选中态与焦点环。

## 5. backdrop root 陷阱

祖先元素上出现以下任一属性，会形成新的 backdrop root，导致 `backdrop-filter` 采样不到真正的背景：

- `opacity < 1`
- `filter`（任意值，包括 `blur(0)`）
- `transform` / `will-change: transform`
- `contain: paint`
- `mask` / `clip-path`

**排查顺序**：先查层叠上下文（z-index 与定位），再查 backdrop root。两者现象很像，但修法完全不同——层叠问题加 z-index 就够，backdrop root 必须把属性移到不相关的包装层上。

**降级**：软件渲染、无 WebGL、或检测到采样失败时，用"较实的半透明纯色 + 边框 + 内阴影"顶上，不要留一块透明玻璃。

## 6. 交付时的可读性记录

每个面记一行：

```text
surface=reading | provider=canvas | blur=16 | tint=0.42 | floor=0.68
backdrop=white → 5.5:1 | backdrop=black → 5.2:1 | stripes → stable
samplePoint=x:320,y:180 (正文第二行左侧)
```

没有 `samplePoint` 的对比度数字不可复核，视为未测。

## 7. 本层验收点

- [ ] 每个面只有一个承载者，启动后无重复表面节点。
- [ ] 雾化 / 染色 / 阅读底是三个独立参数。
- [ ] 正文在纯白、纯黑、条纹三种背衬下都 ≥ 4.5:1，且有取样点。
- [ ] 长文本、选中态、焦点环都检查过。
- [ ] 玻璃关闭后，正文对比不下降（原生表面同样达标）。
- [ ] 祖先无 opacity / filter / transform 造成采样失效；失效时有实底降级。
- [ ] 弹窗比正文更实，不是更透。
