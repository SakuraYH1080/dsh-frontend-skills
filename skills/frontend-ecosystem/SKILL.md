# 一个完整的前端生态（frontend-ecosystem）

这个 skill 只做一件事：**让背景、玻璃、角色、氛围和业务界面在同一个产品里各就各位，并且每一层都能单独关掉。**

它不教你怎么调一块玻璃的参数，也不教你怎么画角色或做粒子。它回答的是那个更容易被跳过的问题：这几层为什么要同时存在、谁在什么时候让位、用户发起下一个动作时旧的那层什么时候才允许消失。

判断标准只有一条：**把全部增强关掉，核心任务仍然完成；逐层打开，每一层都让任务更快或更清楚，而不是更慢或更花。**

## 一、什么时候用 / 不用

**用**

- 同一个界面里同时有动态壁纸（或视频、实时场景）、半透明表面、吉祥物 / 立绘、主题设置，且它们已经开始互相干扰。
- 换背景闪黑、闪白、旧场景回写覆盖新场景、快速连点之后显示的仍是前一个。
- 玻璃面板读不清、多个面板叠起来发脏、正文压在花哨背景上。
- 吉祥物挡住正文或按钮，拖一下就把侧栏开开关关，或者关掉角色后再也找不到设置入口。
- 设置刷新后丢、两个页面互相覆盖、预设导入后资产没了、用户改了又被"自动主题"改回去。
- 要在动手前先定一个可验收的多层结构与退出路径。

**不用**

- 只有一层在动：只是要玻璃 → `frontend-liquid-glass`；只是要粒子 → `frontend-particles`；只是要立绘与面板的空间关系 → `frontend-anime-fusion`。
- 问题是页面节奏、留白、字阶、文案味道 → `frontend-apple-minimal` / `frontend-taste-base`。
- 问题是视觉语言（切角、编号、状态三态、工业控制台） → `frontend-industrial-sci-fi`。
- 只是"再加点动效让它高级"：先回答它替用户完成了什么；答不出就不要加（见第二节原则 1）。

| 用户实际要的 | 交给谁 | 为什么不是这里 |
| --- | --- | --- |
| 玻璃的模糊 / 折射 / 边缘高光 / 降级参数 | `frontend-liquid-glass` | 本 skill 只决定哪一面该用哪种承载强度，不调材料配方 |
| 粒子 / 星空 / 鼠标跟随的生成、寿命、渲染路线 | `frontend-particles` | 本 skill 只决定氛围层何时启用、何时让位、何时停 |
| 立绘比例、视线方向、面板压不压脸、竖屏裁切 | `frontend-anime-fusion` | 本 skill 给安全区与角色位置，不给构图美学 |
| 一屏一节、节高、字阶、滚动叙事 | `frontend-apple-minimal`、`frontend-taste-base` | 本 skill 不改版式与阅读节奏 |
| 工业 / 科幻视觉语言与信息编码 | `frontend-industrial-sci-fi` | 本 skill 不生产视觉语言 |

组合只在用户明确要求时发生，且必须指定主导方：视觉语言归主导 skill，层与层之间的合同、时序与退出路径归本 skill。

## 二、核心原则与硬边界

### 原则 1：先有任务，再谈层

先写一句可验收的核心任务（"读完一篇笔记并把进度记住"、"选一个场景并启动游戏"、"在波形上定位并试听一段"）。五层里任何一层，如果不能指出它让这句任务更快、更准或更少出错，它就不该默认开启。

**硬边界**：全增强关闭时，核心任务必须完整可用。做不到，说明结构依赖了增强。

### 原则 2：一次只有一个有效画面，交接以"有内容"为准

用户的意图可以变得很快，屏幕不能。新画面**真的能显示**之前，旧画面继续留在原位；连续切换时只保留最新一次请求，旧请求的回调按代次作废。

**硬边界**：不允许用"先淡出再加载"制造空屏。空屏不是过渡，是失败。

### 原则 3：材质服从阅读，角色服从操作

玻璃的清晰度不是靠加模糊解决的；角色的存在感不是靠挡住按钮换来的。

**硬边界**：
- 正文与它所在表面的对比度 ≥ 4.5:1，且在**最亮**与**最暗**两种背衬下都成立。
- 脸、正文盒、主操作控件各有保护区；角色可装饰，不可遮挡。
- 关闭角色、角色加载失败、手势取消三种情况下，同一功能都有等价入口（指针、键盘、工具栏）。

### 原则 4：预览走连续通道，提交走单次通道

拖动时的跟手反馈和松手后的状态改变是两件事。前者可以每帧更新、不落盘；后者必须一次、可取消、可幂等。

**硬边界**：连续的指针移动**不得**触发开 / 关、保存、路由跳转这类一次性动作。

### 原则 5：三类数据各有寿命，保存是可验证状态

业务事实（消息、笔记、已读）、长期偏好（场景、玻璃数值、角色开关）、运行事实（首帧、可见性、provider、失败冷却）必须分开存放、分开失效。

**硬边界**："已经预览"与"已经保存"必须是两个可观察状态；保存失败要能指出失败的是哪一批、留下重试入口。

### 原则 6：增强必须可退出

每个增强模块在接入时就要写清六件事：输入、挂载、同步、让位、销毁、持久化。回答不了"我拥有什么、它今天还在不在、退出时怎样还原"，就不算接入完成。

### 一票退回

- 换场景时先清空再加载，出现黑屏 / 白屏 / 骨架屏空转。
- 连续点两次场景，第一次的回调把第二次的画面换掉。
- 玻璃上的正文靠"再加 20px 模糊"来救。
- 吉祥物是打开设置的唯一入口。
- 拖动角色时侧栏反复开合。
- 设置只写了内存，刷新回默认；或两个窗口互相覆盖。
- 预设导入把用户本机资产清空了，因为分不清"没有这个字段"和"明确要清空"。
- 用户手动调过主题，下一次异步取色又把它改回去。
- 减少动态打开后功能缺失，只剩一张静态图。
## 三、结构骨架：五层职责与三个可调族

### 3.1 五层职责（每层都要写"最低可用形态"）

| 层 | 职责 | 最低可用形态 | 退出时留下什么 |
| --- | --- | --- | --- |
| 场景 | 背景构图、光线方向、动势 | 一张静态图，或主题纯色 | 底色仍在，任务区不受影响 |
| 表面 | 透光、边缘、层级、文字承载 | 宿主原生表面，或实色底 | 层级仍可辨，正文对比度不降 |
| 角色 | 身份提示、陪伴、进入设置 | 普通头像按钮 + 文字 | 等价入口仍在（工具栏 / 菜单 / 快捷键） |
| 氛围 | 指针反馈、拖尾、深度 | 无持续动画 | 交互反馈仍由控件自身提供 |
| 业务界面 | 对话、搜索、阅读、输入、焦点 | 同一套语义控件与业务数据 | 完全不受其他层开关影响 |

详细判据与四格独立性（有 / 无壁纸 × 开 / 关玻璃）见 `references/00-constitution.md`。

### 3.2 三个可调族

不是"一堆设置项"，而是三组互相约束的决策：

1. **场景族**：档位（实时 / 视频 / 图片 / 纯色）、交接策略、播放意图、失败回退。
2. **表面族**：每面的承载方式（正文画布 / 局部玻璃 / 独立底板 / 原生）、雾化强度、染色强度、阅读底色、可读性下限。
3. **角色族**：位置（壁纸人物 / 吉祥物 / 会话头像 / 联动桌宠）、安全区、手势状态机、等价入口。

偏好与预设是它们的持久化外壳，见 `references/40-preference-config.md`。

## 五、执行流程

按顺序走。每一步都有可留下的产物，没有产物就不要进下一步。

### 步骤 1：写一句核心任务，切五层职责

- 写出一句可验收的核心任务 + 它的完成判据（"读完并把进度记住"而非"体验流畅"）。
- 用第三节的五层表逐层填：这一层替这句任务做什么、最低可用形态是什么、关掉之后任务还缺什么。
- 任何一层填不出"替任务做了什么"，删掉它。

产物：五层职责表 + 每层最低可用形态。

### 步骤 2：画两条路径，让它们在"有效配置"处相遇

- 素材路径：素材目录 → 库索引 → 选择与准备 → 实时 / 视频 / 静态 / 纯色。
- 偏好路径：用户偏好 → 校验与迁移 → 有效配置 → 场景 / 表面 / 角色 / 氛围。
- 在"有效配置"处收口：由宿主保存并回传可见反馈、失败原因与重试入口。

产物：一张双路径图，标出哪一端是权威源（宿主文件），哪一端只是缓存（浏览器存储）。

### 步骤 3：定场景档位与交接协议

- 声明四级档位与它们的降级顺序：实时 → 视频 → 海报 → 纯色。
- 写清"可显示"的判据：图片要 loaded 且 naturalWidth > 0；视频要海报或可显示首帧；实时层要有垫底图与首帧标记。
- 定代次规则：连续切换只提交最新请求，旧回调按代次作废；A→B→C 时 A 保留到 C 有可交接画面。
- 把暂停、加载、失败做成三个不同状态（文案、画面、可做的动作各不相同），并写音频门避免两路同响。

产物：档位表 + 交接时序图 + 三种状态的文案与动作。细节读 `references/10-stage-handoff.md`。

### 步骤 4：定表面承载与可读性下限

- 逐面选择承载方式：正文画布 / 局部玻璃 / 独立底板 / 原生。一个表面只由一个提供者承载。
- 把雾化（模糊）、染色（色调与强度）、阅读底色（正文背后的实底）分开设计，不要用一个滑块同时管三件事。
- 算一遍最坏情况的覆盖度与对比度：亮底、暗底、条纹三种背衬各测一次，正文 ≥ 4.5:1。
- 检查祖先是否形成 backdrop root（opacity / filter / transform），避免玻璃采样失效。

产物：面 → 承载方式 → 参数 → 对比度读数的表。公式与算例见 `references/20-surface-readability.md`。

### 步骤 5：定角色位置、安全区与手势

- 从四个位置里选（壁纸人物 / 吉祥物 / 会话头像 / 联动桌宠），并说明它承担哪一种身份提示。
- 每个场景画一张安全区图：脸与道具保护框、正文盒、点击热区、角色可搭的面板边线；宽屏与窄屏各一张。
- 把跟手预览与提交拆成两条通道：指针按下 → 越死区 → 连续预览 → 松手 → 单次提交 / 取消复位。
- 列等价入口：指针、键盘（Enter / Space）、隐藏角色后的工具栏入口，三者都能到达同一功能。
- 写 provider 探测与让位：条件不满足时降级，但已进入的手势只返回降级结果，不得改触发点击回退。

产物：安全区图 + 手势状态表 + 等价入口清单。见 `references/30-actor-safe-area.md`。

### 步骤 6：定三类数据与预设协议

- 把字段分到三张表：业务事实 / 长期偏好 / 运行状态。运行状态一律不落盘。
- 写写入次序：读取 → 校验 → 准备 → 提交 → 保存 → 报告；旧配置在新配置可用前继续生效。
- 区分"缺席"与"显式清除"：字段缺失 = 保持本机现有资产；null = 回默认；字符串 = 指向出厂形态。
- 预览与保存分状态；输入延迟合并写入；基线只取实际成功写入的那一批，按值比较并持独立快照。
- 自动适配（如"主题随壁纸"）默认关；用户手改后自动逻辑让位，换下一张才重新评估；异步取样带代次。

产物：三张字段表 + 预设 JSON schema + 写入时序图。见 `references/40-preference-config.md`。

### 步骤 7：跑验收，出交付卡

- 跑九行验收矩阵（明暗极端 / 构图 / 主题竞争 / 玻璃退出 / 角色退出 / 状态诚实 / 资源 / 偏好 / 输入）。
- 跑四步演练：遮罩降档看读数、慢成功连切看交接、拉绳看单次提交、暂停与减少动态看偏好往返。
- 出交付卡八行。

产物：验收记录（含测试环境与仍未验证范围）+ 交付卡。见 `references/50-acceptance.md`。

- [ ] 每个增强层写了启用 / 让位 / 退出 / 恢复四个条件，不是只写"可关闭"。
- [ ] 场景档位四级齐全（实时 / 视频 / 海报 / 纯色），降级顺序与"可显示"判据明确。
- [ ] 连续切换只提交最新请求；旧画面保留到新画面有可交接内容；无空屏过渡。
- [ ] 暂停 / 加载 / 失败三种状态在文案、画面与可行动作上可区分。
- [ ] 每个表面只有一个提供者；正文在最亮与最暗背衬下都 ≥ 4.5:1，且记录取样位置。
- [ ] 雾化、染色、阅读底色是三个独立参数，不是一个滑块。
- [ ] 有桌面与窄屏两张安全区图；脸与主控件无遮挡；无横向裁切。
- [ ] 跟手预览与松手提交走不同通道；拖动过程中不触发开 / 关。
- [ ] 指针、键盘、隐藏角色后三条路径都能完成同一功能。
- [ ] 业务事实 / 长期偏好 / 运行状态分表存放；运行状态不落盘。
- [ ] 预设走"读取 → 校验 → 准备 → 提交 → 保存 → 报告"；旧配置在新配置可用前继续生效。
- [ ] "缺席"与"显式清除"行为不同，且都有测试用例。
- [ ] "已预览"与"已保存"是两个可观察状态；保存失败指出批次并留重试入口。
- [ ] 减少动态、减少透明度、强制颜色下功能完整。
- [ ] 每个增强模块有六字段合同（输入 / 挂载 / 同步 / 让位 / 销毁 / 持久化）与三类往返验证（开-关-再开、A→B→A、缺依赖-恢复）。
- [ ] 交付卡八行已填；交付物区分【源码】/【手册】/【约束】三种证据。
