# 00 · 立场：角色是空间系统，不是贴图

## 1. 一句话立场

二次元界面里，角色不是「一张透明底 PNG 放在背景上」，而是**一个占据三维位置的实体**：它有地面、有受光方向、有前后关系、有被裁切的权利。界面元素则是插进这个空间里的**板子**。两者的关系必须先被决定，样式才有意义。

判据只有一条：**把角色图暂时换成灰色剪影，界面的层级关系还成立吗？** 成立 → 空间是设计出来的；不成立 → 只是贴图。

## 2. 三种关系模型

| | A 角色在界面之后 | B 角色穿透界面 | C 角色在界面之内 |
| --- | --- | --- | --- |
| 结构 | 角色 z=0，面板 z=20，面板不透明或留缝 | 同一张立绘切两片：后片 z=0、前片 z=24，面板 z=20 夹在中间 | 角色是 figure，与面板邻接不重叠 |
| 视觉证据 | 面板边缘切过角色身体 | 角色的手 / 发 / 衣摆压在面板**上方** | 角色有边框或卡片容器 |
| 适用 | 角色详情、个人站、设置页、信息密度高的页 | 游戏启动器、抽卡、活动主视觉、版本宣传 | 团队页、图鉴网格、文章头图、角色列表 |
| 代价 | 低：两个 z-index | 高：两套裁切 + 严格对齐 + 响应式双份 | 最低：普通流式布局 |
| 辨识度 | 低，最容易退化成贴图 | 最高，一眼记住 | 中，靠排版和留白取胜 |
| 失败症状 | 面板像贴上去的便签 | 缩放时手和身体脱开、出现 1–2px 白缝 | 角色变成缩小了的头像 |

**判定顺序（按顺序问，命中即停）**：

1. 角色需要被面板挡一次、又被自己挡回来一次吗？→ 要，选 **B**。
2. 面板需要展示 ≥ 3 行正文或 ≥ 4 个控件吗？→ 是，选 **A**（B 的可用面板面积少 30–40%）。
3. 角色是否只是多个条目之一（列表、网格、图鉴）？→ 是，选 **C**。
4. 三个都答不上来 → 信息结构还没定，先定结构，别选模型。

### 2.1 模型 B 的硬性前提

B 之所以贵，是因为「前片」必须与「后片」是**同一次缩放的同一条曲线**，否则窗口一变就脱开。做法只有一种：两片共用同一个容器坐标系，切开靠 clip-path。

```css
/* 两片共用同一个容器坐标系，切开靠 clip-path 而不是两套图 */
.af-char        { --af-cut: 46%; }               /* 切线上沿，占角色高 */
.af-char__back  { clip-path: inset(0 0 calc(100% - var(--af-cut)) 0); }
.af-char__front { clip-path: inset(var(--af-cut) 0 0 0); }
```

`--af-cut` 是唯一允许的数字。两片各自写 `top: 120px` 这类魔法数字，一定在某个宽度上崩。

**判据**：在 1280 / 1440 / 1920 三个宽度下，前片与后片接缝处的像素错位 < 1px。用截图叠加差值验，不靠肉眼。

## 3. 融合的三个物理证据

| 证据 | 合格标准 | 反例（真实常见） |
| --- | --- | --- |
| 互相遮挡 | 至少一处角色压面板或面板压角色的明确边界 | 角色永远在下、面板永远在上，两者从不相交 |
| 共享光源 | 角色高光方向 = 背景光源方向 = 面板描边亮边方向 | 角色自带左上顶光，背景是右下暖光 |
| 共享基线 | 角色裁切线 / 足部与面板底边落在同一水平线，误差 ≤ 4px | 角色悬空 40px，面板贴底 |

三条缺一，页面就只是「有立绘的网页」；缺两条，退回 A 模型重做比修补便宜。

## 4. 一票退回清单

出现任意一条，不接受「微调一下」，退回重做：

- 任一页面上，面板与头部禁区相交面积 > 0（禁区定义见 `10-composition.md` §7）。
- 角色占屏高 > 80%：面板没有地方放，只能压脸。
- 角色占屏高 < 45%：立绘细节丢失，退化为缩略图。
- 头顶留白 < 5%：`object-fit: cover` 在任何非设计宽度上都会切到发梢。
- 模型 B 的前后片在 1280 / 1440 / 1920 出现 ≥ 2px 错位。
- 正文压在角色花纹、服装纹理或脸上，且没有 scrim。
- 用 `mix-blend-mode: screen` 把角色「融进」背景，角色整体发灰、固有色丢失。
- 入场时角色与面板同帧出现（无延迟），观感退化为「页面加载完成」。
- 素材来源未记录，或文案声称拥有角色版权。

## 5. 什么时候退出本 skill

- 角色是**摄影人物**而非绘制角色：走普通 figure + 排版，本文件的一半构图规则不适用。
- 页面主角是**产品**，角色只是角落贴纸（< 20% 屏高）：不做空间系统，按装饰元素处理，且不得遮挡任何控件。
- 需要的是**角色之间**的关系（双人构图、对立站位）：本 skill 只处理「角色 ↔ 界面」，双人关系属于插画构图，交给画师或视觉稿。
