# 10 · 构图：竖构图里的角色坐标

## 1. 九个旋钮全表

数值唯一权威是 `assets/tokens.json`；本表与之不一致时，改本表。

| # | 变量 | 单位 | 范围 | 默认 | 作用 | 越界症状 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `--af-char-h` | % 视口高 | 45–80 | 62 | 角色显示高 | > 80 面板无处安放；< 45 细节丢失 |
| 2 | `--af-headroom` | % 角色高 | 5–16 | 10 | 头顶到容器顶的留白 | < 5 任何 cover 都切发梢；> 16 角色下沉 |
| 3 | `--af-anchor-x` | % 视口宽 | 25–75 | 61.8 | 角色垂直中心线位置 | 偏离 1/3 或 1/φ 时文字列与角色打架 |
| 4 | `--af-gaze` | 枚举 | left / right / front | right | 视线方向，决定文字落哪侧 | 文字落在视线朝向一侧，视线穿字而过 |
| 5 | `--af-scrim` | 0–1 | 0.40–0.88 | 0.72 | 文字承载层不透明度 | 由算例反解，手调必偏低 |
| 6 | `--af-panel-gap` | px | 16–40 | 24 | 面板与角色轮廓最小间距 | < 16 面板像黏在角色身上 |
| 7 | `--af-edge-glow` | % | 0–100 | 60 | 抠图边缘 1px 内发光强度 | 100 出现抠图白边；0 角色从背景里漏掉 |
| 8 | `--af-parallax` | 比值 | 0–1 | 0.45 | 角色滚动位移 / 背景滚动位移 | > 1 角色比背景跑得快，纵深反转 |
| 9 | `--af-breath` | px / s | 1–3 px / 3–6 s | 2px / 4s | 呼吸位移幅度与周期 | > 3px 像晕船；< 1px 看不见且白烧 GPU |

## 2. 初值 / 运行值 / 建议值

| 概念 | 含义 | 取值 |
| --- | --- | --- |
| 初值 | `tokens.json` 里写死的值 | 上表默认列 |
| 运行值 | 运行时被媒体查询或 JS 覆盖后的值 | 横屏 `char-h` × 0.68；360px 宽时 `headroom` +3 |
| 建议值 | 交付时应当落在的区间 | 桌面 62–74，移动 48–58，横屏 45–52 |

三者不一致是正常的；**把运行值当成初值写进 tokens.json 就是错的**——那样一改预设全部漂移。

## 3. 三分与黄金分割在竖构图里的换算

**为什么按竖构图算**：角色立绘天然是竖长方形（常见 2:3 到 9:16），视口也常是竖的（手机 9:19.5）。竖构图里人眼先看上三分之一，再看中部水平线，底部基本只放操作。

| 分割线 | 位置 | 用途 |
| --- | --- | --- |
| 上三分线 | 视口高 33.3% | 角色**眼睛**大致落在这里，不是头顶 |
| 黄金线（上） | 38.2% | 眼睛的备选位置；比三分线更松，适合 `stage` 预设 |
| 中枢线 | 50% | 面板上沿的极限位置，越过就压脸 |
| 下三分线 | 66.7% | 角色腰线 / 面板主体开始处 |
| 底线 | 100% | 角色裁切线，必须与 `char-h` + `headroom` 自洽 |

**自洽算式**（角色眼睛落 38.2% 时反解 `char-h`）：

```text
eyeY = (1 - char-h) * H + headroom * char-h * H + 0.42 * char-h * H
```

其中 `0.42` 是「眼睛在角色立绘内的相对高度」，随图不同，需实测。解得 `char-h ≈ 0.618` 时 eyeY ≈ 0.382H —— **这正是 62% 默认值的来源**，不是拍脑袋。

**反例**：把角色头顶对准上三分线。头顶是轮廓里最不重要的部分，眼睛会被压到 45% 以下，视线区被面板占满。

## 4. 视线方向决定文字侧

| `--af-gaze` | 文字应落在 | 原因 |
| --- | --- | --- |
| `right`（角色看右） | **左侧** | 人眼沿视线方向扫，视线穿过的区域应保持空，文字落在视线起点后侧 |
| `left` | **右侧** | 同上镜像 |
| `front`（正视） | 任意一侧，但只一侧 | 正视时左右等价，双侧放字会夹碎角色 |

**判据**：从眼睛出发沿视线方向拉一条射线，这条射线与任何文字块矩形不相交。

**反例**：角色看右，标题在右侧、正文在左下 —— 视线穿过标题，注意力在第一条标题处被推走，正文没人读。

## 5. 头顶留白 8–12% 与 5% 的硬下限

为什么不能是 0：`object-fit: cover` 在非设计宽度上会**居中裁切**，裁掉的量等于 `(容器高 - 图显示高) / 2`。留白 0 时，容器只要比设计稿高 4%，发梢就被切。

为什么上限 16%：留白超过 16%，角色整体下沉，眼睛落到 45% 以下，与 §3 的分割线冲突。

**数值推导**：设图高 H_img、容器高 H_box，`object-position: 50% 0%`（顶对齐）时无裁切。若用 `50% 50%`，安全留白 ≥ `(H_box / H_img - 1) / 2`。移动端 `H_box / H_img` 常见到 1.09，则留白 ≥ 4.5% → 取整 5% 为硬下限，10% 为默认。

## 6. 角色尺度 55–75%

| `char-h` | 剩余屏幕 | 可放内容 | 适用 |
| --- | --- | --- | --- |
| 45–52% | 48–55% | 3–4 行正文 + 1 组按钮 | 横屏、个人站、C 模型 |
| 55–65% | 35–45% | 标题 + 2 行副文 + 2 按钮 | 活动页、详情页 |
| 66–75% | 25–34% | 标题 + 1 行 + 1 主按钮 | 启动器、抽卡、A / B 模型 |
| > 80% | < 20% | 只能放一行字 | 不接受：面板必然压脸 |

**判据**：面板需要的垂直空间（正文行数 × 行高 + 控件高 + 上下内边距）必须 ≤ `100% - char-h - headroom × char-h`。算不下就降 `char-h`，不许压缩行高。

## 7. 禁区几何

```text
头部禁区（相对角色容器）：
  宽 = 62% × 角色显示宽，水平居中于 anchor-x
  高 = 26% × 角色显示高，上沿 = headroom × 角色显示高
```

`62%` 的来历：常见立绘的发型外扩在肩宽以内，头部（含发）约占身高 1/7.5；取 26% 高覆盖「头 + 发顶 + 少量肩线」，宽 62% 覆盖侧发。两个数在 3/4 侧身立绘上略保守，宁大不小。

**相交判定**：

```js
const head = { x: cx - w * 0.31, y: top + h * headroom, w: w * 0.62, h: h * 0.26 };
const hit = panels.filter(p => overlapArea(p, head) > 0);
if (hit.length) console.warn("禁区被占", hit);
```

情绪性遮挡例外：对话框、气泡允许覆盖禁区 ≤ 8% 面积，且**只能压下巴以下**（禁区下 1/3）。

## 8. CSS 变量全集

```css
:root {
  --af-char-h: 62;          /* % of viewport height, unitless for calc */
  --af-headroom: 10;        /* % of char height */
  --af-anchor-x: 61.8;      /* % of viewport width */
  --af-scrim: 0.72;
  --af-panel-gap: 24px;
  --af-edge-glow: 60;       /* 0-100 */
  --af-parallax: 0.45;
  --af-breath-amp: 2px;
  --af-breath-dur: 4s;
  --af-enter-char: 0ms;
  --af-enter-panel: 160ms;
  --af-ink: #10121A;
  --af-paper: #FFF7FA;
  --af-accent: #FF5C8A;
  --af-accent-2: #7BD7F5;
  --af-gold: #F5C86B;
}
.af-char {
  height: calc(var(--af-char-h) * 1vh);
  left: calc(var(--af-anchor-x) * 1% - var(--af-w) / 2);
}
```

`char-h` 写成无单位数是为了在 `calc()` 里直接相乘；带 `%` 会在 `height` 上按父元素解析，与 `vh` 语义打架。

## 9. 与面板、动效的耦合

- `char-h` 决定面板可用高度，面板高度反过来限制 `char-h` 下限（见 §6 判据）。
- `anchor-x` 决定面板列宽：文字块宽度 ≤ `min(52vw, 视线反侧可用宽 - panel-gap)`。
- `parallax` 越大，`headroom` 要越大：滚到顶部时角色下移 `parallax × scrollY`，留白不足就露底边。经验式 `headroom ≥ 8 + parallax × 6`。

## 10. 反例

- 手写 `height: 640px`：换屏就崩，且与 `headroom` 无关联。
- 用 `background-image` + `background-position` 放角色：无法裁边缘、无法分片，B 模型直接不可行。
- 角色水平居中 + 文字居中：竖构图里中线是唯一不能放字的位置，角色和文字互相踩。
- `char-h: 90%` 再加底部一行版权字：面板被挤到 10%，实际做法是把面板做成浮层压在胸口上 —— 这正是最常见的返工形态。
