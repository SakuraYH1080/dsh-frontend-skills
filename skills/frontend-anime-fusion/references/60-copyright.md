# 60 · 素材来源、授权与审美迁移

## 1. 三种来源，三种风险

同人、官方、委托不是「好不好看」的区别，是**你被允许做什么**的区别。

| 来源 | 典型情形 | 通常可做 | 通常不可做 | 必须记录 |
| --- | --- | --- | --- | --- |
| 官方素材 | 版权方发布的立绘、宣传图 | 仅限授权范围内的自家产品宣传；多数二次创作需遵守官方指南 | 商用、改图、二次分发原图 | 作品名、版权方、素材页 URL、授权条款 URL、获取日期 |
| 同人（他人作品） | pixiv / X 上画师的二次创作或原创角色 | 取得作者许可后的展示、编制 | 未授权的商用、裁切改色、去掉署名 | 作者名、作品页 URL、许可截图、授权范围（宣传 / 商用 / 可改） |
| 委托（自己买的） | 向画师约稿 | 按合同约定使用；合同未写明的用途一律视为未授权 | 转售、二次分发、默认「买断」 | 合同编号、约定用途、交付文件哈希、画师署名要求 |

**判据**：交付文档里能回答四个问题——谁的、从哪来、允许干什么、要署什么名。答不全就是未授权。

## 2. 授权记录模板

```yaml
# assets/CREDITS.yaml 或交付说明附录
characters:
  - id: char-a
    display_name: 角色 A
    source_type: commissioned        # official | fanart | commissioned | ai-generated | original
    author: 画师名（或机构名）
    work_url: ""                     # 原图页面；委托填合同编号
    license: ""                      # 例如 CC BY-NC 4.0、委托合同第 3 条
    allowed: [web-display]           # web-display | commercial | modify | redistribute
    attribution_text: "角色设计：画师名"
    acquired_at: 2026-01-01
    file_sha256: ""                  # 交付文件指纹，防止换图后记录失效
```

`allowed` 用固定枚举，不写自由文本：自由文本三个月后没人看得懂「可以用一下」。

## 3. AI 生成图的风险清单

AI 图的问题不是「来路不明」，而是**授权链条没有终点**。

| 风险 | 具体表现 | 处理 |
| --- | --- | --- |
| 训练数据来源不明 | 生成的画风可能实质复制某位在役画师 | 不做「指定某画师风格」的商用稿 |
| 角色相似 | 结果与既有 IP 角色高度相似 | 上线前做一次视觉比对，相似即弃用 |
| 平台条款变动 | 多数生成工具的商用授权随套餐变化 | 记录工具名 + 条款版本 + 生成日期 |
| 无署名人 | 无法履行署名义务 | 在 CREDITS 里写工具与提示词摘要，不假装有作者 |
| 细节崩坏 | 手部、文字经不起 4K 放大 | 只用于不超过 40% 屏高的装饰位，不用于主视觉 |

**判据**：主视觉（占屏高 ≥ 55% 的那张）必须是可追溯的人类作者作品或明确授权的官方素材。AI 图只能进辅助位。

## 4. 不得声称拥有角色版权

界面文案、页脚、meta 里都不允许出现「© 角色名」「本角色版权归本站所有」这类表述。能写的只有：

- `角色设计：<作者>`（署名，不是版权声明）
- `本页为同人展示，角色版权归原作者所有`
- `立绘使用已获授权，授权范围见 CREDITS`

确实拥有原创 IP 时写 `© <你的主体> — 角色与立绘均为原创`，并确保能出示创作过程文件。

## 5. 审美迁移：提炼规则，不抄分镜

从一部作品里能拿走的是**关系**，不是**画面**。三层提炼，每层问一个不同的问题：

| 层 | 问什么 | 产出（可迁移） | 不可迁移（抄） |
| --- | --- | --- | --- |
| 色彩关系 | 主色 / 辅色 / 强调色的比例与明度差？ | 「主色占 62%、辅色 26%、强调色 6%，强调色明度比主色高 22」 | 直接吸色得到同一组十六进制 |
| 线条语言 | 轮廓线的粗细、收笔、断点规律？ | 「外轮廓 2px、内结构 1px、转折处断笔」 | 描摹某个角色的发型线 |
| 质感 | 高光形状、阴影边缘软硬、颗粒？ | 「硬边高光 + 3 层软阴影 + 4% 噪点」 | 复制同一张图的笔触 |

**判据**：提炼结果必须是**能用在另一个角色身上**的参数。只对原角色成立的描述（「头发要有三缕挑染」）不是规则，是模仿。

## 6. 从作品到参数的换算

看到某作品「角色浮在界面之上、界面像板子」时，可迁移的是：

| 观察 | 迁移成 | 具体数值 |
| --- | --- | --- |
| 角色边缘有一圈冷光 | 抠图边缘补光 | `--af-edge-glow: 60`，发光色取背景主色提亮 18% |
| 面板永远比角色暗一档 | 面板与角色明度差 | `--af-paper` 与角色平均明度差 ≥ 14 |
| 角色与面板之间总有二十多像素空隙 | `--af-panel-gap` | 24px |
| 静止时画面也在动 | 呼吸 | ±2px / 4s |

不可迁移的是：那张具体的脸、那个具体的构图比例、那套具体的配色。

## 7. 致敬的界线

| 做法 | 判定 |
| --- | --- |
| 用同一套配色比例做另一个角色 | 可以，配色比例不受版权保护 |
| 复刻某个构图，只换角色 | 不可以，构图与角色组合构成实质性相似 |
| 用同样的切角几何做 UI | 可以，几何规则是通用设计语言 |
| 直接使用作品截图做背景 | 不可以，未授权复制 |
| 页面副标题写「致敬 XX」 | 可以，但不得暗示官方关联 |

## 8. 交付时的四行声明

写在页面 footer 或交付说明末尾，四行，缺一行退回：

```text
角色设计：<作者>            （或：本页角色为原创）
素材来源：<URL 或合同编号>
授权范围：<web-display / commercial / ...>
本页与 <作品名> 官方无关联。
```

## 9. 反例

- 从搜索引擎保存一张立绘当主视觉，来源栏写「网络」：等于没有来源。
- 委托合同写「可用于个人网站」，然后拿去做公司活动页：超范围使用。
- AI 图当主视觉，页脚写「© 本站」：既无作者又声称版权。
- 1:1 复刻某作品的构图，只把角色换成自己的原创角色：仍构成实质性相似。
- CREDITS 里 `allowed: ["随便用"]`：三个月后无法判断能做什么。
- 同人图去掉画师水印再上传：侵犯署名权。
