# 50 · 可读性与响应式裁切

## 1. scrim 是算出来的，不是调出来的

立绘的亮度由画师决定，改不了；文字对比度由你决定。所以每一个压在角色上的文字块，都必须坐在一层**有确定不透明度**的 scrim 上，而这个不透明度由最坏情况反解。

**最坏情况的定义**：角色在该文字区域内的**最亮 1% 像素**。不是平均值——平均值会把一块高光忽略掉，而那 1% 恰好是脸或白衣服。

## 2. 计算链（四步，可复算）

```text
1) sRGB → 线性：  c_lin = c/12.92            (c <= 0.04045)
                  c_lin = ((c+0.055)/1.055)^2.4  (c > 0.04045)
2) 相对亮度：     L = 0.2126*R + 0.7152*G + 0.0722*B   （均为线性值）
3) 黑色 scrim 合成：L_out = L_bg * (1 - α)          （α 为不透明度）
4) 对比度：       CR = (L_light + 0.05) / (L_dark + 0.05)
```

白字（L=1.0）压黑 scrim，要求 CR ≥ 4.5：

```text
(1.0 + 0.05) / (L_out + 0.05) >= 4.5
L_out <= 0.1833
α >= 1 - 0.1833 / L_bg
```

## 3. 算例：默认值 0.72 的来历

取一张常见浅底立绘的高光区，实测线性亮度 `L_bg = 0.62`（约等于 sRGB #CEC6C0）：

```text
α >= 1 - 0.1833 / 0.62 = 1 - 0.2956 = 0.7044
取 0.72（向上取整到 0.02 的倍数，留 1.6% 余量）
验算：L_out = 0.62 * 0.28 = 0.1736
      CR = 1.05 / (0.1736 + 0.05) = 4.69 >= 4.5  ✓
```

这就是 `--af-scrim: 0.72` 的来源。同一张图换成更深的高光区 `L_bg = 0.42`，则 α ≥ 0.564，用 0.58 即可——**预设里的 scrim 不同，是因为背景亮度不同，不是因为"想淡一点"**。

## 4. 反算表（白字 / 黑 scrim / 目标 4.5:1）

| L_bg（线性） | 约合 sRGB | 所需 α 下限 | 取整用 |
| --- | --- | --- | --- |
| 0.20 | #7C7C7C | 0.083 | 0.12 |
| 0.30 | #959595 | 0.389 | 0.42 |
| 0.42 | #ADADAD | 0.564 | 0.58 |
| 0.50 | #BCBCBC | 0.633 | 0.66 |
| 0.62 | #CEC6C0 | 0.704 | 0.72 |
| 0.75 | #DEDEDE | 0.756 | 0.78 |
| 0.85 | #E9E9E9 | 0.784 | 0.82 |

**注意上限**：α 超过 0.88 时角色基本被糊掉，此时应改用「文字块整体移出角色区」，而不是继续加黑。

## 5. 暗字方案（浅色 scrim）

当页面是浅色系（`--af-paper: #FFF7FA`），用深墨字（`--af-ink: #10121A`，L≈0.0055）压白色 scrim：

```text
白 scrim 合成：L_out = L_bg + (1 - L_bg) * α
要求 CR >= 4.5：(L_out + 0.05) / (0.0055 + 0.05) >= 4.5
              L_out >= 0.1998
              α >= (0.1998 - L_bg) / (1 - L_bg)
```

`L_bg = 0.62` 时 α ≥ 0 就够（背景本身就够亮）——所以浅色方案的关键不是 scrim 而是**别让角色高光区变成纯白**。反过来说，暗字方案在深色立绘上需要 α ≥ 0.79，几乎等于放白卡片，此时应改用白字方案。

**判据**：一个文字块只属于一种方案，不允许「半黑半白」的渐变 scrim 压正文。

## 6. 4.5:1 的验收方法（可外部复现）

1. 截图（1x 或 2x 均可，记录 DPR）。
2. 用取色器在文字所在区域内取 20 个点，记录最亮的那个像素值。
3. 该像素与文字色的对比度必须 ≥ 4.5:1（正文）/ ≥ 3:1（≥ 24px 或 ≥ 18.66px 粗体）。
4. 再对最暗的背景区验一次（暗字方案需要）。

**必须给两个数**：最亮处 CR 与最暗处 CR。只报一个数说明只测了顺眼的那一半。

## 7. 花纹区不能放正文

角色服装上的花纹、蕾丝、金属反光、发丝高光，会在文字后面形成**高频细节**。高频细节不降低对比度的数值，但显著降低可读性——眼睛在字与纹之间来回抢。

| 区域 | 允许放 | 原因 |
| --- | --- | --- |
| 纯色服装大块面 | 正文（需 scrim） | 细节频率低 |
| 花纹 / 蕾丝 / 刺绣 | 仅 1 行短标签，且 scrim α ≥ 0.82 | 高频干扰 |
| 发丝 | 不放 | 明暗交替最密 |
| 金属高光 | 不放 | 局部亮度尖峰，最坏 1% 就在这 |
| 面部 | 不放任何文字 | 禁区，见 10-composition.md 第 7 节 |

**判据**：把文字临时替换成同字号的灰块，如果灰块边缘与背景细节「咬」在一起看不清边界，就不能放正文。

## 8. 裁切安全区与 object-position

```text
安全区（相对图片）：水平 8%–92%，垂直 4%–96%  —— 超出此范围的像素随时可能被裁
关键区（不可裁）：头部 + 面部，落在图片垂直 4%–32% 区间
```

`object-position` 不是审美参数，是**保头参数**。四档取值与理由：

| 宽度 | 容器比例 | object-position | 理由 |
| --- | --- | --- | --- |
| 360 | 约 9:16 竖 | `50% 4%` | 容器比图更竖 → 上下都富余，顶对齐保住头顶 |
| 768 | 约 3:4 | `50% 0%` | 容器略窄于图 → 左右裁，垂直不裁 |
| 1280 | 约 16:10 | `50% 0%` | 容器远宽于图 → 裁左右 20–28%，头不动 |
| 1920 | 约 16:9 | `50% 0%` | 同上，左右裁更多，仍不动垂直 |

统一规则：**垂直永远 0%（顶对齐），水平 50%（居中）**。唯一例外是角色视线朝侧时，水平改 40% 或 60%，给视线方向留空间。

```css
.af-char__img { object-fit: contain; object-position: 50% 0%; }
@media (max-width: 480px) { .af-char__img { object-position: 50% 4%; } }
```

用 `contain` 而非 `cover`：`cover` 在有留白的画布上会放大再裁，等于双重裁切，头顶一定丢。`contain` 的代价是可能露底——用背景渐变补，不用放大图补。

## 9. 竖屏重排：角色上，内容下

`max-width: 640px` 时结构与数值同时改：

| 项 | 桌面 | 竖屏（≤ 640px） |
| --- | --- | --- |
| 布局 | 角色右 / 面板左（并置） | 角色上 / 面板下（堆叠） |
| `--af-char-h` | 62 | 52 |
| `--af-headroom` | 10 | 12 |
| `--af-anchor-x` | 61.8 | 50 |
| 面板宽度 | 38vw | 100% - 32px |
| 面板圆角 | 14px | 0（贴底），只保留上两角 20px |
| 呼吸幅度 | 2px | 1.5px |
| 视差 | 0.45 | 0（移动端关闭，省电） |

**为什么 char-h 要降到 52**：竖屏高度是最稀缺资源。62% 的角色 + 面板会把面板压到 30% 以下，正文放 3 行就挤。降到 52% 后角色仍占过半屏，辨识度不丢。

**为什么 anchor-x 居中**：竖屏里没有「另一侧」，居中让角色与面板共享同一条中轴，比偏向一侧更稳。

```css
@media (max-width: 640px) {
  .af-stage { --af-char-h: 52; --af-headroom: 12; --af-anchor-x: 50; --af-parallax: 0; }
  .af-char { top: 0; bottom: auto; height: 52vh; }
  .af-panel { position: relative; margin-top: calc(52vh - 24px); width: calc(100% - 32px); }
}
```

`margin-top: calc(52vh - 24px)` 制造 24px 的重叠：面板压住角色下摆 —— 这就是竖屏版的「一处交叉遮挡」。没有这 24px，角色和面板又变成上下两张图。

## 10. 横屏（landscape phone）

`max-height: 500px and orientation: landscape` 时，高度不够而宽度富余：

| 项 | 值 | 理由 |
| --- | --- | --- |
| `--af-char-h` | 46 | 屏高只有 360–430px，62% 会让角色只剩 250px |
| 面板位置 | 左侧 42vw，垂直居中 | 横向空间富余 |
| 面板内边距 | 16px | 高度紧张 |
| 正文行数 | ≤ 3 行 | 超过就滚动，滚动区不得覆盖角色 |
| 前景氛围 | 关闭 | 高度不足时前景会盖住面板 |

```css
@media (max-height: 500px) and (orientation: landscape) {
  .af-stage { --af-char-h: 46; --af-headroom: 6; }
  .af-l3 { display: none; }
}
```

横屏时 `headroom` 可以降到 6（低于常规 8 的下限）：因为高度紧张，宁可少留白也不能让角色小到认不出。这是唯一允许的例外，且必须在交付说明里写明。

## 11. 反例

- 用「这张图挺暗的」判断不用 scrim：最亮 1% 的像素永远比直觉亮。
- scrim 做成 `radial-gradient` 只盖中间：文字四角露出原图，最坏像素在角上。
- 正文压在发丝上，理由是对比度测出来 5.2:1：数值达标但高频干扰，仍然不可读。
- `object-fit: cover` + `object-position: 50% 50%`：上下各裁 50% 的溢出量，头顶先没。
- 移动端只改字号不重排：角色仍占 62% 高，面板被挤成 1 行半，用户必须滚动才能看到按钮。
- 横屏没做处理：角色被裁到只剩腰部，面板盖住整张脸。
