# 50 · 审：把判据变成可执行的检查

这份文件解决一个问题：**怎么证明这页做完了。**
不是"我觉得还行"，是逐条过、有数、能退回。

---

## 1. 三种检查状态

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| **PASS** | 实测通过，有数字或截图 | 记一行 |
| **FAIL** | 实测不通过 | 必须修 |
| **OPEN** | 无法自动判定，需要人看 | 记一行，写清"为什么判不了" |

不算状态的两类：

- **SETUP**：检查还没跑起来（缺依赖、缺截图）。补环境再跑，不算通过。
- **ERROR**：检查脚本自己崩了。修脚本，不能算通过。

**最多三轮。** 第一轮全量，第二轮只跑 FAIL，第三轮只跑上一轮 FAIL。三轮之后还有 FAIL，停下来改设计，不改检查。

---

## 2. 豁免机制

只有一种方式让 FAIL 变成可交付：**写进 waivers.json**。

```json
{
  "waivers": [
    {
      "id": "sections-illegal-band",
      "reason": "客户提供的产品图是 4:5 竖构图，两栏后右栏图高 760px 超出 708",
      "expires": "2026-12-31"
    }
  ]
}
```

规则：

- 最多 5 条
- 每条必须写清"为什么不能改"，不是"暂时不改"
- 必须有过期日
- 超过 5 条 = 设计整体不合格，不是个别问题

**绝对禁止**：为了让检查通过去改检查的逻辑。改了检查，之后所有页面都在骗自己。

## 3. 六组检查

### 3.1 结构组

| 检查 | 判据 | 怎么测 |
| --- | --- | --- |
| 节数 | 5–6 节（不含 footer） | 数 `main > section` |
| 每节一个 h2 | 一节里只有一个 `h2` 且是首元素 | `querySelectorAll` |
| 节高 | 所有节 `--h` ∈ {1, 2} | 读计算样式 |
| 内容窗口 | 每节内容高 ∈ [495, 708] 或 [1320, 1608] | 用 `getBoundingClientRect` 量第一个与最后一个子元素 |
| fill | 每节 ≥ 0.55 | 内容高 / 节高 |
| 卡片数 | `background` + `border-radius` 同时非默认的元素 ≤ 6 | 遍历，统计 |
| 分隔线 | 0 条 `border-top/bottom` 用作节分隔 | 人工看 |

### 3.2 动效组

| 检查 | 判据 |
| --- | --- |
| dealt moment 数量 | 恰好 1 |
| 入场层 | 只在 hero |
| 曲线控制点 | 全部 y ∈ [0,1] |
| 动的属性 | 只有 `transform` / `opacity`（+ 一个 `clip-path` 例外） |
| 滚动监听 | 0 处在 `scroll` 里同步读布局 |
| `will-change` | 0 处加在 body / 整页容器 |
| 降级 | `prefers-reduced-motion` 下所有 moment 有静态终态 |
| 总时长 | hero 入场 ≤ 1.6s |

### 3.3 文案组

| 检查 | 判据 |
| --- | --- |
| 第一代词表 | 0 命中 |
| 数字来源 | 每个数字都有来源或已删 |
| 数字条 | 若存在，四个数字之间有逻辑关系 |
| 句长分布 | 最长句 / 最短句 ≥ 3（说明有长短交替） |
| 过度纠偏 | 命中 ≤ 1 条 |
| 中文标点 | 0 个半角 ，。、；： |

### 3.4 排版组

| 检查 | 判据 |
| --- | --- |
| 正文行宽 | 28–40 字（`max-width` 在 28–40em） |
| 正文字号 | ≥ 16px |
| 正文行高 | ≥ 1.7 |
| 中文字距 | 0（标题可为负） |
| 斜体 | 中文部分 0 处 `font-style: italic` |
| 避头尾 | `line-break: strict` 已设 |
| 字体栈 | 含 Microsoft YaHei |
| 表格数字 | 数字列 `tabular-nums` |

### 3.5 响应组

| 断点 | 判据 |
| --- | --- |
| 1440×900 | 每节内容落在合格窗口 |
| 1280×800 | 同上（窗口改为 608px 内容区） |
| 768×1024 | ≤ 832 一屏 / 1130–1856 两屏 |
| 390×844 | 两栏已塌成一栏，`--gut` = 24 |
| 320 宽 | 无横向滚动 |

### 3.6 一致性组

| 检查 | 判据 |
| --- | --- |
| 颜色 | 只来自 tokens.json，无硬编码 hex |
| 间距 | 全部是 8 的倍数（或 tokens 里定义的） |
| 圆角 | 全页 ≤ 3 种值 |
| 阴影 | 全页 ≤ 2 种值 |
| 字重 | 只用 300/400/500/700 |
| 链接 | 所有 `href` 有效或明确 `#` |

## 4. 审的顺序（重要）

**先审结构，再审视觉，最后审动效。**

原因是结构问题会让后面全部白做。一页分成 9 节、每节都只填一半，这时候去调曲线和字距是浪费时间。

顺序：

1. 节数与节高（5 分钟）
2. 每节内容窗口与 fill（10 分钟）
3. 卡片化程度（2 分钟）
4. 文案（20 分钟，最慢）
5. 排版数字（5 分钟，可脚本化）
6. 断点（10 分钟，截图对比）
7. 动效（5 分钟）
8. 一致性（5 分钟）

---

## 5. 自动化能做什么，不能做什么

**能自动化的**：字号、行高、行宽、颜色是否来自 tokens、节数、`--h` 值、卡片计数、`border-top` 计数、`font-style: italic` 计数、`will-change` 位置、曲线控制点、字体栈内容、`line-break` 值、外链数、viewport meta。

**不能自动化的**：节的结构是否合理、文案是否具体、卡片化是否真的难看、动效是否有意义、fill 是否"看起来"够满、断点下图文是否被裁。

判据：**数字能测的交给脚本，判断交给眼睛。** 但眼睛也要按清单看，否则会漏。

---

## 6. 截图规范

每个断点截 3 张：首屏、中间节、结尾。

- 1440×900（桌面基准）
- 768×1024（平板）
- 390×844（手机）

命名：`shot-{宽}-{序}-{节id}.png`

截图必须**关掉动效**（`prefers-reduced-motion: reduce` 或用 DevTools 的 emulate），否则会截到中间态。

### 6.1 三种必须看出来的问题

1. **同一节在不同断点下"性格"变了** —— 桌面上是横向对照，手机上变成上下堆叠后失去对照关系。
2. **图片被裁掉了主体** —— 尤其是人像的眼睛、产品的关键细节。
3. **文字压在图上看不清** —— 没有 scrim 或 scrim 不够，对比度低于 4.5:1。

---

## 7. 退回之后怎么办

收到 FAIL 不要立刻改 CSS。先判断是哪一类：

| 类型 | 特征 | 处理 |
| --- | --- | --- |
| 局部 | 一个节的 fill 不足 | 补内容或合并节 |
| 系统性 | 五节里三节 fill 不足 | 内容总量不够，加一节或砍到 4 节 |
| 方向性 | 结构组 FAIL 两条以上 | 重做信息架构，不要修 |

判据：**同一组里 FAIL 超过两条，不要修，重做那一层。**

---

## 8. 交付前最后一遍

不看代码，只看截图。问五个问题：

1. 第一屏能不能在 3 秒内说清"这是什么"？
2. 往下滚的时候，有没有一次"咦"？（dealt moment）
3. 有没有哪一屏让你觉得"这屏没内容"？
4. 把公司名换掉，这页还成立吗？（成立 = 文案失败）
5. 这页和同行任意一家的首页，能不能一眼区分？

五问里有两个否，不要交付。
