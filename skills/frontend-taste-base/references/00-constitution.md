# 00 · 为什么是这套规则

这份文件回答一个问题：**这套判据是从哪来的，边界在哪，什么时候它不成立。**

不是设计哲学，是辩护状。三条主干（节高、动效、文案）每一条都会被问「凭什么」，这里是答案。

---

## 1. 为什么「一屏一节」不是审美偏好

### 1.1 它先是一个版权宜

营销页的读者只有一种行为模式：**快速判定「这跟我有没有关系」，没有就走。**
这个判定的单位不是像素，不是段落，是**屏**。手指一滑是一屏，滚轮一格大约三分之一屏。

所以页面的真实阅读单位是屏，不是 section。当一节占 1.3 屏，读者滑到第 1 屏末尾时看到下一节标题露了个头，又看不全，会产生一次「我是不是滑过头了」的犹豫。这个犹豫是节高造成的，不是内容造成的。

更精确地说：它破坏的是**滑动次数的可预测性**。读者滑一次期望看到一节，结果看到一节半。第一次是疑惑，第三次开始烦躁。

### 1.2 然后才是可测量的

参照系取 figma.com 与 x.ai，327 个站点在 1440×900 与 390×844 实测，得到三条：

| 观察 | 数值 |
| --- | --- |
| 公司站 hero 独占首屏 | 78% |
| 节高越接近一屏越容易独占 | 0.29 @ 低于 0.6 屏 → 0.80 @ 0.95–1.1 屏 |
| 节间隙越宽越容易独立成段 | 0.42 @ 低于 60px → 0.82 @ 220px 以上 |

前两条支撑「一屏一节」。第三条支撑「分离靠留白」：间隙宽度比任何装饰都更能决定读者是否把两段读成两段。

**诚实的部分**：这个样本里没有本地小店。所以 product / service / place 三档的节高要求，是从这六类生意推出来的自家标准，不是测量值。skill 里所有 place 的数字都该被这么理解。

### 1.3 为什么「708–1320 非法」是最狠的一条

一屏的可视内容区是 900 − 120（顶） − 72（底）= 708px。两屏是 708 + 900 − 300 = 1308，取整 1320。

那么 708 到 1320 之间是什么？是「比一屏多一点，又不到两屏」。

具体形状：读者滑完第一屏，看到第二节的标题和第一段，然后必须在第二节中间再滑一次。于是第二节被切成两半，前半在屏幕底部，后半在下一屏顶部。中间那一次滑动里，读者既不在第一节也不在第二节，处于「过渡态」。

一页里出现两个过渡态，页面就散了。这是大多数 AI 生成页面的死法：内容量恰好是「一屏半」，于是每一节都留一条尴尬的空带。

三种修法，按优先序：

1. **砍到 708**，把多的内容合并进上一节或删掉。
2. **拆成两节**，每节各补足到 495 以上。
3. 用两栏（`.g2`）把高度吃掉一半。

不许硬塞。硬塞的表现是节内留白忽大忽小，读者说不清哪里不对，只觉得「松」。

## 2. 为什么动效要三层封顶

### 2.1 动效的成本不在性能，在注意力

一个页面同时有三处以上在动，读者的眼睛没有落点。这和字号层级超过三层会退化成「大的/小的」二分是同一个机制：**人能同时追踪的变化源上限很低**。

所以动效不是「加得越多越高级」，是**预算**。一页的动效预算固定，花在哪由内容决定。

### 2.2 三层各管一件事

| 层 | 触发 | 作用 | 次数 |
| --- | --- | --- | --- |
| hero 入场 | 加载 | 告诉读者「页面准备好了」 | 每次加载一次 |
| dealt moment | 滚动或指针 | 这一页唯一值得停一下的地方 | 1（长页 2） |
| hover / press | 指针或触摸 | 确认「这个能点」 | 无限 |

这三层的共同点是：**每一层只回答一个问题**。入场回答「准备好了吗」，moment 回答「有什么值得看」，hover 回答「能不能点」。

反过来，「卡片随滚动淡入升起错开」不属于任何一层。它不回答任何问题，它只是让页面看起来在动。所以它被禁不是因为丑，是因为**没有目的**。

### 2.3 「无目的的动效一律砍掉」怎么执行

动手前写一行：

```text
这一页只动这三处：1) hero h1 逐行升起；2) 第三节的数字滚一次；3) 卡片 hover 抬 2px。
```

写不出来的动效，删。写得出来但说不清「它回答什么问题」的，也删。

### 2.4 为什么禁过冲

overshoot 曲线（`cubic-bezier(.34,1.56,.64,1)` 这类）在 2015 年前后是默认值，因为它让 UI「有弹性、有生命力」。现在它是时代标记，和拟物化图标一个性质。

更实际的理由：过冲会让元素短暂超出容器边界，在有 `overflow: hidden` 的卡片里表现为「边缘闪一下」。修复成本高于收益。

### 2.5 为什么只动 transform / opacity

动 `width` / `height` / `top` / `left` / `margin` / `padding` 会触发 layout，动 `background-color` / `box-shadow` 会触发 paint。在低端机和移动端，这两个都是掉帧的主因。

`transform` 与 `opacity` 走合成层，不碰 layout 与 paint。这是唯一在 60fps 预算内安全的做法。

例外：hover 时可以动颜色（`color` / `background-color` / `border-color`），因为 hover 是离散事件，一次 paint 可以接受。

## 3. 为什么文案是骨架的一部分

### 3.1 版式救不了空话

一个 708px 高、fill 0.6、留白精准的节，如果标题写「赋能未来」，读者仍然不知道这是什么。反过来，一句「每块玻璃只模糊一次」放在粗糙的版式里，读者仍然会读下去。

**信息密度决定读者是否留下，版式只决定留下的体验。** 所以文案不是「最后润色」，是第三根柱子。

### 3.2 为什么 AI 味要被系统性地处理

模型写文案有一个结构性偏差：**它会收敛到训练分布的中心**。中心是什么？是「温暖、具体、有节奏、有一句金句」的营销文案。这不是坏文案，这是**平均好文案**。

平均好文案的问题是：一百个页面读起来是同一个人写的。读者说不出哪里不对，只觉得「这网站好像在哪见过」。

所以判据不是「这句写得好不好」，是「这句是不是只有这个客户会这么写」。答不上来的句子，重写或删掉。

### 3.3 为什么要区分两代 tell

第一代（delve / seamless / unlock）是**词级别**的，好检测，也已经被大家躲开了。

第二代是**结构级别**的：统一腔调、编造具体、数字条、美德词、默认卡司、起源模板。这些之所以活下来，是因为它们**看起来像好文案的技法**。你没法靠 grep 抓，只能靠「这一页和上一页是不是同一个声音」来判断。

skill 里给的是 cap（配额）不是 ban（禁用），因为第二代 tell 单独出现时确实能写出好句子。问题在密度。

### 3.4 为什么保留 Not tells

只列黑名单的清单，执行下去一定变成僵化表演：不敢用 `is`，全改成 `serves as`；不敢写短句，全写成碎句鼓点；不敢有过渡词，句子硬接。

Not tells 这一列的价值是**给执行者松绑**：语法完美不是毛病，朴素的 `is/has` 不是毛病，客户自己写的文案一个字都不许动。有这一列，前面那些 ban 才敢执行。

## 4. 中文为什么不能等比缩放

四条英文规则照搬到中文会立刻坏：

| 英文规则 | 数值 | 中文为什么坏 | 中文取值 |
| --- | --- | --- | --- |
| 行宽 62 字符 | 62ch | 汉字宽度约等于 1.7–2 个字符宽，62ch 中文只有 31 字左右，但 62 个汉字是 105ch | 28–40 字 |
| 最小字号 13px | 13px | 汉字笔画密度高，13px 下「囊」「疆」这类字糊成一团 | 正文 16px 起 |
| 句子式大小写 | Sentence case | 中文没有大小写 | 用标点与分行代替 |
| 0.14em 字距 | 0.14em | 中文加字距会让字散架，且全角字本身已有侧边距 | 0 字距，靠行高与段距 |

详细换算与理由见 `40-type-cn.md`。

## 5. 这套判据什么时候不成立

诚实列出边界，比假装普适更有用。

1. **只适用于营销页**。后台系统、数据面板、App 内部界面没有「节」，节高规则不适用。硬套会把信息密度压死。
2. **C 变体（单屏页）只是简化版**。一屏页没有滚动，三层动效和 dealt moment 都用不上，只剩排版与文案。它不是本 skill 的主战场。
3. **place 档的数字是推出来的**。如 1.2 所述，样本里没有本地小店。这些数字可被现实推翻。
4. **文案判据依赖「客户有辨识度」**。如果客户本身就是「和所有人一样」，那「只有这个客户会这么写」这条判据会逼着你编造个性。这种情况下正确做法是写得更平，不是写得更花。
5. **不解决审美分歧**。这套规则能让页面「不漏」，不能让页面「惊艳」。惊艳来自具体的、不可复制的东西（一张好照片、一个真数据、一个别人没做过的交互），那不在任何 skill 的职责内。

## 6. 一句话总结

> 有品味不是一种感觉，是一组能被违反的约束。

能被违反，才有意义。说不清违反没违反的规则，等于没有规则。
