# 30 · 文案：页面骨架的第三根柱子

这份文件解决一个问题：**这页的文字，能不能让人相信。**
排版和版式骗不了人，文案会。AI 生成的页面最先暴露的地方，从来不是颜色，是句子。

---

## 1. 为什么文案算设计

一个页面的骨架有三根柱子：**节的结构**（每屏讲什么）、**视觉的层级**（眼睛先看哪）、**文案的具体度**（读下去信不信）。

前两根柱子，工具和模板能教。第三根不能，因为它要求写的人知道"这家店几点关门"、"这个插件为什么比别的快 200ms"。模型在不知道的时候，会自动生成一类句子来填空 —— 这类句子有一个共同特征：**换任何一家公司都成立。**

判据一句话：**把主语换成同行任意一家，句子还成立吗？成立的那句就是空话。**

---

## 2. 第一代词表（ban）

这些词在页面上出现一次就算失误。它们没有信息量，只是语气。

| 类别 | 词 |
| --- | --- |
| 万能形容 | 强大、极致、领先、专业、贴心、高效、智能、全新、一站式、全方位、无缝、沉浸式 |
| 空承诺 | 让 X 更简单、重新定义 X、为 X 而生、X 的未来、开启 X 新篇章 |
| 假规模 | 海量、千万级、众多、各类、多种、丰富的 |
| 假精确 | 高达、低至、仅需、仅用、只需、多达 |
| 装饰性副词 | 精心、用心、匠心、专注、致力于、深耕 |
| 假技术感 | 赋能、闭环、抓手、生态、矩阵、链路、中台、底层逻辑 |
| 语气填充 | 我们知道、我们相信、值得一提的是、不得不说、事实上 |

**例外**：行业术语（如"中台"在面向技术采购时）在**有具体所指**时可以留，但同一页不超过一次，且必须紧跟一句解释它指什么。

## 3. 第二代：结构 tell

第一代词表能被机械替换，所以第二代的毛病在结构里。这六种是模型最稳定的产出习惯：

### 3.1 统一腔调（uniform cadence）

每一段的长度、句长、节奏都一样。读起来像同一个人用同一个语速念完。

修法：**让长短句交替。** 一个 8 字的短句后面跟一个 40 字的长句，再跟一个 5 字。真实写作的人不会匀速。

### 3.2 编造具体（invented specificity）

"我们已经服务了 3,000 家企业"、"平均节省 47% 的时间" —— 数字看起来具体，但没有来源。

判据：**这个数字能不能被一个陌生人验证？** 不能的话，要么给来源（"2025 年 3 月，我们对 214 家客户做了回访"），要么删掉。

### 3.3 数字条（number bar）

一排四个数字：`99.9% / 10万+ / 24/7 / 5★`。看着像仪表盘，实际上是装饰。

真数字条只在一种情况下成立：**四个数字互相之间有逻辑关系**（如"1 个 bin / 3 种尺寸 / 12 种颜色 / 48 小时发货"）。

### 3.4 美德词堆叠（virtue stacking）

"专业、可靠、高效、创新" —— 形容词并列。真实的人在描述自己的时候会用一件具体的事，不会用四个形容词。

### 3.5 默认卡司（default cast）

提到人的时候，永远是"产品经理小李"、"资深设计师王工"。没有名字、没有具体做过什么。

修法：给真名（若已获授权），或给一件他做过的事。"我们的主编以前在县城市集卖了六年菜" 比 "资深内容专家" 有力一百倍。

### 3.6 起源模板（origin template）

"2021 年的一个深夜，创始人望着窗外的霓虹果，突然意识到……" —— 创业故事的标准模板。

修法：写一个**具体到不能被编造**的细节。时间、地点、一个动作、一句原话。编不出来的细节就是没发生过。

## 4. 过度纠偏表

反向的毛病同样常见。下面十二条是"为了不像 AI 而写成另一种模板"：

| 过度纠偏 | 为什么也是模板 |
| --- | --- |
| 全篇短句，每句一行 | 变成了海报，读者读不到论证 |
| 通篇口语，"咱"、"这事儿" | 亲密感是表演，尤其在 B 端页面 |
| 故意留一个错别字显真实 | 读者只会认为不专业 |
| 大量破折号断句 —— 像这样 | 这是 2024 年后最明显的 AI 痕迹之一 |
| 每段都以问句开头 | 修辞疲劳，三句之后读者开始跳过 |
| 全小写英文，无标点 | 只在极少数品牌语境成立 |
| 用脏话表达真诚 | 转移注意力，不增加信息 |
| 每节都以一个数字开头 | 结构 tell 换了个位置 |
| 把"我们"改成"我" | 人称不解决具体度问题 |
| 通篇没有一个形容词 | 该描述的地方变得干瘪 |
| 大量使用 emoji 当分隔符 | 移动端读起来像营销短信 |
| 故意写得粗糙（"我们不完美"） | 谦虚也是一种修辞，同样可以批量生产 |

判据：**纠偏的目标是"更具体"，不是"更不像 AI"。** 如果你删掉一个词只是因为它"像 AI"，但没换来更多信息，那只是换了一种腔调。

---

## 5. Not tells：必须保留的痕迹

有些"不完美"恰恰是真实性的证据，不能修掉：

- **句子的长度不齐**（人写作的自然结果）
- **一个具体的、无法被编造的数字**（"周三下午三点，第二炉面包出炉"）
- **一处自我限制**（"我们只做本地，不发货"）—— 限制比承诺可信
- **一句不完美的翻译或术语**（说明真的在做这行）
- **一个真实的名字 + 一件小事**
- **一处承认不知道**（"这个我们还没测过"）
- **重复**（人在强调重要的事时会重复，模板不会）

## 6. 中文的四条特有规则

英文的 copy 规则直接搬到中文上会坏。四条：

### 6.1 中文没有"标题大小写"

英文 Title Case 在中文里的对应物不存在。不要给中文标题加字距假装正式（见 40-type-cn.md），也不要为了"设计感"在词组间加空格。

### 6.2 全角标点，且必须避头尾

中文用全角 ，。、；：？！（）《》""''。行首禁止出现 ，。、；：？！）」』】》 等收尾标点；行尾禁止出现 （「『【《 等开头标点。

### 6.3 中英混排要加 1/4 em 间隙

"用 Figma 做设计" 里 Figma 两侧要有约 1/4 em 的空隙（CSS 里用 `text-spacing-trim` 或手动 `margin` 不好控制，实践中用 `font-feature` 或直接接受浏览器默认）。

不要用半角空格硬顶，那会在断行时脱落。

### 6.4 中文的"说人话"标准与英文不同

英文里 "We build tools for teams" 是正常的。中文里"我们为团队打造工具"就偏书面。中文的口语标准更低——同样一句话，中文要多用动词、少用"打造/赋能/助力"这类动词化名词。

对照表：

| 坏 | 好 |
| --- | --- |
| 助力企业数字化转型 | 帮工厂把订单录进系统 |
| 打造极致用户体验 | 点三次就能下单 |
| 提供全方位解决方案 | 修水管、换龙头、通下水道 |
| 深耕行业十余年 | 从 2014 年开始做，做的是同一个东西 |

## 7. 五类页面的文案要求

| 档 | 必须有的 | 禁止的 |
| --- | --- | --- |
| software | 一个具体动作 + 一个真实界面截图说明 + 一条带来源的数字 | 功能形容词、竞品对比表（除非有实测数据） |
| gaming | 类型 + 平台 + 发售日 + 一句世界观 | "史诗级"、"震撼"、"沉浸" |
| tech | 三个可核对的参数 + 一个使用场景 | 参数堆砌超过 8 项（其余放二级页） |
| product | 材质/尺寸/产地 + 一个使用细节 | "匠心"、"精选" |
| service | 谁 + 在哪 + 做什么 + 怎么联系 | 团队人数、成立年份当卖点 |
| place | 地址 + 营业时间 + 怎么来 + 2–4 项提供物 | 任何形容词式的氛围描写 |

### 7.1 place 档的特别要求

place（咖啡馆、客栈、餐厅）的文案是六档里最容易写坏的，因为写的人会忍不住抒情。

规则：**先给四条事实（地址、时间、怎么来、提供什么），再允许一句抒情。** 顺序不能反。

一句抒情的位置在 closing 节，且不超过 25 字。

---

## 8. 自检流程

写完文案，按顺序做四遍：

1. **换主语测试**：每句的主语换成同行任意一家，还成立吗？成立 → 删或改具体。
2. **来源测试**：每个数字，能不能指出来源？不能 → 删。
3. **朗读测试**：出声读一遍。卡住的地方就是句子有问题的地方。
4. **删三分之一测试**：随机删掉三分之一的句子，页面信息量减少了吗？没减少 → 那些句子本来就是空的。

第四遍最狠，也最有效。
