# 40 · 中文排版：把英文的字阶整套换掉

这份文件解决一个问题：**中文页面的字号、行宽、行高、字重该怎么定。**
直接把英文的设计稿翻译过来会全盘崩。不是审美问题，是标定单位不同。

---

## 1. 为什么英文的排版参数搬到中文上就坏

英文的排版单位是**字符**（ch），一个 em 方块里塞一个字符，字符之间有天然空隙。中文的排版单位是**字**，每个字占满一个 em 方块，没有字间空隙。

这个差别导致四个后果：

| 参数 | 英文 | 直接套到中文会怎样 |
| --- | --- | --- |
| 行宽 | 62ch 最佳 | 62 个汉字 = 105ch，一行太长，眼睛回头找不到起点 |
| 正文字号 | 13–16px 可接受 | 13px 的中文笔画糊成一团 |
| 行高 | 1.5–1.8 | 中文需要更大，因为字是满格方块，行间无天然空隙 |
| 字重 | 300 可以是正文 | 中文 300 在多数屏幕上发虚，正文必须 400 |

---

## 2. 行宽：28–40 字

**正文行宽 = 28–40 个汉字。**

推导：中文的最佳阅读行宽约等于人眼的"一次跳跃能带回的信息量"。西文排版的经验值是 45–75 字符，取中位 62。中文每个字的信息密度约是英文单词的 1.7 倍（一个汉字 ≈ 1.7 个英文单词的语义），所以 62 ÷ 1.7 ≈ 36 字。

实测区间收在 28–40：

- < 28 字：一行断得太快，读者不断回行，节奏碎
- 28–40 字：舒适区
- 40–50 字：可读，但需要更大的行高补偿
- > 50 字：眼睛回头会跳行

### 2.1 怎么落地

不要给 `max-width: 62ch`。用一个按字号算的宽度：

```css
.prose {
  font-size: 17px;
  line-height: 1.8;
  max-width: 34em;   /* 34 个汉字，落在 28–40 中段 */
}
```

`em` 在这里等于字号，所以 `34em` = 34 个字宽。用 `em` 而不是 `ch`，因为 `ch` 在中文里指向 "0" 的宽度，不准。

英文段落仍然用 `62ch`。混排页面要分成两个类。

### 2.2 大标题不受 28–40 限制

h1/h2 可以一行只放 6–12 字，那是节奏，不是行宽。

判据：**标题断行要断在语义边界**，不能靠容器宽度硬折。手动 `<br>` 是可接受的，前提是它在三个断点下都成立。

---

## 3. 字号：正文最小 16px

| 角色 | 英文常用 | 中文必须 | 说明 |
| --- | --- | --- | --- |
| 正文 | 15–17px | **17px**（最小 16） | 17 是中文的甜点值 |
| 次要正文 | 14px | 15–16px | 不再往下降 |
| 标签 / 元信息 | 11–12px | 13–14px | 11px 中文不可读 |
| 按钮文字 | 14–16px | 15–16px | 与正文同级 |
| h1 | 48–72px | 44–72px | 可同值 |
| h2 | 32–40px | 32–40px | 可同值 |

判据一句话：**中文字号下限比英文高 2px。**

### 3.1 模块化字阶

两套，选一套，不要混：

**1.25 倍（温和）**：14 / 17 / 21 / 26 / 33 / 41 / 52 / 65
**1.333 倍（对比强）**：13 / 17 / 23 / 31 / 41 / 55 / 73

1.25 适合信息密集的产品页，1.333 适合少量大字的海报式页面。

一个页面只用 4–5 级。超过 5 级，读者判断不出层级。

### 3.2 流体字号

用 `clamp()` 做跨设备缩放，但**中文的缩放幅度要小**。英文可以从 32 缩到 72，中文从 32 缩到 56 就够 —— 中文的字在视觉上更"重"，放大后压迫感更强。

```css
h1 { font-size: clamp(32px, 5vw, 56px); }
h2 { font-size: clamp(24px, 3vw, 36px); }
```

## 4. 行高：1.7–1.9

| 内容 | 行高 |
| --- | --- |
| 正文（17px） | 1.8 |
| 次要正文（15px） | 1.75 |
| 大标题（44px+） | 1.15–1.25 |
| 中标题（32px） | 1.3 |
| 标签行 | 1.5 |
| 表格单元格 | 1.5 |

### 4.1 为什么中文行高要更大

英文字母有升部（b, d, h）和降部（g, p, y），行与行之间天然有空隙感。汉字是满格方块，占满整个 em 方块，行与行之间没有任何自然空隙。

用 1.5 的行高排中文，行会贴在一起。1.8 是刚好让两行之间有呼吸但又不散的值。

### 4.2 行高与字号的关系

小字需要更大的行高比例。13px 的中文用 1.8，17px 用 1.8，24px 用 1.6，32px 用 1.3。

一个实用的近似公式：`line-height = 1.8 - (font-size - 17) / 100`，字号每大 10px，行高比例降 0.1。这只在 17–42px 区间有效。

## 5. 标点：全角 + 避头尾

### 5.1 必须用全角

，。、；：？！（）《》「」『』【】—— ……

半角逗号在中文里会让行读起来"断得不彻底"。

例外：括号里是纯英文或数字时用半角，如 `Google (2024)`。

### 5.2 避头尾（kinsoku）

行首禁止：`，。、；：？！）」』】》·…`
行尾禁止：`（「『【《`

CSS 落地：

```css
.prose {
  line-break: strict;
  word-break: normal;
  overflow-wrap: break-word;
}
```

`line-break: strict` 会让浏览器按中文标点规则断行，是这几年唯一真正可用的原生方案。不要用脚本手动插 `<wbr>`。

### 5.3 中英混排的 1/4 em 间隙

"用 React 写的界面" —— React 两侧要有约 1/4 em 的间隙。

CSS：`text-spacing-trim: space-first` 与 `text-autospace: normal`（Chrome 119+ 支持 `text-autospace`）。在不支持的浏览器上，浏览器默认的 `word-break` 行为已经足够接近，不要手动敲半角空格 —— 半角空格在两端对齐时会被拉宽，行尾还可能挂一个孤零零的空格。

判据：**看得见的间隙来自字体度量，不来自空格字符。**

## 6. 字体栈

```css
--font-sans: "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei",
             "Source Han Sans SC", "Noto Sans CJK SC", system-ui, sans-serif;
--font-serif: "Songti SC", "Source Han Serif SC", "Noto Serif CJK SC",
              "SimSun", Georgia, serif;
--font-mono: "JetBrains Mono", "SF Mono", Menlo, Consolas,
             "Sarasa Mono SC", monospace;
```

顺序不可换：PingFang SC 是 macOS/iOS 的默认中文，Hiragino 是旧版 macOS 回退，Microsoft YaHei 是 Windows，思源黑体是 Linux。

### 6.1 不要用 webfont 加载中文黑体

一套完整中文字体 5–10MB，按 unicode-range 切片也要 30+ 个请求。首屏会明显延迟。

唯一可接受的做法：**只对标题用 webfont，且只包含出现的字**（子集化）。正文一律用系统字体。

### 6.2 无真斜体

中文没有斜体字形。`font-style: italic` 在中文里是浏览器合成倾斜，看起来像被斜着拉过的方块，很丑。

替代：用字重、颜色、或左侧竖线表示强调。需要斜体时只对英文部分用。

### 6.3 字重只用四档

**300 / 400 / 500 / 700。**

- 中文的 300 在多数屏幕（非 Retina）上笔画粘连，禁止用于正文
- 600 与 700 在系统字体里常常映射到同一字形，不要同时用
- 900 是合成的，边缘毛糙

---

## 7. 字距：只在特定位置加

| 位置 | 字距 |
| --- | --- |
| 大标题（≥ 40px） | -0.01em 到 -0.02em（收紧） |
| 正文 | 0 |
| 标签 / 全大写英文 | 0.14em（放开） |
| 中文小标题 | 0 |

### 7.1 不要给中文标题加字距

英文全大写加 0.14em 字距是排版传统（大写字母本身间距不均，需要补偿）。中文的方块字间距天然均匀，加字距只会让标题散架。

如果你见过"中文标题加字距看起来很高级"，那是全大写英文标题留下的误用习惯。

---

## 8. 数字与表格

- 表格数字必须 `font-variant-numeric: tabular-nums`，否则列对不齐
- 正文里的数字用比例数字（默认），不要全局开 tabular
- 单位与数字之间加 1/4 em：`12 kg`、`30 %`（或按中文习惯写成 `12 公斤`）
- 中文数字与阿拉伯数字不混用：一页里 "三个" 和 "3 个" 只能选一种

---

## 9. 常见崩坏案例

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 中文页面显得"字很大很挤" | 用了英文的 62ch 宽度 | 改 34em |
| 手机上一行放 18 字读起来累 | 字号 14px 且行高 1.5 | 17px / 1.8 |
| 标题看起来"散" | 加了 0.14em 字距 | 去掉，或改成收紧 |
| 段落末尾频繁出现单字一行 | 没有 `text-spacing-trim` 或宽度卡死在临界 | 宽度多给 1–2em 余量 |
| 中英混排像两块拼贴 | 没有 `text-autospace` | 加 CSS，或接受浏览器默认 |
| 引用块看起来像斜体乱码 | 中文用了 italic | 改字重 + 左竖线 |
