# 通用品味基线（frontend-taste-base）

这一层只决定三件事：**一页分几节、每节多高；什么东西可以动、动多少；这些字读起来是谁写的。**

它不决定材质（玻璃、粒子、HUD、立绘都不归它管），不决定配色体系，不决定插画与摄影风格。它给的是骨架与语感。骨架错了，往下叠任何皮肤都是在给一面斜墙贴砖。

判断标准只有一条：**把这一节删掉，读者会损失信息吗？** 不会就删。

## 一、什么时候用 / 不用

**用**

| 用户会说的话 | 实际要解决的问题 |
| --- | --- |
| 「页面每节长短不匀，滚起来一顿一顿」 | 节高没有落进合法区间，见 `references/10-sections.md` |
| 「一屏塞满了 / 一屏空一半」 | fill 值没有量过，或内容落在 708–1320 这个非法带 |
| 「页面很花但说不清在卖什么」 | 主张层缺失，或文案全是形容词 |
| 「文案读着像 AI 写的」 | 命中第二代 tell，见 `references/30-copy.md` |
| 「动效太多 / 太吵 / 卡」 | 动效没有预算，超过三层 |
| 「不知道从哪开始排」 | 缺分档与节清单，见第五节执行流程 |
| 「中文排版怎么看怎么别扭」 | 行宽、字号下限、标点，见 `references/40-type-cn.md` |

**不用**

- 要玻璃材质、折射、模糊参数 → `frontend-liquid-glass`。
- 要粒子、星场、流场 → `frontend-particles`。
- 要二次元立绘与角色空间关系 → `frontend-anime-fusion`。
- 要 HUD、切角、仪表盘密度 → `frontend-industrial-sci-fi`。
- 要极简信息层级与字阶的完整体系 → `frontend-apple-minimal`（它是本 skill 的下游，本 skill 只给节与节奏，不给字号阶梯）。
- 后台系统、数据面板、App 内部界面：没有「节」，本 skill 的节高规则不适用。
- 单页海报、单个组件、一个弹窗：没有滚动，用不上。

**组合规则**：用户明确要求组合时，必须指定一个主导语言。本 skill 永远只做「骨架与语感」这一层，任何风格化 skill 都可以套在本 skill 之上，但不能反过来改节高与节数。让玻璃或粒子去决定页面分几节，等于把骨架交给了材质。

## 二、核心原则与硬边界

**硬边界**：本 skill 只决定节的数量与高度、动效的预算与曲线、文案的腔调判据。材质、配色体系、插画风格、组件库选型不在职责内，即使它们能让画面更好看。

### 原则 1：一屏一节，且节高只能是 1 或 2

```css
main > section, footer.closing { height: calc(var(--h, 1) * 100svh); }
```

`--h` 只允许取 1 或 2。不许 `min-height`，不许 `dvh`，不许第三节，不许用脚本设高。理由与全部换算见 `references/10-sections.md`。

### 原则 2：分离只靠底色变化或留白

节与节之间、节内块与块之间，不许出现分隔线、投影、内嵌色块当分隔。整幅底色换一次，或者什么都不做，靠留白分开。

这一条最容易被违反，因为加一条 1px 线立刻「看起来整齐了」。那是把结构问题用装饰掩盖。

### 原则 3：动效三层封顶

一页只有三层能动能响：hero 入场一次、一个 dealt moment 独占其节、hover/press 层。别的都不动。

> 滚动除了那个 moment，什么都不该移动。

卡片不许随滚动淡入升起错开，文字不许做视差，页面不许被脚本挟持。

### 原则 4：任何曲线不许过冲

三条曲线够用，全部是 ease-out 家族，没有 bounce、没有 overshoot、没有弹性回弹。过冲是 2015 年的语言。

### 原则 5：文案的敌人不是「华丽」，是「均匀」

第一代 AI 味是词表（delve / seamless / unlock），已经被大家躲开了。真正活下来的是第二代：每一段都同样温暖、同样具体、同样有一句金句收尾。均匀本身就是 tell。

修法不是加个性，是按客户选 register，让不同页面的语速不一样。

### 原则 6：中文不是英文的等比缩放

62 字符行宽、13px 最小字号、句子式大小写、0.14em 字距——这四条全是英文口径，照搬到中文会立刻出问题。全部换算见 `references/40-type-cn.md`。

## 三、可调参数与设计变体

### 节高参数

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `--h` | `1` / `2` | 唯一合法的节高倍数 |
| `--padt` | `120px` / 手机 `96px` | 节顶到第一个内容 |
| `--padb` | `72px` / 手机 `48px` | 节底留白 |
| `--gut` | `80px` / 手机 `24px` | 左右边距 |
| 内容窗口 | 一屏 `708px` / 两屏 `1308px` | 1440×900，见窗口表 |
| fill 下限 | `0.55` | 内容占节高比例 |

### 动效参数

| 参数 | 值 |
| --- | --- |
| `--m-in` | `150ms` |
| `--m-out` | `120ms` |
| `--m-press` | `90ms` |
| `--m-image` | `600ms`（进）/ `400ms`（出） |
| `--m-cycle` | `3.2s`（循环类） |
| `--ease` | `cubic-bezier(.2,.8,.2,1)` 所有 UI 步进 |
| `--m-ease-enter` | `cubic-bezier(.22,1,.36,1)` 落定 |
| `--m-ease-io` | `cubic-bezier(.65,0,.35,1)` 只用于位移 |

位移量：卡片抬 `2px`、图在框内推近 `1.02 → 1.03`、箭头 `3px`、菜单下落 `6px`、按钮 hover `1px`、按下 `1px` 且 `scale(.985)`。

### 文案档位

| 档 | 语速 | 适合 |
| --- | --- | --- |
| plain | 短句、名词为主、无形容词 | 工具、B 端、开发者产品 |
| warm | 允许一句人话、允许第一人称 | 小店、服务、工作室 |
| dry | 长句、从句、克制、几乎无感叹 | 出版、研究、专业服务 |
| 其余 register | 按客户身份选，不许全站一个腔 | 见 `references/30-copy.md` |

### 变体

- **A 叙事长页**：6–8 节，全 1 屏，一个 moment。适合产品发布。
- **B 图册页**：4–5 节，其中 1–2 节 2 屏，靠照片主导。适合场所、实物产品。
- **C 单屏页**：1 节 1 屏 + footer，不给动效，只给排版。适合活动页、简历。

三选一，不许混。

## 五、执行流程

1. **分档**。判断产物属于 software / gaming / tech / product / service / place 六类中的哪一类。判据：有人在这里被雇佣 → service；有人来这里 → place；只有门口什么都不发生 → product。写进计划第一行。
2. **列节清单**。用一句话写出每节的主张，必须是可反驳的句子，不许是名词短语。列完数一遍：A 变体 6–8 条，B 变体 4–5 条，C 变体 1 条。
3. **配节高**。逐条估内容高度，查 `references/10-sections.md` 的窗口表，落进 495–708 的给 `--h:1`，落进 1320–1608 的给 `--h:2`，落在 708–1320 的必须砍或拆，不许硬塞。
4. **写结构**。`main > section` + `footer.closing`，唯一的 h2 是每节第一个内容，顶对齐在 `--padt`。
5. **定动效预算**。写一行「这一页只动这三处」，写不出来的动效直接删。
6. **写文案**。先把事实列出来（数字、地点、价格、日期），再组句。每节标题必须有一个名词指向实物。
7. **跑检查**。`node assets/taste-check.mjs index.html`，按输出逐条修。
8. **看两遍**。一遍在 1440×900，一遍在 390×844。看的是「滚下去有没有一段不知道自己在哪里」。

## 六、交付检查清单

**结构**

- [ ] 每节 `height: calc(var(--h,1) * 100svh)`，`--h` 只出现 1 或 2
- [ ] 没有 `min-height` 撑节、没有 `dvh`、没有脚本设高
- [ ] 节内没有分隔线、没有投影当分隔、没有内嵌色块当分隔
- [ ] 每节只有一个 h2，且是第一个内容，顶对齐
- [ ] 每节 fill ≥ 0.55
- [ ] 没有落在 708–1320 非法带的内容
- [ ] 没有 scroll-snap、没有滚动劫持、没有平滑滚动库

**排版（中文）**

- [ ] 正文 ≥ 16px，行高 1.7–1.9
- [ ] 行宽 28–40 字
- [ ] 无斜体强调、无手动字距、无全角空格对齐
- [ ] 全角标点，行首无 ，。、；：？！）」』】
- [ ] 中英混排有间隙，数字与单位不断行

**动效**

- [ ] 每页 hero 入场一次
- [ ] 每页一个 dealt moment（长页两个），独占其节
- [ ] 没有随滚动的卡片淡入/升起/错开
- [ ] 三条曲线之一，无过冲
- [ ] 只动 transform / scale / opacity（hover 另可动颜色）
- [ ] `prefers-reduced-motion` 下全静止且不隐藏内容

**文案**

- [ ] h1 点名品类，2–8 词
- [ ] 首屏有一个硬事实：数字 / 地点 / 价格 / 日期
- [ ] 每个标题里有一个名词指向实物
- [ ] 按钮以动词开头，全部标签 ≤ 10 个不同
- [ ] 主操作在 nav/hero/close 措辞完全一致
- [ ] 无第一代禁用词、无套话残留
- [ ] 第二代 tell 各自未超 cap
- [ ] 页面没有一处谈论自己（「这一节展示了…」）

**最后一条**：把这一页和 figma.com 的一帧并排放。差距在节高还是在文案。
