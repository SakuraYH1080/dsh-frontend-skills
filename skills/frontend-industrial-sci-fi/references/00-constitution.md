# 00 · 宪法：两套语言怎么取舍、怎么裁决、产品该往哪边偏

## 1. 先说结论：不是融合，是分工

「莱茵生命式科研机构语言」和「终末地式工业秩序」不是两种皮肤，是两套约束，管的是不同层：

| 层 | 科研机构侧提供 | 工业秩序侧提供 |
| --- | --- | --- |
| 信息架构 | 三态、读数结构、置信度、时间戳 | 分区、编号、列对齐 |
| 元素形状 | （不管） | 切角、1px 线、零圆角、零阴影 |
| 色彩 | 冷白 + 深墨 + 单一信号色 | 单色强调，只填充不描边 |
| 排版 | （不管） | 宽体大写标签 + 粗体中文 + 0.14em 字距 |
| 动效 | 状态连续性、过渡曲线 | 短硬机械、时长极短 |

**冲突只发生在两侧都「管」的地方**，一共五处，第 6 节逐条裁决。
把两个 skill 直接叠加（科研的圆角 + 工业的切角、科研的多色 + 工业的单色）得到的是噪声，不是混合体。

## 2. 五个冲突点的一行裁决

| 冲突点 | 裁决 | 一句话理由 |
| --- | --- | --- |
| 圆角 | 全站 0 圆角，用切角 | 切角有方向，圆角没有；方向是工业秩序的唯一来源 |
| 强调色数量 | 强调 1 个 + 语义 2 个，分两条通道 | 状态不是强调，混用会让「选中」和「故障」长得一样 |
| 信息密度 | 字段不减，用 1:6:12 留白分级 | 删字段是丢信息，拉间距只是重排 |
| 动效 | 颜色 0ms，几何 90–140ms，进场 220ms | 告警不能「慢慢浮现」；形变可以帮助追踪 |
| 字体 | 标签用宽体大写，数据用等宽，中文用粗体 | 三者各自解决「定位 / 比较 / 理解」，不能互换 |

## 3. 兼容矩阵

行 = 科研侧规则，列 = 工业侧规则。「冲突」意味着必须选一边。

| | 切角零圆角 | 1px 细线 | 单色强调 | 宽体大写 | 短硬动效 |
| --- | --- | --- | --- | --- | --- |
| HUD 模块编号 | 互补 | 互补 | 互补 | 互补 | 互补 |
| 三态状态机 | 互补 | 互补 | **冲突**（见 6.2） | 互补 | **冲突**（见 6.4） |
| 读数 + 单位 + 精度 | 互补 | 互补 | 互补 | **冲突**（见 6.5） | 互补 |
| 置信度条 | 互补 | 互补 | 互补 | 互补 | 互补 |
| 分区标题 | 互补 | 互补 | **冲突**（标题爱用强调色） | 互补 | 互补 |
| 圆角卡片 | **冲突**（见 6.1） | 互补 | 互补 | 互补 | 互补 |

读法：只有三处真冲突 —— 强调色数量、动效连续性、字体角色。其余都是互补，
互补的意思是「两边说的是同一件事的不同侧面」，直接叠就是加强，不需要裁决。

## 4. 产品怎么选主导方向：三问打分

不要凭「哪个好看」选。问三个只有产品能回答的问题，每题 0/1/2 分：

1. **内容有时序吗？** 用户要不要按时间回看、对比前后？
   - 0 分：只看当前状态（设备管理台、开关面板）
   - 1 分：有历史但只偶尔回看（日报、周报）
   - 2 分：核心操作就是沿时间移动（日志回放、试验记录、监控回溯）
2. **操作不可逆吗？** 点错会不会造成不可撤销的后果？
   - 0 分：纯浏览，点错就是点错
   - 1 分：有写操作，但能撤销
   - 2 分：写操作不可撤销（下发指令、删除样本、启动物料）
3. **环境暗吗？** 用户主要在什么照度下看？
   - 0 分：白天、办公室、亮环境
   - 1 分：混合
   - 2 分：夜间、暗室、戴设备看

总分 0–2 → **industry 主导**（工业秩序侧说了算，科研侧只提供三态与读数结构）
总分 3–4 → **research 主导**（科研侧说了算，工业侧只提供切角与字体规则）
总分 5–6 → **research 主导 + 反相预设**（cold-store），并把状态提示提到最上层

为什么用这三问而不是「用户是谁」：身份是最容易自我欺骗的变量。
时序、可逆性、照度是**任务属性**，能直接从交互里数出来。

## 5. 主导方向意味着什么（具体到可见的差别）

| | industry 主导 | research 主导 |
| --- | --- | --- |
| 切角深度 | 4px（更硬） | 8px |
| 行高 | 32px | 36px |
| 一屏模块数 | 4–6 | 8–12 |
| 状态条 | 常驻、细（2px） | 常驻、粗（4px）+ 文字标签 |
| 数字字号 | 20px | 15px（更多列） |
| 时间戳 | 相对（`T-04:12`） | 绝对（`2026-11-06 18:22:04`） |
| 动效 | 90ms | 140ms |

差别不在「风格」，在**取舍的默认值**。默认值错了，细节怎么修都别扭。

## 6. 冲突裁决全文

以下五条是第 2 节表格的展开。每条给：冲突描述 → 裁决 → 理由 → 实现 → 反例。
**裁决不可协商**。如果某个项目确实需要另一边，那不是「调整」，是「换主导方向」（见第 4 节三问）。

### 6.1 圆角：科研偏柔 2–6px vs 工业偏切角

**裁决：全站 `border-radius: 0`，用切角替代。科研侧的「柔和」由留白与行高承担，不由圆角承担。**

理由：圆角是**无方向的** —— 一个 4px 圆角在左上和右下完全一样，它只表达「软」。
切角是**有方向的** —— 右上 + 左下切角构成一条对角线，它表达「这一块归属于某个流向」。
工业秩序的全部信息量来自方向性，所以圆角在这里是纯损失：
它软化了边缘，却没有换来任何可读的信息。

科研侧的「理性、去情绪」其实也不需要圆角 —— 需要的是**均匀的留白**和**稳定的行高**。
把这两项做好，界面已经足够「冷静」；再加圆角只会让它变成「消费品仪表盘」。

实现：

```css
* { border-radius: 0; }   /* 全局，包括 button / input / img */
.isx-card { --cut: 8px; }
/* 切角路径只切右上 + 左下，见 10-tokens.md 第 3 节 */
```

**反例**：卡片 4px 圆角 + 按钮 999px 胶囊。胶囊按钮在这套语言里是最刺眼的一处 ——
它的曲率半径与全站任何元素都不共享几何基准。

### 6.2 强调色数量：科研多色状态编码 vs 工业单色

**裁决：强调 1 个（signal），语义 2 个（caution / interrupt），分属两条通道，互不冒充。**

理由：这两组颜色回答的是不同问题。

| 通道 | 回答 | 元素 | 数量 |
| --- | --- | --- | --- |
| 强调（accent） | 「你在哪 / 这能点」 | tab 选中、主按钮、焦点环 | 1 |
| 语义（state） | 「它正常吗」 | 状态条、状态点、告警行 | 2（+ NOMINAL 用中性灰） |

工业侧说「单色强调」，说的是第一条通道；科研侧说「多色状态编码」，说的是第二条通道。
**它们本来就不在同一层**，所以不是「谁让步」，是「各自归位」。

真正要禁止的是**交叉使用**：用 interrupt 红做按钮背景，或把 signal 黄绿用在告警条上。
一旦交叉，「这是选中」和「这是故障」就长得一样，两个通道同时失效。

实现约束（可机器检查）：

```css
[data-state="caution"]   { --isx-state: var(--isx-caution); }
[data-state="interrupt"] { --isx-state: var(--isx-interrupt); }
.isx-gauge-fill { background: var(--isx-state); }        /* 只有状态元件读 --isx-state */
.isx-btn--primary { background: var(--isx-signal); }     /* 按钮只读 signal */
```

检查方法：`grep -rn "E2453C\|E8A33D" assets/industrial.css | grep -v "\-\-isx-"` 应当无输出 ——
状态色只允许出现在变量声明处，不允许出现在组件规则里。

**反例**：三个 tab 分别用黄绿 / 琥珀 / 赤做选中条（「多色状态编码」被误用到强调通道）。
用户看到的是一排「红黄绿灯」，他以为三个 tab 分别是正常 / 警告 / 故障。

### 6.3 信息密度：科研 HUD 高密度 vs 工业克制

**裁决：字段不减，用 1:6:12 的留白分级建立分组；一屏模块数由预设决定，不由「想放多少」决定。**

理由：删字段是**丢信息**，拉间距是**重排信息**。前者不可逆，后者可逆。
高密度 HUD 之所以能读，不是因为字小，是因为**分组边界清楚** ——
读者靠「块」跳过无关区域，而不是逐字读。

留白分级（10-tokens 第 5 节）：段内 4/8/12 → 段间 24 → 区块 48/64，比例 1:6:12。
只要这个比例成立，13px 字 + 32px 行 + 12 模块就是可读的；
比例失效（段内 12、段间 16），即使降到 6 模块也不可读。

**反面案例**：为了「工业克制」，把 8 个字段删到 4 个。结果用户需要点开详情看另外 4 个，
每看一次就丢失一次上下文 —— 查阅与执行的来回跳，比高密度更耗神。

### 6.4 动效：科研连续过渡 vs 工业短硬机械

**裁决：颜色 0ms（瞬时），几何 90–140ms（可追踪），进场 220ms（上限）。同一帧内颜色先到位、几何后完成。**

理由：两套语言对动效的诉求其实指向**不同的属性**：

- 科研侧要「连续性」，是要让用户**追踪状态迁移**（这条从 60% 涨到 82%）。
- 工业侧要「短硬」，是要让用户**立刻知道结果**（这条已经中断）。

属性拆开就都满足了：颜色承担「结果」，几何承担「过程」。
所以 `transition: all` 是这里最危险的写法 —— 它让颜色也走过程，直接违反工业侧。

实现与禁止清单见 40-motion 第 3、6 节。

**反例**：状态条宽度 400ms 缓动 + 底色 400ms 渐变。观感像「仪表盘在呼吸」，
但操作员抬眼时看到的是「橙色正在变成红色」，他无法判断此刻到底断了没有。

### 6.5 字体：科研中性无衬线 vs 工业宽体大写

**裁决：按角色分工 —— 标签用宽体大写（工业），数据用等宽（中性），正文中文用系统无衬线粗体（中性）。**

理由：三种文字解决三个不同问题，没有重叠，所以不需要「选一个」。

| 角色 | 解决 | 为什么非它不可 |
| --- | --- | --- |
| 标签（宽体大写 11px / 0.14em） | **定位**：在密集区里跳到某一列 | 大写去掉了字形的升降部差异，轮廓变成等高矩形，扫视时是「块」而不是「词」 |
| 数据（等宽 + tabular-nums） | **比较**：两列数字的差 | 只有等宽能让小数点对齐 |
| 正文（中文系统字） | **理解**：读一句话 | 中文没有大写，强行加字距会散架 |

冲突只出现在「把其中一种当成全站唯一字体」的时候。三种并存不是妥协，是必要的分工。

**反例**：全站宽体大写（包括中文和数值）。中文变成「冷 却 回 路」，
数值 `24.6` 与 `7.8` 不再对齐 —— 三个问题一个都没解决。

## 7. 组合时的主导语言规则

当一个界面同时出现两套语言的设计意图时，按下面顺序判定：

1. **有不可逆写操作** → 工业侧主导（切角 4–8、行高 32、短动效、状态常驻）。
   理由：不可逆操作要求「确认感」，短硬反馈提供确认感；连续过渡提供的是「流畅感」，用错了地方。
2. **否则有强时序内容**（日志回放、试验记录） → 科研侧主导（行高 36、绝对时间戳、8–12 模块）。
3. **否则两者打平** → 工业侧主导。
   理由：默认值应该偏向**约束更强**的那一侧。工业侧的约束（零圆角、单强调色、1px）
   是可验证的硬约束；科研侧的约束（留白、密度）是软的。硬约束做默认，容错更高。

**不允许的判定方式**：

- 「客户喜欢科技感」 —— 不是判据，无法验证。
- 「两个都要」 —— 会导致 6.1 的圆角 + 切角共存。
- 「看哪个参考图好看」 —— 参考图不含交互约束，无法推出默认值。

## 8. 一票退回（按可验证性排序，越靠前越容易机检）

1. `border-radius` 出现非 0 值（`grep -rn "border-radius" assets/ ` 数，除 `0` 外任何值都算）。
2. 一屏出现 ≥ 2 个「看起来是强调」的色块（截图转灰度，两个元素灰度相近却语义不同，即命中）。
3. 状态色（琥珀 `#E8A33D` / 赤 `#E2453C`）出现在按钮背景、tab 选中条、链接文字上。
4. 切角与边框不同路径：放大 400% 时切角处 1px 线断开或错位。
5. 用 `box-shadow` 表达层级 —— 与 `clip-path` 并存时会出现被裁的脏边。
6. 使用 `linear-gradient` 做面或做文字。
7. 数字列未设 `tabular-nums`，导致小数点不对齐。
8. 状态自动降级（INTERRUPT → CAUTION → NOMINAL 无 RESET 控件）。
9. 告警必须 hover 才可见。
10. 首次渲染即播放超过 3 个并行动效。
11. 圆角与切角同屏共存（含 `border-radius: 50%` 的头像、开关）。
12. `transition: all` 出现在任何状态容器上。
13. 浅底预设（cold-store）直接沿用深底的状态色，未做压暗。
14. 一屏出现两种切深，且不属于 chip 4 / card 8 / panel 14 三档。
15. 标签用中文大写化（`text-transform: uppercase` 作用于含中文的元素）。
