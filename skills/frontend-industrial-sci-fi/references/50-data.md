# 50 · 数据：读数、表格、图表、时间戳、告警流

## 1. 读数的四要素

一个合格的读数必须同时有四项，缺一项就会被误读：

```html
<div class="isx-readout">
  <span class="isx-readout-label">供液温度 / SUPPLY TEMP</span>
  <span class="isx-readout-value">
    <span class="isx-num">24.6</span><span class="isx-unit">°C</span>
  </span>
  <span class="isx-readout-meta">SET 22.0 · Δ +2.6</span>
  <span class="isx-readout-meta">18:22:04</span>
</div>
```

| 要素 | 缺了会怎样 |
| --- | --- |
| 数值 + 单位 | 用户不知道 24.6 是什么 |
| 设定值 / 目标 | 用户不知道 24.6 算不算正常 |
| 偏差（Δ） | 用户要自己做减法，高密度下会算错 |
| 时间戳 | 用户不知道这是不是当前值 |

**反面案例**：只显示大数字 `24.6`。观感干净，但操作员必须去别处找设定值，
两次扫视之间状态可能已经变了。

## 2. 表格：7 列上限与两级表头

| 列数 | 策略 |
| --- | --- |
| ≤ 7 | 单级表头，行高 32px |
| 8–12 | 两级表头（分组 + 子列），组间用 2px 分隔（唯一允许的 2px，且只用于表头分组） |
| > 12 | 拆分：主表 5 列 + 详情面板 |

```html
<table class="isx-table">
  <thead>
    <tr class="isx-group-row">
      <th colspan="3">IDENTITY</th>
      <th colspan="2">MEASURE</th>
    </tr>
    <tr>
      <th>编号</th><th>名称</th><th>状态</th>
      <th class="isx-num">温度 °C</th><th class="isx-num">压力 kPa</th>
    </tr>
  </thead>
</table>
```

规则：

- **数字列右对齐**，文本列左对齐，状态列居中。三者在同一行里形成固定的视觉锚点。
- **行高固定 32px**（不随内容变化）。变高行会让"第几行"失效，而人靠行位置定位。
- **斑马纹不要**。用 1px `line-weak` 分隔即可；斑马纹会让 12 行以上出现摩尔纹。
- **hover 只改底色 `ink-700`，不改尺寸**。任何让行变高/变宽的 hover 都会引起整表重排。

**反面案例**：行高由内容撑开，长名称换行成两行。结果第 7 行之后的所有行位置都变了，
用户按"从上往下第 5 行"找到的东西，刷新一次就换了。

## 3. 图表：只允许三种

| 类型 | 用途 | 约束 |
| --- | --- | --- |
| 时序折线 | 单指标随时间 | 最多 4 条线；每线 1.5px；不填充（填充会遮住其他线） |
| 阈值带 | 表示安全区间 | 用 8% 不透明度的色块，不加边框 |
| 水平条 | 占比 / 进度 | 高 6px，底槽 1px 线；条本身用 signal 或 state 色 |

**不要**：饼图（6 个以上扇区无法比较）、3D 任何东西、双 Y 轴（两条曲线的交点毫无意义）、
渐变填充面积图（渐变与零渐变原则冲突）。

时序折线的实现要点：

```css
.isx-spark { --w: 320; --h: 48; }
.isx-spark path { fill: none; stroke-width: 1.5; vector-effect: non-scaling-stroke; }
```

`vector-effect: non-scaling-stroke` 是关键：SVG 缩放时线宽不会跟着变粗，
这在响应式里能保证 1.5px 恒定 —— 与"1px 线"的语言一致。

## 4. 时间戳的三种位置

| 位置 | 格式 | 例 |
| --- | --- | --- |
| 行内（记录级） | `HH:MM:SS` | `18:22:04` |
| 区块级（页面顶部） | `YYYY-MM-DD HH:MM:SS` | `2026-11-06 18:22:04` |
| 跨系统（导出、API） | ISO 8601 + 偏移 | `2026-11-06T18:22:04+08:00` |

规则：**同一层级只用一种格式**。行内不用日期（因为区块级已经给了），
区块级不给毫秒（因为行内的秒已经够）。

## 5. 告警流（Alarm Feed）

告警流不是"消息列表"，是**按严重度排序的时间线**。三条规则：

1. **排序键是"严重度 → 时间"，不是"时间"。** 最新的 CAUTION 不应该压住 10 秒前的 INTERRUPT。
2. **每条告警必须能回答三问**：哪个模块？什么指标？什么时候？
3. **ACK 之后不删除，改为降饱和并下沉到"已确认"区。** 删除会让操作员失去"刚才发生了什么"的记录。

```html
<li class="isx-alarm" data-state="interrupt">
  <span class="isx-alarm-time">18:21:57</span>
  <span class="isx-alarm-code">SYS-03</span>
  <span class="isx-alarm-msg">回路断开 / LOOP OPEN</span>
  <button class="isx-alarm-ack">ACK</button>
</li>
```

样式要点：

- 未确认：左侧 3px 状态色竖条 + 正常对比度。
- 已确认：竖条变为 `ink-500`，文字降到 `ink-300`，**仍可读**（≥ 4.5:1）。
- 未读计数用 signal 色**填充**的方块数字，不用红点（红点是 status 通道，会与 interrupt 混淆）。

## 6. 空态与加载态

| 态 | 做法 | 禁止 |
| --- | --- | --- |
| 空 | 一行 `micro` 文字 `NO RECORD` + 编号 `—` | 插画、笑脸、"暂无数据"居中大图标 |
| 加载 | 一行 1px 的 `line-strong` 从 0 到 100% 宽，140ms × 3 次循环 | 旋转 spinner（无方向，且与"机械"语言冲突） |
| 错误 | 状态色 interrupt 的 1px 边框 + 文字 `ERR: <code>` | 弹窗、Toast（会遮住正在看的数据） |

为什么不用 spinner：旋转是连续的圆周运动，本语言里所有运动都是**直线 + 硬停**。
一个转圈的东西会立刻暴露"这不是同一套系统"。

## 7. 数据密度与可读性的边界

一屏能放多少读数，由**最小可读行高**决定，不是由审美决定：

- 行高 32px 是"能扫"的下限（28px 需要更长的注视时间，40px 开始浪费竖向空间）。
- 900px 高的可视区，减去页头 64 + 页脚 40 + 区块间距 48×2 = 700px 可用 → **21 行**。
- 加上两级表头 64px → 20 行。
- 再考虑"一眼能记住"的上限是 **12–15 行** —— 超过这个数，用户必须滚动。

结论：**单屏数据区 12–15 行、总行数无限**。不要为了塞进一屏而把行高压到 24px，
那会让整块区域变成"纹理"，用户会跳过它。

**反面案例**：为了"信息密度高"，把行高压到 22px、字号 11px。结果没人读它，
用户改用搜索框 —— 表格变成了装饰。
