# 10 · Token：色板、字号、切角几何、线宽、间距

## 1. 色板：两条通道，一名一实

### 1.1 基础色（不承担语义，只承担明暗）

| Token | HEX | 用在哪 | 为什么是这个值 |
| --- | --- | --- | --- |
| `ink-950` | `#07090A` | 页面底（夜间 / site 预设） | 比 `#000` 浅 3 级灰阶，纯黑在 OLED 上会让 1px 线"发光溢出" |
| `ink-900` | `#0A0C0E` | 页面底（默认） | 与 `paper-000` 的对比 17.74:1，远超 4.5:1，但不到刺眼的 21:1 |
| `ink-850` | `#111417` | 面板底（比页底亮一档） | 亮一档而不加阴影，是唯一允许的"层级"手段 |
| `ink-700` | `#1C2126` | 面板 hover / 表头 | 与 ink-850 差 5%，刚好可辨 |
| `ink-500` | `#828E96` | 次要文字 | 对 ink-900 为 5.84:1、对 panel `#111417` 为 5.51:1、对 raised `#1C2126` 为 4.83:1 |
| `ink-300` | `#8B979F` | 标签文字 | 对 ink-900 为 6.55:1 |
| `paper-000` | `#F2F4F3` | 浅底页面 / 深底主文字 | 略带青绿的中性白，避免纯白的"办公软件感" |
| `paper-100` | `#E3E7E5` | 浅底面板 | 与 paper-000 差 4%，浅底上唯一层级手段 |
| `line-strong` | `#66737B` | 分区主线 | 对 `#1C2126` 为 3.32:1、对 `#111417` 为 3.79:1、对 `#0A0C0E` 为 4.01:1；三条底线都过，且仍是「细线不抢戏」 |
| `line-weak` | `#262C31` | 行分隔线 | 只在深底出现，浅底用 `#CBD2CF` |

### 1.2 信号色与状态色：分属两条通道

| Token | HEX | 通道 | 允许出现的元素 | 不允许 |
| --- | --- | --- | --- | --- |
| `signal` | `#C8F04B` | 强调 | 当前 tab 填充、主按钮填充、焦点环、状态条末端 4px | 告警、错误、禁用态 |
| `signal-hover` | `#BCE146` | 强调 | 只用于 `:hover` / `[aria-pressed=true]` 的填充 | 常态填充、静态装饰 |
| `caution` | `#E8A33D` | 语义 | 状态条中段、状态点、告警行左侧 3px | 按钮、选中、链接 |
| `interrupt` | `#E2453C` | 语义 | 中断条、中断徽标、闪烁边框（1Hz） | 任何可点击元素 |
| `cold-store` | `#A6C43E` | 强调（降饱和） | night-shift 预设的 signal | 与其他预设混用 |

为什么信号色选黄绿 `#C8F04B`：它在深底上的对比是 14.95:1，可以当填充也能当焦点环；
同时色相在 74°（黄绿），与 caution 的 35°（橙）和 interrupt 的 4°（红）都 ≥ 30° 间隔，
色盲模拟下不会互相混淆 —— 这是三个颜色能同时存在的前提。

**反面案例**：信号色用青色 `#39D0D8`。青与绿在红色盲（protanopia）下几乎同色，
一旦状态条出现了绿色段，用户分不清那是"正常"还是"高亮"。

### 1.3 hover：显式给值，不用 `filter`

强调色的三档 hover（`#BCE146` / `#4C5D19` / `#98B536`）都是硬写的，不是 `filter: brightness(0.94)`。

理由是可比：滤镜作用在**渲染后的像素**上，压暗 6% 的结果肉眼看不出差别，
但任何颜色计算（对比度、色盲模拟、导出设计稿）都拿不到这个值 —— 不可计算的规则没法检查，也就没法守住。
显式给值的代价只有三行变量，收益是 hover 态的 `onSignal` 对比可以逐项验（13.06 / 6.58 / 8.39）。

**反面案例**：`.btn:hover { background: var(--isx-signal); filter: brightness(0.94); }`。
它的问题不是对比度 —— 深底上压暗后 14.95→13.06，浅底上 4.62→5.09，两种都还在线上。问题是三件别的事：

1. **数值不可预测**：`brightness(0.94)` 的实际输出要按每个预设的 hex 手算一遍才知道，而显式值写下来就是答案。
2. **创建包含块**：元素上的 `filter` 使其成为 `position: fixed` 后代的包含块，也让 `clip-path` 切角层的定位基准从视口变成该元素 —— 切角会错位 1px。
3. **导出即失真**：设计稿、色板、对比度报告都拿不到这个像素值，规则从此不可审。

## 2. 字号阶梯：五档，只有五档

| Token | px | 行高 | 字重 | 字距 | 用途 |
| --- | --- | --- | --- | --- | --- |
| `display` | 40 | 1.1 | 700 | -0.01em | 大屏主读数（最多 2 个/屏） |
| `readout` | 20 | 1.2 | 700 | 0 | 模块主数值 |
| `body` | 13 | 1.45 | 400 | 0 | 正文、表格单元格 |
| `label` | 11 | 1.2 | 500 | 0.14em | 英文全大写标签、表头 |
| `micro` | 10 | 1.2 | 500 | 0.18em | 编号、单位、时间戳 |

为什么只有五档：字号每多一档，"哪个更大"就开始依赖像素级比较。
五档的跳跃是 40/20/13/11/10 —— 前两档差 2×，后三档差 1.18–1.3×，
这是肉眼能立刻分辨的最小集合。**加第六档等于取消层级。**

**反面案例**：加一个 15px 用于"副标题"。结果是 13 与 15 混排时，读者以为 15 是重点，
但它其实只是排版顺手 —— 层级被伪造了。

## 3. 切角几何：对角两角，三个深度

```css
/* 右上 + 左下切角，cut 为切深 */
clip-path: polygon(
  0 0,
  calc(100% - var(--cut)) 0,
  100% var(--cut),
  100% 100%,
  var(--cut) 100%,
  0 calc(100% - var(--cut))
);
```

- `chip`: cut = 4px（标签、状态点容器、按钮）
- `card`: cut = 8px（面板、卡片、表格块）
- `panel`: cut = 14px（整页大区块、抽屉）

**边框同路径的做法**（这是最容易做错的地方）：

```css
.isx-card {
  --cut: 8px;
  position: relative;
  clip-path: polygon(0 0, calc(100% - var(--cut)) 0, 100% var(--cut),
                     100% 100%, var(--cut) 100%, 0 calc(100% - var(--cut)));
  background: var(--isx-line);              /* 外层 = 线色 */
}
.isx-card::before {
  --cut-inner: calc(var(--cut) - 1.414px);  /* 45° 内缩 1px = 减 √2 */
  content: "";
  position: absolute;
  inset: 1px;
  clip-path: polygon(0 0, calc(100% - var(--cut-inner)) 0, 100% var(--cut-inner),
                     100% 100%, var(--cut-inner) 100%, 0 calc(100% - var(--cut-inner)));
  background: var(--isx-panel);
}
```

为什么内层要减 1.414 而不是 1：45° 倒角上，垂直内缩 1px 对应的斜边截距是 `1 / sin45° = 1.414`。
减 1 会让切角处的线变粗 0.41px，放大后是一条明显歪掉的边。

**反面案例**：用 `border: 1px solid` + `clip-path`。`clip-path` 会裁掉一半边框，
切角处要么没线，要么线只剩 0.5px —— 这是"切角像贴纸"的头号原因。

## 4. 线宽：只有一个值

`--isx-hairline: 1px`。全站唯一。

- 分区线、表格线、切角边、状态条底槽，全部 1px。
- 需要"更重"的线时，**不改宽度，改颜色**（`line-weak` → `line-strong`）。
- 高 DPI 屏上 1px 物理像素 = 0.5 CSS px，仍然写 1px；不要写 `0.5px`（Safari 会四舍五入成 0）。

**反面案例**：用 2px 做"重要分区"。结果是重要分区看起来像边框失控，
而且和 1px 并排时会出现 1px 的错位缝。

## 5. 间距：七档，比例 1:6:12

| Token | px | 用途 |
| --- | --- | --- |
| `s-1` | 4 | 同一行内元素间（图标与文字） |
| `s-2` | 8 | 同一段内行距 |
| `s-3` | 12 | 字段与字段 |
| `s-4` | 16 | 卡片内边距 |
| `s-6` | 24 | **段间距** |
| `s-12` | 48 | **区块间距** |
| `s-16` | 64 | 页面外边距 |

比例关系：段内 4 → 段间距 24 → 区块 48，即 **1:6:12**。
这个比值不是审美，是**分组可辨性**：当两个间距的比值 < 2 时，人眼会把它们读成同一级；
6× 保证"这一段结束了"能被一眼看出，而不需要加分隔标题。

**反面案例**：段内 12、段间 16。比值 1.33，于是每个字段看起来都属于同一组 ——
这正是"高密度表格扫不动"的真实原因，与字号无关。

## 6. tokens.json 字段说明

```jsonc
{
  "presets": {
    "standard": {
      "surface": { "page": "#0A0C0E", "panel": "#111417", "raised": "#1C2126" },
      "text":    { "primary": "#F2F4F3", "secondary": "#8B979F", "muted": "#828E96" },
      "line":    { "strong": "#66737B", "weak": "#262C31" },
      "signal":  "#C8F04B",
      "signalHover": "#BCE146",
      "cut": { "chip": 4, "card": 8, "panel": 14 },
      "hairline": 1,
      "track": 0.14,
      "row": 32,
      "dur": 140
    }
  },
  "state": { "nominal": "#8B979F", "caution": "#E8A33D", "interrupt": "#E2453C",
             "nominalOnLight": "#6E7A82", "cautionOnLight": "#8F5A10", "interruptOnLight": "#B22E26" },
  "motion": { "instant": 0, "tick": 90, "geom": 140, "enter": 220,
              "ease": "cubic-bezier(0.2,0,0,1)" }
}
```

三个约定：

1. **单位**：所有长度字段是纯数字，单位在实现层补（CSS px / iOS pt / Android dp）。
   `cut` 的 4/8/14 在 2x 屏上仍是 4/8/14 CSS px。
2. **不存派生值**：`tokens.json` 里没有 `cutInner`，因为它由 `cut - 1.414` 推导；
   存了就会在两个地方各改一次，然后不一致。
3. **状态色在 `state` 下，不在 `presets` 下**：状态是全局语义，不随预设变化。
   把 `caution` 放进预设，等于允许某个预设"没有警告色"，那就不再是同一套系统。

## 7. 落成 CSS 的一处定义

```css
:root {
  --isx-signal: #C8F04B;
  --isx-signal-hover: #BCE146;
  --isx-caution: #E8A33D;
  --isx-interrupt: #E2453C;
  --isx-cut: 8px;
  --isx-hairline: 1px;
  --isx-track: 0.14em;
  --isx-row: 32px;
  --isx-dur: 140ms;
}
:root[data-isx-preset="cold-store"] {
  --isx-page: #F2F4F3;
  --isx-panel: #E3E7E5;
  --isx-text: #0A0C0E;
  --isx-line: #CBD2CF;
}
```

规则：**变量只在 `:root` 和 `[data-isx-preset]` 上赋值**，组件里只读不写。
组件里出现 `#C8F04B` 这个字面量，就是一次未来的不一致。
