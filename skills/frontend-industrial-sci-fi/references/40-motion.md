# 40 · 动效：机械曲线、四档时长、状态过渡

## 1. 立场：动效是"确认"，不是"表演"

工业界面里，动效只回答一个问题：**我这一下操作，系统收到没有？**
回答完就结束，不做任何多余的移动。

所以本 skill 的动效有三条硬性限制：

1. **时长上限 220ms。** 超过 220ms 的过渡在监控场景里会被读成"卡"。
2. **只动几何与不透明度，不动颜色。** 颜色变化必须瞬时（0ms），见第 4 节。
3. **同屏并行动效 ≤ 3 个。** 第 4 个开始，人眼无法分配注意力，只感到"在闪"。

**反面案例**：面板进场用 `translateY(24px) + scale(0.96) + opacity`，420ms。
观感"高级"，但用户在等待那 420ms 里无法确认点击是否生效 —— 这段等待是纯成本。

## 2. 曲线：一条自定义 + 两条系统

```css
--isx-ease: cubic-bezier(0.2, 0, 0, 1);   /* 主曲线：快出慢入，机械感 */
```

为什么是 `cubic-bezier(0.2, 0, 0, 1)`：

- 起点斜率 = `(0 - 0.2) / (0 - 0) = ∞` 之外的陡升：0.2 的水平控制点意味着**头 20% 时间走完 55% 距离**。
- 这就是"机械"的来源：机构启动时是瞬时到位，然后停住，不是缓慢加速。
- 终点 `(0,1)` 与 `(1,1)` 重合 → 末段几乎无减速，直接停 —— 这就是"硬"。

对比 `cubic-bezier(0.16,1,0.3,1)`（液态玻璃用的那种）：它先快后极慢，
末段有 200ms 以上的"尾巴"，观感柔软 —— 与本 skill 的机器感冲突。
**不要跨 skill 借用缓动曲线**，曲线是最容易串味的参数。

其余两条用系统关键字即可：

| 场景 | 曲线 | 理由 |
| --- | --- | --- |
| 状态条宽度 | `linear` | 线性变化让"变化速度"本身可读 |
| 数值滚动 | `cubic-bezier(0.2,0,0,1)` | 与主曲线统一 |
| 中断呼吸 | `steps(2, end)` | 机械闪烁，不要平滑（见第 5 节） |

## 3. 四档时长

| Token | 值 | 用在哪 | 上界推导 |
| --- | --- | --- | --- |
| `instant` | 0ms | 颜色、状态色、选中态 | 颜色渐变 = 告警"慢慢浮现"，必须禁 |
| `tick` | 90ms | 数值滚动、hover 底色 | < 100ms 时人感觉"立刻"；> 120ms 开始有等待感 |
| `geom` | 140ms | 状态条宽度、切角展开、面板高度 | 与 60fps 下 8–9 帧对齐，肉眼可追踪但不觉慢 |
| `enter` | 220ms | 面板出现、抽屉、模态 | 超过 220ms 用户开始怀疑没响应 |

`geom = 140ms` 的推导：人眼能追踪的位移需要在 6 帧以上（@60fps ≈ 100ms），
低于 6 帧会被读成"跳变"，高于 16 帧（267ms）会被读成"慢"。**140ms ≈ 8.4 帧**，正落在中间。

## 4. 状态过渡：颜色 0ms，几何 140ms

这是本 skill 最容易被做错的一条。

```css
/* 正确：颜色瞬切，只有几何过渡 */
.isx-panel {
  transition: border-color 0ms linear,
              --isx-state-width 140ms var(--isx-ease);
}
```

```css
/* 错误：颜色也过渡 */
.isx-panel { transition: all 220ms ease; }
```

为什么：`transition: all` 会把 `background-color` 也带上。当状态从 NOMINAL 切到 INTERRUPT，
红底色会用 220ms"渐入"—— 在监控场景里，这 220ms 正好是操作员抬眼的那一下，
他看到的是"橙色正在变成红色"，而不是"这条已经中断了"。**告警必须瞬间成立。**

正确做法：**只用几何的过渡来引导注意力**。同一帧里，

1. 状态色 `0ms` 到位（用户立刻知道"变了"）；
2. 状态条宽度用 `140ms` 过渡（用户能追踪"是哪一条变长/变短了"）；
3. 状态文字用 `0ms` 替换（不要打字机效果）。

**反面案例**：状态条宽度 400ms 缓动 + 颜色 400ms 缓动。观感像"仪表盘在摆动"，
但 400ms 里操作员已经切走了视线，他没看见是哪一条变的。

## 5. 中断呼吸：1Hz，用 steps 不用 ease

```css
@keyframes isx-breathe {
  from { opacity: 1; }
  to   { opacity: 0.72; }
}
.isx-interrupt {
  animation: isx-breathe 1000ms steps(2, end) infinite;
}
@media (prefers-reduced-motion: reduce) {
  .isx-interrupt { animation: none; opacity: 1; }
}
```

为什么 1Hz：0.5Hz（2s 周期）太慢，人眼在扫视时会错过半波；2Hz 以上进入"闪烁"区间，
长时间观看会引起不适。1Hz 是"一定能被看到，又不至于刺眼"的唯一值。

为什么用 `steps(2, end)` 而不是默认 ease：ease 会让透明度连续变化，
看起来像"呼吸"；steps 是两帧硬切，看起来像**指示灯**。机器是指示灯，不是肺。

**降级后必须仍有信号**：`prefers-reduced-motion` 下动画关掉，
但 4px 红条 + 实心红点保留 —— 中断态不能因为降级而变成"和正常一样"。

## 6. 进场：只允许位移 + 不透明度

```css
.isx-enter {
  animation: isx-enter 220ms var(--isx-ease) both;
}
@keyframes isx-enter {
  from { opacity: 0; transform: translateY(6px); }
  to   { opacity: 1; transform: translateY(0); }
}
```

- 位移量 **6px**：大于 12px 会显得"从很远飞过来"，小于 4px 看不出来。
- **不缩放**。`scale()` 会让 1px 线在动画过程中变成 0.8px 或 1.3px，
  切角边框会出现"抖动"的锯齿 —— 与"零圆角 + 1px 线"的语言直接冲突。
- **不旋转、不模糊**。`filter: blur()` 在这套语言里没有语义。

**反面案例**：进场用 `scale(0.96) → 1`。切角在缩放的每一帧都在重新栅格化，
1px 边框会出现可见的粗细跳动。

## 7. 数值滚动

```js
// 90ms、每帧步进；只在数值变化 > 2% 时启用
function roll(el, from, to, ms = 90) {
  if (Math.abs(to - from) < Math.abs(from) * 0.02) { el.textContent = fmt(to); return; }
  const t0 = performance.now();
  (function step(t) {
    const k = Math.min(1, (t - t0) / ms);
    el.textContent = fmt(from + (to - from) * k);
    if (k < 1) requestAnimationFrame(step);
  })(t0);
}
```

为什么设 2% 阈值：小于 2% 的变化滚动起来只有 1–2 个字符在跳，
观感是"数字在抖"，比直接替换更差。直接替换反而清楚。

## 8. 禁止清单

| 禁止 | 原因 |
| --- | --- |
| `transition: all` | 会带上颜色，破坏第 4 节 |
| 时长 > 220ms | 等待被读成卡顿 |
| `scale()` 参与过渡 | 1px 线与切角抖动 |
| `filter: blur()` 过渡 | 无语义，且触发重绘 |
| 自动循环的非告警动效 | 抢注意力，等于把告警降级 |
| 打字机文字效果 | 文字必须一次到位，用户要能立刻读 |
| 视差滚动 | 本语言里没有"深度"，只有"层" |
| `will-change` 常驻 | 内存代价，且掩盖真实的性能问题 |
