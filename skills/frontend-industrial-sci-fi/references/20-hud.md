# 20 · HUD：模块、编号、分区标题、三态

## 1. HUD 是什么，不是什么

HUD 不是「科幻边框 + 扫描线」。HUD 解决的问题只有一个：
**在一个高密度屏幕里，让人在 0.5 秒内定位「哪一块属于什么、它现在正常吗」。**

所以 HUD 只有三件组成部分，缺一件就不成立：

| 组成 | 解决 | 形态 |
| --- | --- | --- |
| 模块边界 | 「这一块是一个单元」 | 1px 线 + 切口两角 + 角落编号 |
| 分区标题 | 「这一块属于哪一类」 | 英文全大写 label + 12px 中文 |
| 状态指示 | 「它现在正常吗」 | 2px 状态条 / 状态点 / 状态字 |

装饰性的角标、扫描线、网格底纹**不属于 HUD**，它们是"科技感"的替代品，
占位但不传递信息。加了三层以上装饰的 HUD，实际问题往往是模块边界不清楚。

**反面案例**：八个面板都用 `box-shadow` 描出边框，每个面板四角加 L 形角标。
结果：边界看不出层级，角标重复八次以后变成噪声，用户的注意力被平均分配到所有地方。

## 2. 模块：三段编号

```text
SYS-03 / SEC.A / 0147
 │      │       └── 序号：4 位，本地递增，跨模块不重复
 │      └────────── 分区：A–F（一个屏最多 6 个分区）
 └───────────────── 单元：系统代号 + 2 位
```

为什么会话要三段而不是一段：

- **单元**（`SYS-03`）稳定不变，用来在聊天里指代（"看 SYS-03"）。
- **分区**（`SEC.A`）随页面组织变化，用来在屏内定位。
- **序号**（`0147`）全局唯一，用来写日志和贴问题单。

一段编号（`SYS-03-0147`）在口头沟通时无法断句，三段可以被说出来。
**这是编号存在的唯一理由：能被念出来。**

## 3. 分区标题（Zone Header）

```html
<header class="isx-zone-head">
  <span class="isx-zone-id">SEC.A</span>
  <h2 class="isx-zone-title">冷却回路 / COOLANT LOOP</h2>
  <span class="isx-zone-count">04 UNITS</span>
</header>
```

规则：

- 左 `SEC.A`（micro，10px，字距 0.18em，颜色 `ink-300`）
- 中 中文 + `/` + 英文全大写（body 13px 700；英文 label 11px 500 字距 0.14em）
- 右 计数或度量（micro，右对齐）
- 底部 1px `line-strong`，**长度 = 内容宽度**，不是 100%。

为什么分隔线不铺满：铺满的线会与下一个区块的线连成一条，
读者会误以为两个区块属于同一组。线短 40px 就断开了分组。

**反面案例**：标题用信号色。结果每个区块都有一个"高亮"，
信号色失去「你现在在这里」的含义，用户找不到当前 tab。

## 4. 三态：NOMINAL / CAUTION / INTERRUPT

| 态 | 颜色 | 几何 | 文字 | 出现条件 |
| --- | --- | --- | --- | --- |
| NOMINAL | `#8B979F` | 状态条 100% 宽，2px | 无（静默） | 默认 |
| CAUTION | `#E8A33D` | 状态条 60–99%，2px + 左侧 3px 竖条 | `CAUTION · 阈值 82%` | 单指标越阈 |
| INTERRUPT | `#E2453C` | 全宽 4px + 1Hz 呼吸（`opacity 1→0.72`） | `INTERRUPT · 回路断开` | 数据中断 / 安全联锁 |

三个必须成立的规则：

1. **NOMINAL 不显示文字。** 一旦正常也写字，用户就会开始忽略所有文字。
2. **CAUTION 必须给数值。** `CAUTION` 单独出现没有信息量，必须带「阈值多少、当前多少」。
3. **INTERRUPT 必须有终止动作。** 要么有 `ACK`（确认）按钮，要么有 `RESET`；
   只闪不给动作，等于让用户看着它闪。

## 5. 状态连续性：只升不降

这是本 skill 最重要的一条状态规则。

```text
NOMINAL ──► CAUTION ──► INTERRUPT      （自动，可跳级）
   ▲            │            │
   └────────────┴────────────┘
       仅通过显式 RESET / ACK
```

**为什么不让它自动降级**：自动降级意味着"警报自己消失了"。
在人机协作里，这条路径会让操作员错过事件 —— 他抬头时屏幕已经恢复绿色，
于是他不知道刚才发生过什么。显式 RESET 强制产生一次"我看到了"的动作，
这个动作本身就是确认（acknowledgement）。

实现上，状态存的是**历史最高值**而不是当前值：

```js
state.peak = Math.max(state.peak, state.current); // 只升
// 降级只有一条路径：
function acknowledge() { state.peak = state.current; }
```

## 6. 状态条与数据的关系

状态条长度**必须**来自真实数据，不能是装饰。

```html
<div class="isx-gauge" style="--v: 0.82">
  <div class="isx-gauge-track"></div>
  <div class="isx-gauge-fill"></div>
  <span class="isx-gauge-val">82.4 %</span>
</div>
```

```css
.isx-gauge-fill { width: calc(var(--v) * 100%); }
```

**反面案例**：为了「看起来在运行」，给每个模块随机一个 30–80% 的进度条。
用户第一次会看，第二次会发现所有条都不动，然后永久忽略这一列 —— 包括真正的告警。

## 7. 一屏的 HUD 上限

| 元素 | 上限 | 超了会怎样 |
| --- | --- | --- |
| 分区（SEC） | 6 | 无法在 0.5s 内建立空间记忆 |
| 模块（card） | 12 | 每个模块的信息密度低于可读阈值 |
| 同时 INTERRUPT | 1 | 两个同时中断时，用户会先处理视觉上更响的那个，而它不一定是更严重的 |
| 同时进行动效 | 3 | 眼睛无法追踪，只感到"在闪" |

第二条的推导：一屏 1440×900 可用区约 1400×820。12 个模块时每个约 330×250，
能放下 1 个主读数 + 4 个次读数 —— 这正好是"看一眼就够"的信息量。

## 8. HUD 的降级

- `prefers-reduced-motion: reduce`：INTERRUPT 的 1Hz 呼吸改为**静态 4px 红条 + 实心红点**，不动。
- 打印：状态色改为灰度 + 文字标签（`[CAUTION]` / `[INTERRUPT]`），因为打印机会把琥珀打成灰。
- 色盲：状态永远同时有**形状**差异（2px / 2px+竖条 / 4px），不只靠颜色。

**这条是硬要求**：只靠颜色区分的三态，在 protanopia 下 CAUTION 与 INTERRUPT 的
亮度差只有 8%，几乎同色。形状是唯一的兜底通道。
